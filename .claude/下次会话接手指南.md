## ⭐ 为什么阶段3/5不执行？

### 阶段3: 提交聚合逻辑 - 评估后不执行

**原因分析**:
`handlePanelSubmit()` 函数（第1159-1225行）包含状态同步逻辑：
```javascript
async function handlePanelSubmit() {
  // 同步面板UI状态到form
  const hasTimeRange = timeToggle.value && timeStart.value && timeEnd.value;
  form.value.isAllDay = !hasTimeRange;
  // ... 更多UI状态同步
}
```

**不执行原因**:
1. ✅ **这是Component层的职责**：UI状态 → 表单数据的映射
2. ✅ **代码已经很清晰**：逻辑简单直观，注释完整
3. ❌ **提取后更复杂**：需要传入10+个ref参数，违反架构原则
4. ❌ **无复用价值**：AddTaskPanel特有的状态转换逻辑

**架构原则**: Composable层不应处理UI特定的状态转换。

### 阶段5: 时间选择器逻辑 - 评估后不执行

**原因分析**:
时间选择器逻辑（第945-1066行）包含UI交互代码：
```javascript
const showTimePicker = ref(false);  // UI状态

// H5专用：按钮调整
function adjustStartHour(delta) { /* ... */ }

```

**不执行原因**:
1. ✅ **包含大量UI逻辑**：弹窗显示、滚动事件等
2. ✅ **强耦合三端差异**：H5按钮 vs App滚轮，无法抽象
3. ✅ **代码已经清晰**：结构清晰，分H5/App两段
4. ❌ **无复用价值**：AddTaskPanel特有的UI交互

**架构原则**: 强耦合UI交互的逻辑应保留在Component层。
