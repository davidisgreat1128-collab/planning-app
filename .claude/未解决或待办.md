### 4. 重复任务象限切换功能实现错误 ⚠️ **架构设计问题**
**优先级**: ⭐⭐⭐⭐ P0
**状态**: ⚠️ 待修复（2026-03-15发现）
**发现者**: 用户反馈 + Claude分析

**问题截图**: 用户提供的对话框截图，显示3个更新选项

**问题描述**:
在实现重复任务象限切换功能时，选项2"更改当天及未来计划"和选项3"只更新当天计划"的后端实现违反了RRULE的核心架构原则。

**RRULE架构原则** ⭐ 用户正确总结：
> "后端：任务规则只存一条，执行记录按天存；前端获取任务规则，判定是否显现"

具体来说：
- **Task表** - 存储任务模板（RRULE规则），全局唯一
- **CompletionRecord表** - 存储每日完成记录和字段覆盖（JSON格式）
- **前端计算** - 通过RRuleCalculationService实时计算哪些日期应该显示任务

**当前错误实现**（Line 432-456 in taskService.js）:
```javascript
async function updateTaskRecurrence(taskId, userId, updateData, scope, currentDate) {
  const task = await Task.findOne({ where: { id: taskId, userId } });

  // ❌ BUG: 这行代码更新了Task表（模板），导致所有日期都受影响
  await task.update(updateData);

  // ❌ BUG: 删除未来记录也无法挽救，因为模板已经被修改
  if (scope === 'future') {
    await completionRecordRepository.deleteFutureRecords(taskId, currentDate);
  }

  return task;
}
```

**为什么是错的**:
1. 更新Task表会影响RRULE规则本身
2. 前端计算时，所有日期（包括过去）都会使用新的象限属性
3. 违反了"模板-实例分离"原则
4. 无法实现"仅更改未来"或"仅更改当天"的语义

**正确的实现应该是**:
- **不应该修改Task表**
- **应该创建CompletionRecord记录，在note字段中存储象限覆盖**
- 前端获取任务时，优先使用CompletionRecord的覆盖值

**影响范围**:
- ✅ 选项1："完整更改此条重复计划" - 实现正确（确实应该更新Task表）
- ❌ 选项2："更改当天及未来计划" - 实现错误（不应更新Task表）
- ❌ 选项3："只更新当天计划" - 实现错误（不应更新Task表）

**涉及文件**:

#### **方案A: 创建有限期覆盖记录（推荐）** ⭐
**核心思想**: 不修改Task表，为未来N天（如90天）创建CompletionRecord覆盖

**优点**:
- ✅ 符合RRULE架构原则（模板-实例分离）
- ✅ 不影响过去的数据（真正的"不影响过去记录"）
- ✅ 实现简单，前端兼容性好

**缺点**:
- ⚠️ 只覆盖有限期（如90天），90天后恢复原象限
- ⚠️ 需要创建多条CompletionRecord记录（90条）

**实现伪代码**:
```javascript
// 选项2: 更改当天及未来计划（未来90天）
async function updateTaskRecurrence(taskId, userId, updateData, scope, currentDate) {
  const task = await Task.findOne({ where: { id: taskId, userId } });

  // 不修改Task表！

  // 为未来90天创建覆盖记录
  const rrule = parseRrule(task.rrule);
  const futureOccurrences = generateOccurrences(rrule, currentDate, addDays(currentDate, 90));

  for (const date of futureOccurrences) {
    await CompletionRecord.upsert({
      taskId,
      userId,
      occurDate: date,
      note: JSON.stringify({
        overrides: {
          isUrgent: updateData.isUrgent,
          isImportant: updateData.isImportant
        }
      })
    });
  }

  return task;
}

// 选项3: 只更新当天计划
async function updateTaskOccurrence(taskId, userId, date, updateData) {
  // 只创建一条覆盖记录
  const record = await CompletionRecord.upsert({
    taskId,
    userId,
    occurDate: date,
    note: JSON.stringify({
      overrides: {
        isUrgent: updateData.isUrgent,
        isImportant: updateData.isImportant
      }
    })
  });

  return record;
}
```

**前端配合修改**:
```javascript
// taskStore.js - 获取任务时应用覆盖
function applyCompletionRecordOverrides(task, completionRecord) {
  if (!completionRecord?.note) return task;

  const note = JSON.parse(completionRecord.note);
  if (note.overrides) {
    return { ...task, ...note.overrides };
  }

  return task;
}
```

#### **方案B: 更新Task + 保留过去覆盖**
**核心思想**: 更新Task表，但先为过去创建CompletionRecord备份

**优点**:
- ✅ 未来永久生效（不限90天）
- ✅ 过去的数据被备份到CompletionRecord

**缺点**:
- ❌ 违反RRULE架构原则（修改了模板）
- ⚠️ 需要回溯创建大量CompletionRecord记录
- ⚠️ 逻辑复杂，容易出错

**实现伪代码**:
```javascript
async function updateTaskRecurrence(taskId, userId, updateData, scope, currentDate) {
  const task = await Task.findOne({ where: { id: taskId, userId } });

  // 步骤1: 为过去所有出现的日期创建覆盖记录（保留旧象限）
  const pastOccurrences = generateOccurrences(
    parseRrule(task.rrule),
    task.createdAt,
    addDays(currentDate, -1)
  );

  for (const date of pastOccurrences) {
    await CompletionRecord.upsert({
      taskId,
      userId,
      occurDate: date,
      note: JSON.stringify({
        overrides: {
          isUrgent: task.isUrgent,  // 保留旧值
          isImportant: task.isImportant
        }
      })
    });
  }

  // 步骤2: 更新Task表（影响未来）
  await task.update(updateData);

  return task;
}
```

**预估工作量**: 6-8小时

#### **方案C: UNTIL截止 + 新建任务**
**核心思想**: 在旧任务RRULE中添加UNTIL截止昨天，新建任务从今天开始

**优点**:
- ✅ 完全符合RRULE架构原则
- ✅ 数据清晰，易于理解

**缺点**:
- ❌ 会生成两个任务ID（用户可能困惑）
- ❌ 历史记录被拆分

**实现伪代码**:
```javascript
async function updateTaskRecurrence(taskId, userId, updateData, scope, currentDate) {
  const oldTask = await Task.findOne({ where: { id: taskId, userId } });

  // 步骤1: 更新旧任务的RRULE，添加UNTIL（截止昨天）
  const yesterday = addDays(currentDate, -1);
  const newRrule = addUntilToRrule(oldTask.rrule, yesterday);
  await oldTask.update({ rrule: newRrule });

  // 步骤2: 创建新任务（从今天开始）
  const newTask = await Task.create({
    ...oldTask.toJSON(),
    id: undefined,  // 新ID
    ...updateData,  // 新象限
    rrule: updateRruleStart(oldTask.rrule, currentDate)
  });

  return { oldTask, newTask };
}
```

**预估工作量**: 8-10小时
