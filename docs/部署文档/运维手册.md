## 1. 日常运维

### 1.1 每日巡检（5分钟）

```bash
cd /opt/planning-app

# 1. 检查服务状态
docker-compose ps

# 2. 检查磁盘空间
df -h

# 3. 检查内存使用
free -h

# 4. 检查API健康状态
curl https://txjjzyzqbx.cn/health

# 5. 查看最近日志
docker-compose logs --tail=50
```

### 1.2 每周维护（30分钟）

```bash
# 1. 清理Docker资源
docker system prune -f

# 2. 检查备份文件
ls -lh backups/mysql/

# 3. 检查SSL证书有效期
certbot certificates

# 4. 查看慢查询日志
docker-compose exec mysql tail -n 20 /var/log/mysql/slow.log

# 5. 更新Docker镜像
docker-compose pull
```

### 1.3 每月维护（1小时）

```bash
# 1. 系统更新
apt update && apt upgrade -y  # Ubuntu/Debian
# yum update -y  # CentOS/RHEL

# 2. 数据库优化
docker-compose exec mysql mysqlcheck --optimize --all-databases -uroot -p

# 3. 日志归档
tar -czf logs/archive_$(date +%Y%m).tar.gz logs/*.log
rm logs/*.log

# 4. 备份归档到COS
# （如果配置了腾讯云COS）

# 5. 性能测试
ab -n 10000 -c 100 https://txjjzyzqbx.cn/health
```

## 2. 监控与告警

### 2.1 健康检查脚本

**已配置定时任务**（每5分钟自动检查）:

```bash
*/5 * * * * /opt/planning-app/scripts/health-check.sh >> /opt/planning-app/logs/health.log 2>&1
```

**手动执行**:

```bash
bash scripts/health-check.sh
```

### 2.2 关键指标监控

| 指标 | 正常范围 | 告警阈值 | 检查命令 |
|------|---------|---------|---------|
| CPU使用率 | < 70% | > 90% | `top` |
| 内存使用率 | < 80% | > 90% | `free -h` |
| 磁盘使用率 | < 80% | > 90% | `df -h` |
| API响应时间 | < 200ms | > 1000ms | `curl -w "@%{time_total}\n"` |
| 数据库连接数 | < 100 | > 150 | `SHOW PROCESSLIST` |
| 错误日志数 | < 10/天 | > 50/天 | `grep ERROR logs/*.log \| wc -l` |

### 2.3 日志监控

```bash
# 实时查看错误日志
docker-compose logs -f | grep -i error

# 统计今日错误数
docker-compose logs --since "$(date +%Y-%m-%d)" | grep -i error | wc -l

# 查看慢查询
docker-compose exec mysql tail -f /var/log/mysql/slow.log
```

## 3. 备份与恢复

### 3.1 自动备份

**已配置定时任务**（每日凌晨2点）:

```bash
0 2 * * * /opt/planning-app/scripts/backup-mysql.sh >> /opt/planning-app/logs/backup.log 2>&1
```

**手动备份**:

```bash
bash scripts/backup-mysql.sh
```

### 3.2 数据恢复

```bash
# 1. 列出可用备份
ls -lh backups/mysql/

# 2. 恢复数据库
bash scripts/restore-mysql.sh backups/mysql/planning_app_20240320_020000.sql.gz

# 3. 验证数据
docker-compose exec mysql mysql -uroot -p planning_app_prod -e "SHOW TABLES;"
```

### 3.3 完整灾难恢复流程

**场景**: 服务器完全损坏，需要在新服务器上恢复

```bash
# 1. 新服务器上安装Docker和Docker Compose
curl -fsSL https://get.docker.com | sh
apt install docker-compose -y

# 2. 克隆项目
cd /opt
git clone git@github.com:davidisgreat1128-collab/planning-app.git
cd planning-app

# 3. 从COS下载最新备份（或从其他存储）
# coscli cp cos://bucket/planning-app/mysql/latest.sql.gz backups/mysql/

# 4. 生成密钥并修改.env（使用原密钥）
bash scripts/generate-secrets.sh
# 手动修改.env，使用原来的密钥

# 5. 部署服务
bash scripts/deploy.sh

# 6. 恢复数据
bash scripts/restore-mysql.sh backups/mysql/latest.sql.gz

# 7. 申请SSL证书
bash scripts/setup-ssl.sh

# 8. 配置定时任务
crontab -e  # 添加备份、续期、健康检查任务
```

## 4. 性能优化

### 4.1 数据库优化

**慢查询分析**:

```bash
# 查看慢查询日志
docker-compose exec mysql cat /var/log/mysql/slow.log

# 分析慢查询
docker-compose exec mysql pt-query-digest /var/log/mysql/slow.log
```

**索引优化**:

```sql
-- 查找缺少索引的表
SELECT DISTINCT
    TABLE_NAME
FROM
    information_schema.TABLES
WHERE
    TABLE_SCHEMA = 'planning_app_prod'
    AND TABLE_ROWS > 1000
    AND TABLE_NAME NOT IN (
        SELECT DISTINCT TABLE_NAME
        FROM information_schema.STATISTICS
        WHERE TABLE_SCHEMA = 'planning_app_prod'
    );
```

**连接池优化**（backend）:

```javascript
// backend/src/config/database.js
const sequelize = new Sequelize({
  pool: {
    max: 20,      // 最大连接数（生产环境建议10-20）
    min: 5,       // 最小连接数
    acquire: 30000,
    idle: 10000
  }
})
```

### 4.2 Redis缓存优化

**清理过期键**:

```bash
docker-compose exec redis redis-cli -a ${REDIS_PASSWORD} --scan --pattern "*" | xargs docker-compose exec redis redis-cli -a ${REDIS_PASSWORD} DEL
```

**查看缓存命中率**:

```bash
docker-compose exec redis redis-cli -a ${REDIS_PASSWORD} INFO stats | grep keyspace
```

### 4.3 Nginx优化

**启用HTTP/2**（已启用）:

```nginx
listen 443 ssl http2;
```

**启用Gzip压缩**（已启用）:

```nginx
gzip on;
gzip_comp_level 6;
```

**增加worker进程**:

```nginx
# nginx/nginx.conf
worker_processes auto;  # 自动检测CPU核心数
```

## 5. 安全维护

### 5.1 SSL证书续期

**自动续期**（已配置定时任务，每月1号凌晨3点）:

```bash
0 3 1 * * /opt/planning-app/scripts/renew-ssl.sh >> /opt/planning-app/logs/ssl-renew.log 2>&1
```

**手动续期**:

```bash
bash scripts/renew-ssl.sh
```

**检查证书有效期**:

```bash
certbot certificates
```

### 5.2 密钥轮换

**定期更换JWT密钥**（建议每6个月）:

```bash
# 1. 生成新密钥
NEW_JWT_SECRET=$(openssl rand -base64 64)

# 2. 更新.env
sed -i "s/JWT_SECRET=.*/JWT_SECRET=$NEW_JWT_SECRET/" .env

# 3. 重启后端
docker-compose restart backend
```

### 5.3 安全审计

```bash
# 1. 检查开放端口
netstat -tuln | grep LISTEN

# 2. 检查Docker容器安全
docker scan planning-app-backend:latest

# 3. 检查系统更新
apt list --upgradable

# 4. 查看登录日志
last -20
```

## 6. 故障处理

### 6.1 服务无响应

**诊断**:

```bash
# 1. 检查容器状态
docker-compose ps

# 2. 查看资源使用
docker stats

# 3. 查看日志
docker-compose logs --tail=100
```

**解决**:

```bash
# 重启服务
docker-compose restart
```

### 6.2 数据库连接满

**诊断**:

```sql
SHOW PROCESSLIST;
```

**解决**:

```bash
# 1. 杀死长时间运行的查询
docker-compose exec mysql mysql -uroot -p -e "KILL <PROCESS_ID>;"

# 2. 增加最大连接数
docker-compose exec mysql mysql -uroot -p -e "SET GLOBAL max_connections = 300;"

# 3. 优化应用连接池配置
```

### 6.3 磁盘空间不足

**清理Docker资源**:

```bash
# 清理未使用的镜像
docker image prune -a -f

# 清理未使用的卷
docker volume prune -f

# 清理构建缓存
docker builder prune -a -f
```

**清理日志**:

```bash
# 归档旧日志
tar -czf logs_archive_$(date +%Y%m%d).tar.gz logs/*.log
rm logs/*.log

# 清理旧备份（保留最近7天）
find backups/mysql -type f -mtime +7 -delete
```

## 8. 常用命令速查

### Docker相关

```bash
# 查看服务状态
docker-compose ps

# 启动服务
docker-compose up -d

# 停止服务
docker-compose down

# 重启服务
docker-compose restart

# 查看日志
docker-compose logs -f [服务名]

# 进入容器
docker-compose exec [服务名] bash

# 查看资源使用
docker stats
```

### MySQL相关

```bash
# 进入MySQL
docker-compose exec mysql mysql -uroot -p

# 导出数据库
docker-compose exec mysql mysqldump -uroot -p planning_app_prod > backup.sql

# 查看数据库大小
docker-compose exec mysql mysql -uroot -p -e "SELECT table_schema AS 'Database', ROUND(SUM(data_length + index_length) / 1024 / 1024, 2) AS 'Size (MB)' FROM information_schema.tables GROUP BY table_schema;"
```

### Nginx相关

```bash
# 测试配置
docker-compose exec nginx nginx -t

# 重载配置
docker-compose exec nginx nginx -s reload

# 查看访问日志
docker-compose logs nginx | grep "GET /api"
```
