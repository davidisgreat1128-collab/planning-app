## 📋 问题概述

### Bug 1: 点击特定日期报错 ⭐⭐⭐ P0级

**用户报告**:
> "现在是日历能渲染出来了，但是不能拖拽，设置测试日志，排查BUG原因；还有我4号、5号就报错了，点击2号、3号、7号、8号，就没事，是因为节日的原因吗？"

**错误日志**（测试前端日志第147行）:
```
TypeError: planStore.getTasksByDate is not a function
    at getTaskDots (useCalendar.js:141:33)
    at useCalendar.js:185:29
```

**触发场景**:
- 点击3月4日、5日 → 报错（TypeError）
- 点击2号、3号、7号、8号 → 正常工作

---

## 🔍 问题分析

### 根本原因

项目中存在**两个不同的规划Store**，职责完全不同：

#### 1. `usePlanningStore` (新版，三层架构)
- **文件**: `store/planning.js`
- **职责**: 管理 **PlanningRecord**（规划记录实体）
- **API**: Composition API
- **方法**: `loadList()`, `createPlanning()`, `updatePlanning()`, `getByType()` 等
- ❌ **没有** `getTasksByDate()` 方法

#### 2. `usePlanStore` (旧版)
- **文件**: `store/plan.js`
- **职责**: 管理 **规划生成的任务**（generatedTasks）
- **API**: Options API
- **方法**: `getTasksByDate()`, `allGeneratedTasks`, `generateTasksFromPlan()` 等
- ✅ **有** `getTasksByDate()` 方法

### 错误代码定位

**文件**: `frontend/Planning-app/composables/useCalendar.js`

**第31行** - 导入了错误的Store:
```javascript
// ❌ 错误导入
import { usePlanningStore } from '@/store/planning';
```

**第101行** - 初始化了错误的Store:
```javascript
// ❌ 错误初始化
const planStore = usePlanningStore(); // 这个Store没有getTasksByDate()方法
```

**第144行** - 调用不存在的方法:
```javascript
// ❌ TypeError: planStore.getTasksByDate is not a function
const planTasks = planStore.getTasksByDate(dateStr);
```

### 为什么点击4号/5号报错，2号/3号正常？

**初步猜测**: 与节日数据无关

**真正原因**:
- 初始加载时，计算属性 `currentWeekDates` 可能未立即触发 `getTaskDots()` 函数
- **点击日期时**，触发 `selectDate()` → 计算属性重新计算 → 调用 `getTaskDots()` → 报错
- 2号/3号/7号/8号能正常工作，可能是因为测试顺序问题或缓存状态

**测试日志证据**（第100-105行）:
```

101→useCalendar.js:420 [useCalendar] selectDate 被调用, 日期: 2026-03-04
102→useCalendar.js:425 [useCalendar] selectDate - 已更新 selectedDate 和 taskStore.selectedDate
103→log.js:60 [LogStore] 切换到日期: 2026-03-04
104→useCalendar.js:161 [useCalendar] currentWeekDates 计算属性被调用
105→useCalendar.js:422 [Vue warn]: Unhandled error during execution of render function
```

### Bug 2: 拖拽功能失效（待测试）

**问题**: 日历渲染正常，但无法拖拽任务
**分析**: 日志中未看到 `[useDragDrop]` 的拖拽相关日志（startDrag/onTaskTouchMove等）
**可能原因**: H5环境下的鼠标/触摸事件绑定问题，需进一步测试

## ✅ 解决方案

### 方案选择：快速修复 - 使用正确的 usePlanStore

**技术决策依据**:
1. **业务需求**: 日历需要显示"规划生成的任务"（generatedTasks）
2. **快速修复**: 使用现有可用代码，优先修复用户阻塞Bug
3. **后续优化**: 将 `usePlanStore` 迁移到三层架构作为独立任务处理

### 代码修改

**文件**: `frontend/Planning-app/composables/useCalendar.js`

**修改1: 导入正确的Store（第31-34行）**

```javascript

import { usePlanningStore } from '@/store/planning';
import { useLogStore } from '@/store/log';

// 修改后
```

**修改2: 初始化正确的Store（第101-111行）**

