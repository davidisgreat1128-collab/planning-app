## 🔧 技术决策

### 决策1: 工作日数据存储结构
**选择**: 独立的work_days表，与holidays表分离

**理由**:
- holidays存储固定节日（每年相同日期）
- work_days存储年度工作日调整（每年不同，需单独管理）
- 方便后续扩展（如添加2027、2028年数据）

### 决策2: 工作日API返回Map结构
**选择**: `{ "YYYY-MM-DD": { type, holidayName, remark } }`

**理由**:
- 前端O(1)查找效率
- 减少数组遍历开销
- 统一API响应格式（与holidayMap、lunarMap一致）

### 决策3: 注释调试日志而非删除
**选择**: 使用 `//` 注释而非完全删除

**理由**:
- 保留代码便于后续调试
- 避免删除时破坏代码结构
- 方便快速启用日志排查问题
