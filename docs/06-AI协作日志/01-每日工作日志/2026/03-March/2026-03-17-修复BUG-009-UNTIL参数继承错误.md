### 日志分析结果

**问题任务**：任务ID=110

**日志关键信息**：
```
RRULE字符串: DTSTART:20260321T000000Z
             RRULE:FREQ=DAILY;UNTIL=20260320T235959Z

开始日期：2026-03-21
结束日期：2026-03-20

❌ DTSTART (2026-03-21) > UNTIL (2026-03-20)
```

### 根本原因

**问题1：UNTIL参数被错误继承** ⭐ 根本原因

在`_updateRRuleStartDate`方法中（第329-349行）：

```javascript
// ❌ 错误写法（修复前）
const newRRule = new RRule({
  ...options,           // 展开所有参数，包括until
  dtstart: new Date(newStartDate + 'T00:00:00Z'),
  until: null          // RRule构造函数不接受null值
});
```

**为什么会继承UNTIL？**

1. 第336行`...options`会展开原始RRULE的**所有参数**
2. 如果原始RRULE包含UNTIL（如旧任务的UNTIL=2026-03-20）
3. 该UNTIL会被展开到新RRule对象中
4. 虽然第338行设置了`until: null`，但RRule.js不接受null值
5. 最终导致新任务继承了旧任务的UNTIL

**为什么de0210e修复没有解决？**

- de0210e修复保存了原始RRULE字符串（在修改旧任务之前）
- 但`_updateRRuleStartDate`方法仍然通过`...options`继承了UNTIL
- 这个问题在**所有**使用`_updateRRuleStartDate`的场景都会出现

**问题2：EXDATE字段值错误**

在`modifyFuture`方法中（第109行）：

```javascript
// ❌ 错误写法
exdate: '[]'  // 字符串

// 数据库存储结果
EXDATE: ["[]"]  // 字符串数组，而不是空数组

// 应该是
exdate: null  // null会被Model getter转换为空数组[]
```

## ✅ 修复方案

### 修复1：排除UNTIL和DTSTART字段（彻底解决继承问题）

**文件**：`backend/src/services/RecurringTaskService.js`
**位置**：第329-349行（`_updateRRuleStartDate`方法）

**修改前**：
```javascript
_updateRRuleStartDate(rruleString, newStartDate) {
  try {
    const rrule = rrulestr(rruleString);
    const options = rrule.options;

    // ❌ ...options 会展开所有参数，包括until
    const newRRule = new RRule({
      ...options,
      dtstart: new Date(newStartDate + 'T00:00:00Z'),
      until: null // RRule构造函数不接受null
    });

    return newRRule.toString();
  } catch (error) {
    console.error('更新RRULE开始日期失败:', error);
    throw error;
  }
}
```

**修改后**：
```javascript
_updateRRuleStartDate(rruleString, newStartDate) {
  try {
    const rrule = rrulestr(rruleString);
    const options = rrule.options;

    // ⭐ 从options中排除until和dtstart字段（防止继承）
    const { until, dtstart, ...cleanOptions } = options;

    // ⭐ 创建新RRULE：只设置新的dtstart，不包含until（新任务永久重复）
    const newRRule = new RRule({
      ...cleanOptions,
      dtstart: new Date(newStartDate + 'T00:00:00Z')
      // 不设置until字段 = 永久重复
    });

    return newRRule.toString();
  } catch (error) {
    console.error('更新RRULE开始日期失败:', error);
    throw error;
  }
}
```

**关键改动**：
- 使用ES6解构赋值：`const { until, dtstart, ...cleanOptions } = options;`
- 排除`until`和`dtstart`字段，只保留其他参数（FREQ、INTERVAL、WKST等）
- 新RRule对象中不包含`until`字段 = 永久重复

## 🎯 总结

### 问题根源

**BUG-009的三个层次**：

1. **直接原因**：任务110的RRULE包含DTSTART > UNTIL
2. **技术原因**：`...options`展开运算符继承了UNTIL参数
3. **设计原因**：之前的修复（de0210e）只解决了"使用原始RRULE"，未解决"UNTIL继承"

### 修复链条

```
BUG-007（cf70dcd）
  → 修复前端键名不匹配（oldTask vs originalTask）
  ↓
BUG-008第一次（259a7d4）
  → 添加 until: null，但仍使用已修改的RRULE
  ↓
BUG-008第二次（de0210e）
  → 使用原始RRULE，但...options仍继承UNTIL
  ↓
BUG-009（0ffc79d）⭐ 彻底解决
  → 解构排除until和dtstart字段，防止继承
```

### 关键经验

1. **展开运算符的陷阱**：`...options`会展开**所有**字段，包括不想要的
2. **null vs 不设置**：RRule.js中`until: null`和"不设置until字段"是不同的
3. **测试日志的价值**：详细日志帮助快速定位具体问题任务和RRULE字符串
4. **数据清理的重要性**：错误数据会持续触发BUG，必须清理
