## 💭 技术决策与思考

### 决策1：选择对象格式存储subtask_completion

**问题**：子任务完成状态应该用对象格式还是数组格式？

**方案A**：对象格式（推荐）
```json
{"st_001": {"isDone": true, "completedAt": "2026-03-14T09:30:00Z"}}
```

**方案B**：数组格式
```json
[{"subtaskId": "st_001", "isDone": true, "completedAt": "..."}]
```

**决策**：选择**方案A**（对象格式）

**理由**：
1. **查询性能**: O(1) vs O(n)
   ```javascript
   // 对象格式：直接访问 O(1)
   const isDone = subtaskCompletion['st_001'].isDone;

   // 数组格式：需要遍历 O(n)
   const isDone = subtaskCompletion.find(st => st.subtaskId === 'st_001')?.isDone;
   ```

2. **合并更新简单**:
   ```javascript
   // 对象格式：展开运算符
   const merged = { ...oldCompletion, ...newCompletion };

   // 数组格式：需要复杂的合并逻辑
   ```

3. **数据结构直观**：子任务ID作为key，直接映射到完成状态

### 决策2：使用rrule库而非自己实现

**问题**：RRULE规则计算是自己实现还是用现成库？

**方案A**：自己实现RRULE解析器
**方案B**：使用npm包 `rrule`

**决策**：选择**方案B**（使用rrule库）

**理由**：
1. **标准兼容**：rrule库完全符合RFC 5545规范
2. **功能完整**：支持所有RRULE高级功能（BYSETPOS、BYWEEKNO等）
3. **久经考验**：周下载量100万+，广泛使用
4. **节省时间**：避免重复造轮子，专注业务逻辑
5. **减少Bug**：日期计算复杂，自己实现容易出Bug

### 决策3：使用TEXT类型存储exdate而非JSON

**问题**：例外日期字段应该用TEXT还是JSON类型？

**数据库字段定义**：
```sql
exdate TEXT DEFAULT NULL  -- 存储JSON字符串
```

**Sequelize Model**：
```javascript
exdate: {
  type: DataTypes.TEXT,
  get() {
    const rawValue = this.getDataValue('exdate');
    if (!rawValue) return [];
    return JSON.parse(rawValue);
  },
  set(value) {
    this.setDataValue('exdate', JSON.stringify(value || []));
  }
}
```

**理由**：
1. **MySQL版本兼容**：TEXT类型所有MySQL版本都支持，JSON类型需要MySQL 5.7.8+
2. **数据迁移简单**：TEXT类型可以直接存储JSON字符串
3. **Sequelize自动处理**：通过getter/setter自动解析JSON，代码层使用数组

## 💡 经验总结

### 1. 大文档创建的最佳实践

**问题**：初次尝试创建3000行文档，遇到32000 token输出限制

**解决方案**：
1. **用户先创建骨架**：用户手动创建文档和第一/二部分（约760行）
2. **Claude补充细节**：Claude补充剩余4个部分（约950行）
3. **分批编写**：每次编写一个章节，避免token超限
4. **模板化代码**：使用代码模板，减少重复代码的token消耗

**效果**：
- 最终文档：1710行
- 质量：完整、可执行、可交接
- 时间：约2小时完成

### 2. 文档同步的重要性

**教训**：如果不及时更新《文档导航.md》，新文档容易成为"孤儿文档"

**最佳实践**：
1. 创建任何.md文件时，立即在《文档导航.md》中登记
2. 更新现有文档时，同步更新文档版本号和维护日志
3. 相关文档之间添加交叉引用链接

### 3. 技术决策的记录价值

**发现**：本次工作中记录了3个技术决策（对象格式、rrule库、TEXT类型）

**价值**：
- 为未来的Claude实例提供决策上下文
- 避免重复讨论相同问题
- 帮助用户理解设计思路
