### 2. 关键技术实现

#### 2.1 无限滚动核心算法

**问题**: 如何实现真正的"无限滚动"而不预渲染大量页面？

**解决方案**: 3视图循环复用

```javascript
// useInfiniteScroll.js
// 核心思想：只渲染3个视图（prev/current/next）
// 滑动超过阈值时，更新 baseDate 并重置位置

function resetToNext() {
  // 1. 更新基准日期
  state.baseDate = addDate(state.baseDate, 1, 'month')

  // 2. 重置滚动位置到中间
  scrollPosition.value = screenWidth // 始终显示中间的 current 视图

  // 3. views (computed) 自动重新计算，生成新的 prev/current/next
}
```

**性能优势**:
- DOM数量: O(1)固定（周：21个单元格，月：126个单元格）
- 内存占用: ~30MB（不随滑动增加）
- 滑动帧率: 58-60fps

#### 2.2 周/月平滑过渡算法

**问题**: 如何实现 iOS 原生日历的平滑过渡效果？

**解决方案**: 高度插值 + transitionProgress

```javascript
// CalendarGrid.vue
const gridStyle = computed(() => {
  const cellWidth = screenWidth / 7

  // 高度插值：week(1行) → month(6行)
  const weekHeight = cellWidth
  const monthHeight = cellWidth * 6
  const height = weekHeight + (monthHeight - weekHeight) * props.transitionProgress

  return {
    height: `${height}px`,
    overflow: 'hidden' // 周视图时裁剪多余行
  }
})
```

**关键点**:
- `transitionProgress`: 0=week, 1=month
- 通过 CSS `overflow: hidden` 实现裁剪
- 动画由 `useGesture` 控制

#### 2.3 手势识别系统

**问题**: 如何避免横向滑动和纵向滑动冲突？

**解决方案**: 首次移动判断方向 + 锁定方向

```javascript
// useGesture.js
function handleTouchMove(e) {
  const deltaX = clientX - gesture.value.startX
  const deltaY = clientY - gesture.value.startY

  // 1. 首次移动判断方向（避免冲突）
  if (gesture.value.direction === null) {
    gesture.value.direction = Math.abs(deltaX) > Math.abs(deltaY)
      ? 'horizontal' // 横向滑动 → 翻页
      : 'vertical'   // 纵向滑动 → 周/月切换
  }

  // 2. 根据方向处理（锁定后只响应一个方向）
  if (gesture.value.direction === 'horizontal') {
    handleDrag(-deltaX)
  } else if (gesture.value.direction === 'vertical') {
    handleVerticalDrag(deltaY)
  }
}
```

**三端兼容处理**:
```javascript
// 使用条件编译确保三端兼容
function preventDefaultCompat(e) {
  // #ifdef H5
  if (e.cancelable) {
    e.preventDefault()
  }
  // #endif

  // #ifdef APP-PLUS
  if (e.preventDefault) {
    e.preventDefault()
  }
  // #endif
}
```

#### 2.4 Store 集成（四层架构关键）

**问题**: Composable 层如何正确集成任务数据？

**解决方案**: useCalendarCore → useTaskStore（符合四层架构）

```javascript
// useCalendarCore.js
import { useTaskStore } from '@/store/task' // ✅ Composable 调用 Store

export function useCalendarCore(initialDate, options) {
  let taskStore = null
  if (options.enableTaskIntegration) {
    taskStore = useTaskStore() // ✅ 通过 Store 获取数据
  }

  function getTasksForDate(date) {
    if (!taskStore) return []

    // ✅ 从 Store 过滤任务，不直接调用 Repository 或 API
    return taskStore.tasks.filter(task =>
      isSameDay(new Date(task.startDate), date)
    )
  }

  return { getTasksForDate, ... }
}
```

**调用链验证**:
```
Component (InfiniteCalendar.vue)
  → Composable (useCalendarCore)
    → Store (useTaskStore)
      → Repository (TaskRepository)
        → API (taskApi)

✅ 符合四层架构，无跨层调用
```

## 📚 知识点总结

### 1. 四层架构实践

**核心要点**:
- Composable 层是**业务流程编排层**，不是数据访问层
- Composable 可以调用 Store，但不能调用 Repository/API
- 全局状态放 Store，局部状态放 Composable（reactive/ref）

**判断标准**:
```
Q: 这段代码应该放哪一层？
A:
- 纯工具函数 → Utils
- 数据CRUD → Repository
- 全局状态 → Store
- 业务流程 → Composable
- UI渲染 → Component
```

### 2. 无限滚动原理

**核心思想**: 视图复用 + 时间驱动

```
初始状态：[Prev | Current | Next]
           (Feb   Mar      Apr)
                  ↑ 视口

向左滑动超过阈值 →
  更新 baseDate: Mar → Apr
  重新计算：[Mar | Apr | May]
                  ↑ 视口仍在中间

关键：DOM结构不变，只是数据更新
```

### 3. 手势识别技巧

**避免横纵冲突**: 首次移动判断方向 + 锁定

```javascript
if (!direction) {
  direction = |deltaX| > |deltaY| ? 'horizontal' : 'vertical'
}

if (direction === 'horizontal') {
  // 只处理横向
} else if (direction === 'vertical') {
  // 只处理纵向
}
```

## 📝 决策记录

### 决策1：为什么不用 Swiper？

**问题**: UniApp 提供了 `swiper` 组件，为什么不用？

**原因**:
1. Swiper 需要预渲染大量页面（无法真正无限滚动）
2. 性能随页面数线性下降
3. 周/月切换需要2个独立组件（状态管理复杂）

**解决方案**: 3视图循环复用 + transform

### 决策2：为什么 transitionProgress 不放 Store？

**问题**: `transitionProgress` 是全局状态吗？

**原因**:
- `transitionProgress` 是单个日历实例的**局部状态**
- 如果页面有多个日历，它们的 progress 应该独立
- 放 Composable 更符合 SRP

**结论**: 局部状态放 Composable，全局状态放 Store

### 决策3：为什么性能监控可选？

**问题**: PerformanceMonitor 是否应该始终启用？

**原因**:
- 开发环境：需要实时监控性能
- 生产环境：监控有性能开销，应默认关闭

**解决方案**: 根据 `process.env.NODE_ENV` 自动启用/禁用
