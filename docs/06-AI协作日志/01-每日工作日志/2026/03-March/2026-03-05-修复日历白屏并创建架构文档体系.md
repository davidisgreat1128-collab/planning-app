### 任务1: 修复日历白屏问题 ✅

#### 问题分析

**错误现象**:
- 用户打开日历页面后白屏
- 浏览器控制台报错：`TypeError: planStore.getTasksByDate is not a function`
- 错误位置：`useCalendar.js` 第174行和第211行

**根本原因**:
- `useCalendar.js` 尝试调用 `planStore.getTasksByDate(dateStr)` 方法
- PlanningStore 的职责是管理"规划容器"本身（title, type, status 等）
- **不负责查询"规划下的任务"** - 这个方法从未存在过
- 这是对业务逻辑的误解导致的错误代码

**业务逻辑澄清**（用户提供）:
```
"全部"容器 (虚拟)
├── 规划容器 (Planning)    → 包含任务（planId = P001）
├── 分类容器 (Category)    → 包含任务（categoryId = C001）
└── 无分类容器 (虚拟)       → 包含任务（planId=null, categoryId=null）

日历页面职责：显示所有任务，不区分任务所属容器
```

#### 解决方案

**修改文件**: `frontend/Planning-app/composables/useCalendar.js`

**修改位置1**（第174行，`currentWeekDates` 计算属性内）:
```javascript
// ❌ 删除错误代码
const planTasks = planStore.getTasksByDate(dateStr);
const dateTasks = [...taskStore.tasks, ...planTasks].filter(t => {
  const taskDate = t.date || t.taskDate || '';
  return taskDate.startsWith(dateStr);
});

// ✅ 修改为
// 获取该日期的任务（日历显示所有任务，不区分所属容器）
const dateTasks = taskStore.tasks.filter(t => {
  const taskDate = t.date || t.taskDate || '';
  return taskDate.startsWith(dateStr);
});
```

**修改位置2**（第211行，`monthRows` 计算属性内）:
```javascript
// ❌ 删除错误代码
const planTasks = planStore.getTasksByDate(dateStr);
const hasTask = [...taskStore.tasks, ...planTasks].some(t => {
  const taskDate = t.date || t.taskDate || '';
  return taskDate.startsWith(dateStr);
});

// ✅ 修改为
// 获取该日期的任务（日历显示所有任务，不区分所属容器）
const hasTask = taskStore.tasks.some(t => {
  const taskDate = t.date || t.taskDate || '';
  return taskDate.startsWith(dateStr);

```

**修改结果**:
- 删除了 2 处 `planStore.getTasksByDate()` 调用
- 日历页面现在只使用 `taskStore.tasks`（已包含所有任务）
- 页面不再白屏，功能恢复正常

## 🔍 技术亮点

### 1. 业务逻辑梳理

通过与用户深度沟通，明确了系统的容器层级关系：
```
"全部"容器（虚拟）
├── 规划容器（Planning） - 复杂分类，有目标、进度、易经建议
├── 分类容器（Category） - 简单分类，纯前端管理
└── 无分类容器（虚拟）  - planId=null && categoryId=null
```

**关键理解**:
- 规划和分类是**平级关系**
- 规划是"复杂的分类"（更多属性）
- 任务通过 `planId` 和 `categoryId` 关联到容器

### 2. Sequelize 自动映射机制

**全局配置**（`backend/src/models/index.js`）:
```javascript
const sequelize = new Sequelize(dbConfig.database, dbConfig.username, dbConfig.password, {
  underscored: true,  // ⭐ 全局开启 snake_case ↔ camelCase 自动映射
  // ...
});
```

**映射示例**:
```
数据库 (snake_case)    →    JS代码 (camelCase)
user_id                →    userId
created_at             →    createdAt
is_urgent              →    isUrgent
task_date              →    taskDate
```

**优势**:
- 数据库遵循 MySQL 规范（snake_case）
- 代码遵循 JS 规范（camelCase）
- Sequelize 自动转换，无需手动映射

### 3. Repository 离线优先架构

**核心特性**:
1. **内存缓存** (MemoryCache)：Map 结构，O(1) 查找
2. **操作队列** (OperationQueue)：离线时记录操作，网络恢复后重放
3. **防抖同步** (Debounced Sync)：500ms 防抖，避免频繁网络请求
4. **指数退避** (Exponential Backoff)：重试间隔 1s → 2s → 4s → 8s → 16s
5. **软删除** (Soft Delete)：deletedAt 字段，数据可恢复

**数据流**:
```
用户操作 → 立即写入 memoryCache（0ms，UI 立即响应）
         → 添加到 operationQueue（1ms）
         → 保存到 localStorage（500ms 防抖）
         → 上传到服务器（500ms 防抖 + 指数退避）
```
