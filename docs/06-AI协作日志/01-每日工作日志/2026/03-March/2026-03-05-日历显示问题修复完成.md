## 💡 技术总结

### 为什么 init() 如此重要?

`useCalendar.init()` 是日历 Composable 的**启动入口**,负责初始化所有核心状态:

```javascript
function init() {
  console.log('[useCalendar] ========== init 初始化开始 ==========');

  // 初始化为当前周
  currentWeekStart.value = getWeekMonday(new Date());
  currentMonthFirst.value = getMonthFirst(new Date());

  console.log('[useCalendar] init - 已初始化周/月起始:', {
    currentWeekStart: currentWeekStart.value,
    currentMonthFirst: currentMonthFirst.value,
    todayStr
  });

  // 选中今天
  selectDate(todayStr);  // ← 触发 watch(),加载今日任务

  // 加载节日数据
  loadHolidays();

  console.log('[useCalendar] ========== init 初始化完成 ==========');
}
```

**如果不调用 init()**:
1. `currentWeekStart` = `null` → `currentWeekDates` 计算属性返回空数组 `[]`
2. `selectedDate` = `''` → CalendarBar 无法高亮显示当前选中日期
3. `holidayMap` = `{}` → 无节日/农历信息
4. `loadHolidays()` 执行失败 → 日志警告 "currentWeekStart 为空"

### 为什么之前没调用 init()?

**可能原因**:
- 重构过程中遗漏（从 3728行 → 799行,大量代码移动）
- 之前的 onMounted 直接调用 loadHolidays(),未意识到需要先 init()
- 测试不充分,未覆盖"首次进入页面"场景

**经验教训**:
- ✅ Composable 提供 init() 方法时,必须在组件 onMounted 中调用
- ✅ 重构后必须进行完整的端到端测试
- ✅ 调试日志非常有效,快速定位到 `currentWeekStart: null` 根本原因

### 为什么移除全局空状态?

**设计原则**: **细粒度空状态 > 全局空状态**

**四象限视图的空状态设计**:
```vue
<!-- Q3象限的空状态 -->
<view v-if="urgentNotImportant.length === 0 && urgentNotImportantDone.length === 0" class="empty-quadrant">
  <text class="empty-icon">○</text>
  <text class="empty-text">琐事象限</text>
  <text class="empty-hint">减少做</text>
</view>
```

**优势**:
- ✅ 每个象限独立显示空状态,不影响其他象限
- ✅ 空状态提示与象限意义关联（如Q3提示"减少做"）
- ✅ 即使某些象限有任务,空象限仍能显示提示
- ✅ 布局更清晰,无遮挡

**全局空状态的问题**:
- ❌ 占据整个 scroll-view 大片空间
- ❌ 挡住下方的四象限布局
- ❌ 当有任何任务时就消失,无法为空象限提供提示
- ❌ 不符合"分区管理"的四象限理念
