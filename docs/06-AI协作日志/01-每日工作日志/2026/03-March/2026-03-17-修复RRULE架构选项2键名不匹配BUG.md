## 🔍 问题根因分析

### 1. 前后端数据结构不一致

**后端返回格式**（backend/src/services/RecurringTaskService.js 第115-118行）：
```javascript
return {
  originalTask,  // ✅ 键名是 originalTask
  newTask
};
```

**前端解构格式**（frontend/Planning-app/repositories/TaskRepository.js 第399行）：
```javascript
const { oldTask, newTask } = result  // ❌ 期望键名是 oldTask
```

**键名不匹配！** 导致 `oldTask` 为 `undefined`，后续访问 `oldTask.id` 时报错。

### 2. 错误传播链路

```
1. useTaskQuadrant.js:238 - 用户点击"确定"
   ↓ 调用 taskStore.updateTaskFuture(taskId, updates, splitDate)
2. task.js:302 - Store层
   ↓ 调用 TaskRepository.updateTaskFuture(id, data, splitDate)
3. TaskRepository.js:389-396 - Repository层
   ↓ 调用后端API: POST /tasks/:id/modify-future
4. RecurringTaskService.js:115-118 - 后端返回
   ↓ return { originalTask, newTask }
5. TaskRepository.js:399 - 前端解构 ❌ 键名不匹配
   ↓ const { oldTask, newTask } = result  // oldTask = undefined
6. TaskRepository.js:402 - 访问未定义属性 ❌ 报错
   ↓ this.memoryCache.set(oldTask.id, oldTask)
   ❌ TypeError: Cannot read properties of undefined (reading 'id')
```

### 3. 为什么之前没发现？

- **Day1-4 后端开发**：后端单元测试通过，Service层返回格式正确
- **Day5-6 前端开发**：前端代码编写时，未与后端实际返回格式对齐
- **Day7 集成测试**：用户手动测试时才发现问题

**根本原因**：前后端接口对接时缺少格式验证，导致不一致问题。

## 🛠️ 修复方案

### 修复策略

**方案选择**：修改前端代码，与后端返回格式对齐（后端格式更合理，`originalTask` 语义更清晰）

**原因**：
1. 后端已发布且有单元测试覆盖，修改成本高
2. `originalTask` 比 `oldTask` 语义更清晰（强调"原始任务"）
3. 前端只需修改4处代码，影响范围小

### 修复内容

#### 文件1: frontend/Planning-app/repositories/TaskRepository.js

**修改位置**: 第398-411行

**修改前**：
```javascript
// result = { oldTask, newTask }
const { oldTask, newTask } = result

// 更新旧任务缓存（UNTIL已修改）
this.memoryCache.set(oldTask.id, oldTask)

// 添加新任务到缓存
this.memoryCache.set(newTask.id, newTask)

// 持久化
this._saveToLocalStorage()

// ⭐ 发布事件：通知订阅者任务已更新
this._notify('updateTaskFuture', { oldTask, newTask })
```

**修改后**：
```javascript
// result = { originalTask, newTask }（后端返回的键名）
const { originalTask, newTask } = result

// 更新旧任务缓存（UNTIL已修改）
this.memoryCache.set(originalTask.id, originalTask)

// 添加新任务到缓存
this.memoryCache.set(newTask.id, newTask)

// 持久化
this._saveToLocalStorage()

// ⭐ 发布事件：通知订阅者任务已更新
this._notify('updateTaskFuture', { originalTask, newTask })
```

**修改说明**：
- 4处修改：解构声明（1处）、缓存写入（1处）、事件发布（1处）、注释（1处）
- 使用 `sed` 命令批量替换，确保无遗漏

#### 文件2: frontend/Planning-app/store/task.js

**修改位置**: 第299行注释

**修改前**：
```javascript
/**
 * @returns {Promise<object>} { oldTask, newTask }
 */
```

**修改后**：
```javascript
/**
 * @returns {Promise<object>} { originalTask, newTask }
 */
```

**修改说明**：
- 仅更新JSDoc注释，保持文档与代码一致
