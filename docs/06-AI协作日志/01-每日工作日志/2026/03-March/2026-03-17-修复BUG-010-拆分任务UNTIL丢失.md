# 2026-03-17 工作日志：修复BUG-010 拆分有UNTIL的任务时新任务UNTIL丢失

**日期**: 2026-03-17
**作者**: Claude Sonnet 4.5
**任务**: 修复拆分有结束日期的任务时UNTIL丢失
**类型**: BUG修复
**优先级**: P1（逻辑错误）

---

## 📋 任务概述

**背景**：
- 用户发现拆分有结束日期的重复任务时，新任务变成了永久重复
- 例如：原任务UNTIL=2026-03-20，在19号拆分，新任务UNTIL=NULL（错误）

**目标**：
- 修复拆分逻辑，使新任务保留原任务的结束日期
- 确保时间区间完整拆分：[17-18] + [19-20] = [17-20]

---

## 🔍 问题分析

### 错误场景

**原任务**：
- DTSTART=2026-03-17
- UNTIL=2026-03-20
- 时间范围：17-18-19-20（共4天）

**操作**：19号拖拽任务，选择"选项2：更改当天及未来计划"

**当前行为（错误）**：
```
旧任务109：DTSTART=2026-03-17, UNTIL=2026-03-18（17-18）✅
新任务110：DTSTART=2026-03-19, UNTIL=NULL（永久重复）❌

问题：原本20号就结束的任务，拆分后变成永久重复了！
```

**期望行为（正确）**：
```
旧任务109：DTSTART=2026-03-17, UNTIL=2026-03-18（17-18）✅
新任务110：DTSTART=2026-03-19, UNTIL=2026-03-20（19-20）✅

时间区间完整拆分：[17-18] + [19-20] = [17-20]（原始区间）✅
```

### 根本原因

**问题位置**：`backend/src/services/RecurringTaskService.js` 第335行

**问题代码**：
```javascript
// _updateRRuleStartDate 方法
const { until, dtstart, ...cleanOptions } = options;
// ❌ 解构赋值时排除了until字段

const newRRule = new RRule({
  ...cleanOptions,  // 不包含until
  dtstart: new Date(newStartDate + 'T00:00:00Z')
  // until字段丢失 → 新任务变成永久重复
});
```

**为什么会排除until？**

在BUG-009修复时（commit 0ffc79d），为了解决"UNTIL参数通过`...options`展开运算符错误继承"的问题，我们排除了`until`字段。

但是，**那次修复的场景是错误的**：
- BUG-009场景：新任务继承了**旧任务修改后的UNTIL**（错误）
- BUG-010场景：新任务应该继承**原任务的UNTIL**（正确）

**关键区别**：
```
BUG-009（0ffc79d修复的问题）：
- 第92行：旧任务RRULE被修改，添加UNTIL=2026-03-20
- 第107行：使用修改后的RRULE创建新任务
- 问题：新任务继承了修改后的UNTIL → 导致DTSTART > UNTIL

BUG-010（本次修复的问题）：
- 第74行：保存原始RRULE（包含原始UNTIL=2026-03-20）
- 第107行：使用原始RRULE创建新任务
- 问题：_updateRRuleStartDate方法排除了until → 新任务丢失UNTIL
```

**正确逻辑**：
- 第74行保存的`originalRRuleString`包含原始UNTIL
- 第107行调用`_updateRRuleStartDate(originalRRuleString, splitDate)`
- `_updateRRuleStartDate`应该保留原始UNTIL，只更新dtstart

---

## ✅ 修复方案

### 修复：只排除dtstart，保留until

**文件**：`backend/src/services/RecurringTaskService.js`
**位置**：第329-351行（`_updateRRuleStartDate`方法）

**修改前**：
```javascript
_updateRRuleStartDate(rruleString, newStartDate) {
  try {
    const rrule = rrulestr(rruleString);
    const options = rrule.options;

    // ❌ 排除了until和dtstart
    const { until, dtstart, ...cleanOptions } = options;

    // ❌ 新RRULE不包含until → 变成永久重复
    const newRRule = new RRule({
      ...cleanOptions,
      dtstart: new Date(newStartDate + 'T00:00:00Z')
    });

    return newRRule.toString();
  } catch (error) {
    console.error('更新RRULE开始日期失败:', error);
    throw error;
  }
}
```

**修改后**：
```javascript
_updateRRuleStartDate(rruleString, newStartDate) {
  try {
    const rrule = rrulestr(rruleString);
    const options = rrule.options;

    // ⭐ 只排除dtstart字段，保留until字段（如果原始RRULE有的话）
    // 这样可以保持原任务的结束日期
    const { dtstart, ...cleanOptions } = options;

    // ⭐ 创建新RRULE：更新dtstart，保留原始until（如果存在）
    // - 如果原任务有UNTIL → 新任务保留这个UNTIL（维持原结束日期）
    // - 如果原任务无UNTIL → 新任务也无UNTIL（继续永久重复）
    const newRRule = new RRule({
      ...cleanOptions,  // 包含原始的until（如果有）
      dtstart: new Date(newStartDate + 'T00:00:00Z')
    });

    return newRRule.toString();
  } catch (error) {
    console.error('更新RRULE开始日期失败:', error);
    throw error;
  }
}
```

**关键改动**：
- 第336行：从 `const { until, dtstart, ...cleanOptions } = options;`
  改为 `const { dtstart, ...cleanOptions } = options;`
- 只排除`dtstart`，保留`until`（如果原始RRULE有的话）
- 新RRule对象包含原始的`until`字段

**原任务**：

**拆分操作**（19号拖拽，选择"选项2"）：

```javascript
// 1. 第74行：保存原始RRULE（包含UNTIL=2026-03-20）
const originalRRuleString = originalTask.rrule;

// 2. 第82-94行：修改旧任务，添加UNTIL=2026-03-18
const newOriginalRRule = new RRule({
  ...originalOptions,
  until: new Date('2026-03-18T23:59:59Z')  // 19号前一天

originalTask.rrule = newOriginalRRule.toString();

// 3. 第107行：创建新任务，使用原始RRULE

// 4. _updateRRuleStartDate 内部（修复后）：
const { dtstart, ...cleanOptions } = options;  // 保留until
const newRRule = new RRule({
  ...cleanOptions,  // 包含until=2026-03-20
```

## 🎯 总结

### BUG修复链条

```
BUG-007（cf70dcd）→ 前端键名不匹配
    ↓
BUG-008第一次（259a7d4）→ 添加 until: null（不完整）
    ↓

    ↓

    ↓

```

### 关键经验

1. **过度修复的陷阱**：BUG-009修复时排除了`until`，虽然解决了当时的问题，但引入了新问题
2. **场景区分**：需要区分"继承修改后的UNTIL"（错误）vs"继承原始UNTIL"（正确）
3. **时间区间完整性**：拆分任务应保持时间区间完整：[17-18] + [19-20] = [17-20]
4. **逻辑一致性**：有UNTIL的任务拆分后，两个任务应该共享同一个结束日期
