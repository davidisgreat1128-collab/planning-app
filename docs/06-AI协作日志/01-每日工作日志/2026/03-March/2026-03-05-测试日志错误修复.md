### 2. 错误修复实施 (20分钟)

#### 错误1: 缺失API导出函数 ⭐ P0

**问题详情**:
```
SyntaxError: The requested module '/api/task.js' does not provide an export named 'updateTaskRecurrence'
  at useTaskQuadrant.js:33:10
```

**根本原因**:
- `useTaskQuadrant.js` 第33行导入: `import { updateTaskRecurrence } from '@/api/task';`
- `api/task.js` 中没有导出此函数
- 该函数在 `confirmChangeQuadrant()` 中被调用(第195, 198行)

**解决方案**:
在 `api/task.js` 中添加缺失的函数导出:

```javascript
/**
 * 更新重复任务的象限属性(批量更新)
 * @param {number} taskId - 原始任务ID
 * @param {object} data - 更新数据 { isUrgent, isImportant }
 * @param {string} scope - 更新范围 'all'(全部更改) | 'future'(当天及未来)
 * @returns {Promise<object>}
 */
export const updateTaskRecurrence = (taskId, data, scope) =>
  patch(`/tasks/${taskId}/recurrence`, { ...data, scope });
```

**修改文件**: [api/task.js](../../frontend/Planning-app/api/task.js) 第120-128行

#### 错误2: 分页参数超限 ⭐ P1

**问题详情**:
```
业务错误: pageSize must be less than or equal to 100
GET /api/v1/planning?page=1&pageSize=200 400 (Bad Request)
```

**根本原因**:
- `PlanningRepository.js` 第257行请求 `pageSize: 200`
- 后端Joi验证规则限制 `pageSize` 最大值为100
- 导致数据同步失败(被try-catch捕获,静默失败)

**解决方案**:
修改分页参数为符合后端限制的值:

```javascript
// 修改前:
const result = await getPlanningListApi({ page: 1, pageSize: 200 })

// 修改后:
const result = await getPlanningListApi({ page: 1, pageSize: 100 })
```

**修改文件**: [PlanningRepository.js](../../frontend/Planning-app/repositories/PlanningRepository.js) 第257行

#### 错误3: 未导出的方法调用 ⭐ P1

**问题详情**:
- `index.vue` 第398, 410行调用 `dragDropComposable.endDrag()`
- `useDragDrop.js` 的返回对象中没有导出 `endDrag` 方法
- 该方法在代码中根本不存在(grep搜索结果为空)

**根本原因**:
- 拖拽结束后需要重置状态
- 原计划使用 `endDrag()` 但该函数从未创建
- `useDragDrop.js` 已有 `cancelDrag()` 方法,功能相同

**解决方案**:
使用已存在的 `cancelDrag()` 替代不存在的 `endDrag()`:

```javascript
// 修改前:
dragDropComposable.endDrag();

// 修改后:
dragDropComposable.cancelDrag();
```

**语义分析**: `cancelDrag` 更准确,因为当 `fromQuadrant === toQuadrant` 时,拖拽是被取消而非正常结束。

**修改文件**: [index.vue](../../frontend/Planning-app/pages/calendar/index.vue) 第398, 410行

## 🔍 技术决策

### 决策1: 为什么选择 cancelDrag 而非创建 endDrag?

**备选方案**:
- 方案A: 创建 `endDrag` 函数(本质是 `cancelDrag` 的别名)
- 方案B: 直接使用 `cancelDrag` 替代 `endDrag`

**选择方案B的理由**:
1. **语义准确性**: 当拖拽无效时(同象限或无任务),是"取消"而非"结束"
2. **避免冗余**: `cancelDrag` 已有完整实现,无需重复代码
3. **代码简洁**: 减少一个函数定义,降低维护成本

**代码对比**:
```javascript
// cancelDrag 的实现(已存在):
function cancelDrag() {
  dragState.value.dragging = false;
  dragState.value.task = null;
  dragState.value.fromQuadrant = '';
  pressedTaskId.value = null;
}

// 如果创建 endDrag,代码会重复:
function endDrag() {
  cancelDrag(); // 本质上只是调用 cancelDrag
}
```

## 🎯 问题根源分析

### 为什么会出现这些错误?

1. **API导出遗漏**:
   - 在重构过程中创建了 `useTaskQuadrant.js`
   - 该Composable需要调用后端接口更新重复任务
   - 但未同步在 `api/task.js` 中添加对应函数
   - **预防措施**: API函数与Composable同步开发,遵循TDD

2. **后端限制未同步**:
   - 后端修改了Joi验证规则(max: 100)
   - 前端代码未同步更新参数值
   - **预防措施**: 后端变更API限制时,必须通知前端并更新文档

3. **方法命名不一致**:
   - 开发时计划使用 `endDrag`
   - 实际实现时只创建了 `cancelDrag`
   - 调用代码未同步更新
   - **预防措施**: 使用TypeScript或ESLint进行静态检查
