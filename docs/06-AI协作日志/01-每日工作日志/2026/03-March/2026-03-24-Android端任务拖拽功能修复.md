### 2. 添加长按检测逻辑（BUG-2）

#### 问题诊断

**用户反馈**：
> "现在测试安卓端，控制台没有警告也没有报错，但是BUG很多，请设计详细日志，在控制台输出测试日志；例如：长按Q1任务 → 拖到Q2 → 松手；目前点击某个"任务"，就出现任务副本；根本不需要长按"

**从日志发现问题**（HBuilderX.txt第一版）：
```
20:10:06.104 👆 [TaskCard] handleTouchStart 被触发
20:10:06.104 🚀 [TaskCard] emit("drag-start")  ← 立即触发！
20:10:06.104 🟢 [useDragDrop] startDrag() 被调用
```

**根本原因**：
- `TaskCard.vue` 的 `@touchstart` 事件直接触发 `drag-start`
- 没有500ms长按延迟检测
- 导致任何点击都立即触发拖拽

#### 解决方案

**添加长按检测状态**（APP端专用）：
```javascript
// #ifndef H5
let longPressTimer = null;  // 长按定时器
const touchStartPos = ref({ x: 0, y: 0 });  // 触摸起始位置
const LONG_PRESS_DELAY = 500;  // 长按延迟（毫秒）
const MOVE_THRESHOLD = 10;  // 移动阈值（像素）
// #endif
```

**实现长按检测函数**（APP端专用）：

1. **handleTouchStart**：启动500ms定时器
   ```javascript
   function handleTouchStart(e) {
     if (!props.draggable) return;

     // 记录触摸起始位置
     const touch = e.touches?.[0] || e.changedTouches?.[0];
     touchStartPos.value = {
       x: touch.clientX || touch.pageX || 0,
       y: touch.clientY || touch.pageY || 0
     };

     // 清除旧定时器
     if (longPressTimer) clearTimeout(longPressTimer);

     // 启动长按定时器（500ms）
     longPressTimer = setTimeout(() => {
       // 触发拖拽开始事件
       emit('drag-start', e, props.task, props.quadrant);
       longPressTimer = null;
     }, LONG_PRESS_DELAY);
   }
   ```

2. **handleTouchMove**：如果移动>10px则取消长按
   ```javascript
   function handleTouchMove(e) {
     if (!longPressTimer) return;

     const touch = e.touches?.[0] || e.changedTouches?.[0];
     const currentX = touch.clientX || touch.pageX || 0;
     const currentY = touch.clientY || touch.pageY || 0;

     const deltaX = Math.abs(currentX - touchStartPos.value.x);
     const deltaY = Math.abs(currentY - touchStartPos.value.y);

     // 如果移动超过阈值，取消长按
     if (deltaX > MOVE_THRESHOLD || deltaY > MOVE_THRESHOLD) {
       clearTimeout(longPressTimer);
       longPressTimer = null;
     }
   }
   ```

3. **handleTouchEnd**：清除定时器（未到500ms则取消拖拽）
   ```javascript
   function handleTouchEnd(e) {
     if (longPressTimer) {
       clearTimeout(longPressTimer);
       longPressTimer = null;
     }
   }
   ```

4. **handleTouchCancel**：处理系统中断
   ```javascript
   function handleTouchCancel(e) {
     if (longPressTimer) {
       clearTimeout(longPressTimer);
       longPressTimer = null;
     }
   }
   ```

**模板中绑定事件**（条件编译）：
```vue
<view
  class="task-card"
  <!-- #ifndef H5 -->
  @touchstart="handleTouchStart"
  @touchmove="handleTouchMove"
  @touchend="handleTouchEnd"
  @touchcancel="handleTouchCancel"
  <!-- #endif -->
  <!-- #ifdef H5 -->
  @mousedown="handleMouseDown"
  <!-- #endif -->
  @tap="handleTaskClick"
>
```

**H5端保持原有逻辑**：
```javascript

  if (!props.draggable) return;
  emit('mouse-drag-start', e, props.task);
}
// #endif
```

### 3. 转发scroll-view事件到useDragDrop（BUG-3）

#### 问题诊断

**用户反馈**：
> "查看"D:\MyProject\Planning设计\测试日志\HBuilderX.txt"，还是不能拖拽；连松开，任务副本消失逻辑也没实现"

**从日志发现问题**（HBuilderX.txt第二版）：
```
20:24:14.632 🟢 [useDragDrop] startDrag() 被调用  ← drag started ✅
20:24:14.632 ✅ [useDragDrop] dragState 已更新 (dragging: true)
20:24:15.768 🔴 [TaskCard] handleTouchEnd 被触发  ← but only TaskCard end!

Missing logs:
❌ No 🔵 [useDragDrop] onTaskTouchMove logs
❌ No 🔴 [useDragDrop] onTaskTouchEnd logs
❌ No 🔍 [useDragDrop] detectQuadrantAtPosition logs
```

**根本原因分析**：
1. TaskCard触发 `drag-start` → `useDragDrop.startDrag()` 设置 `dragging=true` ✅
2. 用户移动手指 → scroll-view的 `@touchmove` → `onContentTouchMove` ❌
3. 但`onContentTouchMove`只处理日历折叠，没有转发到useDragDrop ❌
4. 同理，`onContentTouchEnd`也没有转发 ❌

**关键认识**：
- scroll-view捕获了触摸事件（事件冒泡机制）
- TaskCard的 `@touchmove` 和 `@touchend` 无法触发（被scroll-view拦截）
- 必须在scroll-view的事件处理函数中检测拖拽状态并转发

#### 解决方案

**修改 `index.vue` 的事件处理函数**：

1. **onContentTouchMove**（第1176-1180行）：
   ```javascript
   function onContentTouchMove(e) {
     // #ifndef H5
     // ⭐ APP端：如果正在拖拽，调用拖拽移动逻辑
     if (dragDropComposable.dragState.value.dragging) {
       console.log('📍 [index.vue] onContentTouchMove: 检测到拖拽中，调用 useDragDrop');
       dragDropComposable.onTaskTouchMove(e);
       return; // 拖拽时不处理日历折叠
     }
     // #endif

     // 在月视图模式下，如果向上滑动且已滚动到顶部，触发折叠
     if (calendarComposable.calendarMode.value === 'month' && contentScrollTop.value === 0) {
       const dy = e.touches[0].clientY - contentTouchStartY.value;
       if (dy < -50) {
         calendarComposable.collapseToWeek();
       }
     }
   }
   ```

2. **onContentTouchEnd**（第1202-1206行）：
   ```javascript
   function onContentTouchEnd(e) {
     // #ifndef H5
     // ⭐ APP端：如果正在拖拽，调用拖拽结束逻辑
     if (dragDropComposable.dragState.value.dragging) {
       console.log('🔴 [index.vue] onContentTouchEnd: 检测到拖拽中，调用 useDragDrop');
       dragDropComposable.onTaskTouchEnd(e);
     }
     // #endif

     // 清理状态
     contentTouchStartY.value = 0;
   }
   ```

**事件委托流程图**：
```
用户触摸任务 → TaskCard.handleTouchStart
  → 500ms后 → TaskCard emit("drag-start")
  → index.vue 接收 → dragDropComposable.startDrag()
  → 设置 dragging=true

用户移动手指 → scroll-view @touchmove → index.vue onContentTouchMove
  ├─ 检查 dragState.dragging === true?
  ├─ Yes → 转发到 dragDropComposable.onTaskTouchMove(e)
  └─ No → 处理日历折叠逻辑

用户松开 → scroll-view @touchend → index.vue onContentTouchEnd
  ├─ 检查 dragState.dragging === true?
  └─ Yes → 转发到 dragDropComposable.onTaskTouchEnd(e)
       → 移动任务 → 重置状态
```

### 决策1：长按检测逻辑放在Component层

**背景**：需要实现500ms长按检测才触发拖拽

**选项**：
1. 放在Component层（TaskCard.vue）
2. 放在Composable层（useDragDrop.js）
3. 提取到独立的 `useLongPress.js` Composable

**选择**：选项1（放在Component层）

**理由**：
1. **CLAUDE.md第7.9节规定**：Composable层禁止访问浏览器API（如setTimeout、touch事件）
2. **长按检测属于用户交互逻辑**，不是业务逻辑
3. **Component的职责**：处理UI和用户交互 → 长按检测属于用户交互 ✅

**用户确认**：
- 问题："以上修改是否符合四层架构"
- 回答："✅ 符合，长按检测属于用户交互逻辑，应放在Component层"

### 决策2：暂不提取 useLongPress.js

**背景**：长按检测是否需要提取到独立的Composable

**选项**：
1. 立即提取到 `useLongPress.js`
2. 暂不提取，保留在TaskCard中

**选择**：选项2（暂不提取）

**理由**：
1. **复用性**：目前只有TaskCard需要长按检测，未来其他组件可能需要时再提取
2. **文件大小**：TaskCard.vue = 606行 < 800行阈值 ✅
3. **单一职责**：TaskCard的职责仍然清晰（任务卡片 + 长按检测）
4. **提取成本**：提取后需要Composable访问event对象，违反架构规范

**用户确认**：
- 问题："拖拽逻辑是单一职责，是否创建单独文件"
- 回答："✅ 暂不需要，文件大小和复用性都未超标，未来需要时再提取"

**背景**：TaskCard的touchmove/touchend被scroll-view拦截

1. 在scroll-view的事件处理函数中检测拖拽状态并转发

- ✅ 使用条件编译（`#ifdef H5`、`#ifndef H5`）严格分离

## 🎓 经验总结

### 技术要点

1. **UniApp条件编译的重要性**
   - APP端和H5端事件机制完全不同
   - 必须使用 `#ifdef H5` / `#ifndef H5` 严格分离
   - 模板、脚本、样式都需要条件编译

2. **长按检测实现方案**
   - 500ms定时器 + 10px移动阈值
   - 必须在touchend和touchcancel中清理定时器（防止内存泄漏）
   - APP端和H5端检测逻辑分离（APP在Component，H5在Composable）

3. **scroll-view事件拦截机制**
   - scroll-view会拦截子组件的touchmove/touchend事件
   - 必须在scroll-view的事件处理函数中检测拖拽状态并转发
   - 使用条件转发（dragging=true时转发，否则正常滚动）

4. **四层架构的边界**
   - Component层：UI渲染 + 用户交互（触摸事件、长按检测）✅
   - Composable层：业务逻辑（不应访问DOM或浏览器API）✅
   - 长按检测属于用户交互，应放Component层 ✅

### 4. 修复删除区域检测失败（BUG-4）⭐ 核心BUG

#### 问题诊断

**从HBuilderX.txt日志分析**：
```
Line 102: overDelete: false  // 应该为true当拖入删除区域时
Line 243: overDelete: false  // 整个拖拽过程中始终为false
缺失日志: deleteRect的值未被记录（说明deleteRect为null）
```

**根本原因**（DOM渲染时序问题）：
1. DragOverlay.vue的delete-zone元素在 `v-if="dragState.dragging"` 内部
2. `startDrag()` 设置 `dragging = true` 时，Vue调度DOM更新（异步）
3. 但 `updateQuadrantRects()` 在第142行同步调用
4. 此时delete-zone元素还未渲染到DOM
5. `uni.createSelectorQuery().select('.delete-zone')` 返回null
6. 结果：`quadrantRects.value.delete = null`

#### 解决方案

**方案A**（采用）：添加setTimeout延迟，等待Vue DOM更新周期
```javascript
// 修改前（行140-144）
// #ifndef H5
// APP端:获取所有象限和删除区域的位置信息
updateQuadrantRects();
console.log('🔍 [useDragDrop] APP端: 开始获取象限位置');
// #endif

// 修改后
// #ifndef H5
// APP端:延迟获取位置信息（等待拖拽蒙层DOM渲染完成）
setTimeout(() => {
  updateQuadrantRects();
  console.log('🔍 [useDragDrop] APP端: 延迟100ms后获取象限和删除区域位置');
}, 100);
// #endif
```

**原理**：
- Vue的响应式更新是异步的（nextTick机制）
- setTimeout将DOM查询推迟到下一个事件循环
- 保证delete-zone元素已渲染到DOM

**添加详细日志**（行168-202）：
```javascript

  query.select('.quadrant-q3').boundingClientRect();
  query.select('.quadrant-q4').boundingClientRect();

        q1: res[0],

        q3: res[2],

  });
```

```javascript
function openTask(task) {
  console.log('🎯 [index.vue] openTask 被调用', {
    taskId: task.id,
    taskTitle: task.title
  });

  // #ifndef H5
  // APP端：检查拖拽状态，避免拖拽结束时误触发跳转
  if (dragDropComposable.dragState.value.dragging) {
```
