## 1. 检查概述

### 1.1 检查范围

本次检查覆盖"重复任务拖动3个选项"功能的完整调用链：

```
Component（UI层）
    ↓
Composable（业务流程层）
    ↓
Store（状态管理层）
    ↓
Repository（数据访问层）
    ↓
API（后端Service层）
```

### 1.2 核心文件清单

| 层级 | 文件路径 | 行数 | 职责 |
|------|---------|------|------|
| **Component** | `pages/calendar/index.vue` | 789行 | UI交互、拖拽事件处理 |
| **Composable** | `composables/useTaskQuadrant.js` | 433行 | 象限管理业务逻辑 |
| **Store** | `store/task.js` | ~400行 | 任务状态管理 |
| **Repository** | `repositories/TaskRepository.js` | ~600行 | 数据持久化、缓存、队列 |
| **Service** | `backend/src/services/RecurringTaskService.js` | 355行 | 重复任务核心业务逻辑 |

### 1.3 三个选项的调用路径

#### 选项1：完整更改此条重复计划

```
Component (拖拽事件)
  → useTaskQuadrant.changeTaskQuadrant()
  → useTaskQuadrant.confirmChangeQuadrant() [option=1]
  → taskStore.updateTask()
  → TaskRepository.update()
  → API PUT /tasks/:id
  → 后端直接更新Task表
```

#### 选项2：更改当天及未来计划

```
Component (拖拽事件)
  → useTaskQuadrant.changeTaskQuadrant()
  → useTaskQuadrant.confirmChangeQuadrant() [option=2]
  → taskStore.updateTaskFuture()
  → TaskRepository.updateTaskFuture()
  → API POST /tasks/:id/modify-future
  → RecurringTaskService.modifyFuture()
  → 拆分任务规则（旧任务UNTIL截止 + 创建新任务）
```

#### 选项3：只更新当天计划

```
Component (拖拽事件)
  → useTaskQuadrant.changeTaskQuadrant()
  → useTaskQuadrant.confirmChangeQuadrant() [option=3]
  → taskStore.updateTaskSingleDay()
  → TaskRepository.updateTaskSingleDay()
  → API POST /tasks/:id/modify-single-day
  → RecurringTaskService.modifySingleDay()
  → 创建task_overrides记录
```

## 2. 四层架构符合性

### 2.1 检查标准（CLAUDE.md 第7.9节）

**四层架构规范**：
- Component 层：UI渲染、用户交互
- Composable 层：复杂业务流程、多Store协调
- Store 层：全局状态管理、调用Repository
- Repository 层：数据CRUD、缓存、离线队列、同步

**禁止行为**：
- ❌ Component 直接调用 Repository/API
- ❌ Composable 直接调用 Repository/API
- ❌ Store 直接调用 API（绕过Repository）

```javascript
async updateTaskSingleDay(id, data, date) {
  const task = this.memoryCache.get(id)
  if (!task) {
    throw new Error(`任务不存在：${id}`)
  }

  try {
    // ✅ 调用后端API

      url: `/tasks/${id}/modify-single-day`,

      data: { date, updates: data }

    return override
  } catch (error) {
    console.error('[TaskRepository] 修改单日实例失败:', error)
    throw error
  }
}

// 选项2：修改未来实例
async updateTaskFuture(id, data, splitDate) {
  const task = this.memoryCache.get(id)
  if (!task) {
    throw new Error(`任务不存在：${id}`)
  }

  try {
    // ✅ 调用后端API
    const result = await request({
      url: `/tasks/${id}/modify-future`,
      method: 'POST',
      data: { splitDate, updates: data }
    })

    const { originalTask, newTask } = result

    // ✅ 更新缓存
    this.memoryCache.set(originalTask.id, originalTask)
    this.memoryCache.set(newTask.id, newTask)

    // ✅ 持久化
    this._saveToLocalStorage()

    // ✅ 通知订阅者
    this._notify('updateTaskFuture', { originalTask, newTask })

    return result
  } catch (error) {
    console.error('[TaskRepository] 修改未来实例失败:', error)
    throw error
  }
}
```

**符合性**：
- ✅ 所有数据操作都通过Repository层

- ✅ 发布-订阅模式通知Store层
- ✅ 统一错误处理

## 5. 单一职责原则符合性

### 5.1 检查标准（CLAUDE.md 第8.0节 SRP）

**核心原则**：一个组件只应该有一个改变的理由（一个职责）
