## 📊 性能影响

### 渲染性能

**旧版**：
- 2个 `scroll-view` 组件（通过 `v-if` 切换）
- 每次Tab切换需要销毁/重建DOM
- 切换有轻微延迟

**新版**：
- 1个 `scroll-view` 组件
- 所有列表项一次性渲染
- 无Tab切换，无延迟

**性能提升**：
- 减少50%的 scroll-view 组件
- 消除Tab切换的重渲染开销

### 内存占用

假设有10个分类 + 5个规划：

**旧版**：
- 分类Tab：10个列表项 + 1个按钮 = 11个节点
- 规划Tab：5个列表项 + 1个按钮 = 6个节点
- Tab栏：2个Tab = 2个节点
- **总计**：19个节点（但同时只显示13个）

**新版**：
- 1个顶部栏：2个按钮 = 2个节点
- 统一列表：1个无分类 + 10个分类 + 5个规划 = 16个节点
- **总计**：18个节点（全部显示）

**内存优化**：节点数接近，但布局更简单
