## 2. 备份策略

### 2.1 备份优先级

| 优先级 | 数据类型 | 备份频率 | 保留时长 | 恢复时间目标（RTO） |
|--------|---------|---------|---------|-------------------|
| **P0** | MySQL 数据库 | 每天 4 次 | 30 天 | < 1 小时 |
| **P0** | Docker Hub 镜像 ✅ | 每次发布 | 永久 | < 3 分钟 |
| **P1** | .env 配置文件 | 每次修改后 | 永久 | < 5 分钟 |
| **P1** | 用户上传文件 | 每天 1 次 | 90 天 | < 2 小时 |
| **P2** | Redis 数据 | 每天 1 次 | 7 天 | < 30 分钟 |
| **P2** | SSL 证书 | 每周 1 次 | 90 天 | < 10 分钟 |
| **P3** | 应用日志 | 每周 1 次 | 30 天 | 不恢复 |
| **P3** | Nginx 日志 | 每周 1 次 | 7 天 | 不恢复 |

## 3. 自动备份脚本

### 3.1 MySQL 数据库备份脚本

**文件**: `scripts/backup-mysql.sh`

```bash
#!/bin/bash
# ============================================================
# Planning App - MySQL 数据库自动备份脚本
# ============================================================
# 功能: 每天4次备份（00:00, 06:00, 12:00, 18:00）
# 保留策略: 7天内保留所有备份，7-30天仅保留每日首次备份
# ============================================================

set -e

# ============================================================
# 配置变量
# ============================================================
BACKUP_DIR="/opt/planning-app/backups/mysql"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
DATE_ONLY=$(date +"%Y%m%d")
BACKUP_FILE="planning_app_${TIMESTAMP}.sql"
BACKUP_PATH="${BACKUP_DIR}/daily/${BACKUP_FILE}"

# Docker容器名称
MYSQL_CONTAINER="planning-app-mysql"

# 加载环境变量
if [ -f "/opt/planning-app/planning-app/.env" ]; then
    export $(grep -v '^#' /opt/planning-app/planning-app/.env | xargs)
fi

# ============================================================
# 创建备份目录
# ============================================================
mkdir -p "${BACKUP_DIR}/daily"
mkdir -p "${BACKUP_DIR}/weekly"
mkdir -p "${BACKUP_DIR}/monthly"

# ============================================================
# 执行备份
# ============================================================
echo "[$(date)] 开始备份 MySQL 数据库..."

docker exec "$MYSQL_CONTAINER" mysqldump \
    -u root \
    -p"${MYSQL_ROOT_PASSWORD}" \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --databases "${MYSQL_DATABASE}" \
    > "$BACKUP_PATH"

# 压缩备份文件
gzip "$BACKUP_PATH"
BACKUP_PATH="${BACKUP_PATH}.gz"

echo "[$(date)] 备份完成: ${BACKUP_PATH}"

# 获取备份文件大小
BACKUP_SIZE=$(du -h "$BACKUP_PATH" | cut -f1)
echo "[$(date)] 备份大小: ${BACKUP_SIZE}"

# ============================================================
# 每周备份（周日执行）
# ============================================================
if [ "$(date +%u)" -eq 7 ]; then
    WEEKLY_FILE="planning_app_weekly_${DATE_ONLY}.sql.gz"
    cp "$BACKUP_PATH" "${BACKUP_DIR}/weekly/${WEEKLY_FILE}"
    echo "[$(date)] 已创建周备份: ${WEEKLY_FILE}"
fi

# ============================================================
# 每月备份（每月1日执行）
# ============================================================
if [ "$(date +%d)" -eq 1 ]; then
    MONTHLY_FILE="planning_app_monthly_$(date +%Y%m).sql.gz"
    cp "$BACKUP_PATH" "${BACKUP_DIR}/monthly/${MONTHLY_FILE}"
    echo "[$(date)] 已创建月备份: ${MONTHLY_FILE}"
fi

# ============================================================
# 清理过期备份
# ============================================================
echo "[$(date)] 清理过期备份..."

# 删除7天前的每日备份
find "${BACKUP_DIR}/daily" -name "*.sql.gz" -mtime +7 -delete

# 删除30天前的每周备份
find "${BACKUP_DIR}/weekly" -name "*.sql.gz" -mtime +30 -delete

# 删除365天前的每月备份
find "${BACKUP_DIR}/monthly" -name "*.sql.gz" -mtime +365 -delete

echo "[$(date)] 备份任务完成"

# ============================================================
# 上传到远程存储（可选）
# ============================================================
# 如果配置了腾讯云COS
if command -v coscmd &> /dev/null; then
    coscmd upload "$BACKUP_PATH" "/mysql/$(basename $BACKUP_PATH)"
    echo "[$(date)] 已上传到腾讯云COS"
fi
```

### 3.2 配置文件备份脚本

**文件**: `scripts/backup-config.sh`

```bash
#!/bin/bash
# ============================================================
# Planning App - 配置文件备份脚本
# ============================================================
# 功能: 备份 .env, SSL证书等关键配置
# ============================================================

set -e

BACKUP_DIR="/opt/planning-app/backups/config"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
APP_DIR="/opt/planning-app/planning-app"

mkdir -p "$BACKUP_DIR"

# 备份 .env
if [ -f "${APP_DIR}/.env" ]; then
    cp "${APP_DIR}/.env" "${BACKUP_DIR}/.env.${TIMESTAMP}"
    echo "[$(date)] 已备份 .env"
fi

# 备份 SSL 证书
if [ -d "/etc/letsencrypt/live/txjjzyzqbx.cn" ]; then
    tar -czf "${BACKUP_DIR}/ssl_${TIMESTAMP}.tar.gz" \
        /etc/letsencrypt/live/txjjzyzqbx.cn \
        /etc/letsencrypt/renewal/txjjzyzqbx.cn.conf
    echo "[$(date)] 已备份 SSL 证书"
fi

# 备份 Docker Compose 配置
cp "${APP_DIR}/docker-compose.yml" "${BACKUP_DIR}/docker-compose.yml.${TIMESTAMP}"

echo "[$(date)] 配置文件备份完成"
```

### 3.3 完整备份脚本（一键备份）

**文件**: `scripts/backup-all.sh`

```bash
#!/bin/bash
# ============================================================
# Planning App - 一键完整备份脚本
# ============================================================
# 功能: 备份所有关键数据（数据库、配置、上传文件）
# 使用场景: 重大升级前、服务器迁移前
# ============================================================

set -e

BACKUP_ROOT="/opt/planning-app/backups"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
FULL_BACKUP_DIR="${BACKUP_ROOT}/full_backup_${TIMESTAMP}"

mkdir -p "$FULL_BACKUP_DIR"

echo "=========================================="
echo "Planning App - 完整备份"
echo "时间: $(date)"
echo "=========================================="

# 1. 备份 MySQL 数据库
echo "[1/6] 备份 MySQL 数据库..."
bash /opt/planning-app/planning-app/scripts/backup-mysql.sh
cp "${BACKUP_ROOT}/mysql/daily/"*.sql.gz "$FULL_BACKUP_DIR/"

# 2. 备份 Redis 数据
echo "[2/6] 备份 Redis 数据..."
docker exec planning-app-redis redis-cli -a "${REDIS_PASSWORD}" SAVE
docker cp planning-app-redis:/data/dump.rdb "${FULL_BACKUP_DIR}/redis_dump.rdb"

# 3. 备份配置文件
echo "[3/6] 备份配置文件..."
bash /opt/planning-app/planning-app/scripts/backup-config.sh
cp -r "${BACKUP_ROOT}/config" "$FULL_BACKUP_DIR/"

# 4. 备份用户上传文件
echo "[4/6] 备份用户上传文件..."
if [ -d "/opt/planning-app/planning-app/backend/uploads" ]; then
    tar -czf "${FULL_BACKUP_DIR}/uploads.tar.gz" \
        /opt/planning-app/planning-app/backend/uploads
fi

# 5. 备份应用日志
echo "[5/6] 备份应用日志..."
if [ -d "/opt/planning-app/planning-app/backend/logs" ]; then
    tar -czf "${FULL_BACKUP_DIR}/logs.tar.gz" \
        /opt/planning-app/planning-app/backend/logs
fi

# 6. 创建备份清单
echo "[6/6] 生成备份清单..."
cat > "${FULL_BACKUP_DIR}/BACKUP_INFO.txt" <<EOF
Planning App 完整备份
=====================
备份时间: $(date)
备份目录: ${FULL_BACKUP_DIR}

包含内容:
- MySQL 数据库备份
- Redis 数据备份
- .env 配置文件
- SSL 证书
- Docker Compose 配置
- 用户上传文件
- 应用日志

恢复说明:
请参考 docs/02-技术设计/灾难恢复和备份方案.md

版本信息:
$(cd /opt/planning-app/planning-app && git log -1 --oneline)
EOF

# 计算备份大小
BACKUP_SIZE=$(du -sh "$FULL_BACKUP_DIR" | cut -f1)

echo "=========================================="
echo "✅ 备份完成！"
echo "备份位置: ${FULL_BACKUP_DIR}"
echo "备份大小: ${BACKUP_SIZE}"
echo "=========================================="

# 可选: 打包为单个压缩文件
echo "是否打包为单个文件？(y/N)"
read -r PACK_CHOICE
if [ "$PACK_CHOICE" = "y" ] || [ "$PACK_CHOICE" = "Y" ]; then
    cd "$BACKUP_ROOT"
    tar -czf "full_backup_${TIMESTAMP}.tar.gz" "full_backup_${TIMESTAMP}"
    echo "✅ 已打包: ${BACKUP_ROOT}/full_backup_${TIMESTAMP}.tar.gz"
fi
```

## 4. 灾难恢复流程

### 4.1 场景1: 服务器完全崩溃（需要重建）

**前提条件**:
- 有最新的 MySQL 备份文件
- 有 .env 配置文件备份
- GitHub 仓库代码完整

**恢复步骤**（预计时间：20-40 分钟，⚡ 镜像拉取方案比构建快10-20分钟）:

```bash
# ============================================================
# 步骤1: 准备新服务器
# ============================================================
# 1.1 安装 Docker 和 Docker Compose
curl -fsSL https://get.docker.com | bash
sudo apt install docker-compose-plugin -y

# 1.2 安装 Git
sudo apt install git -y

# 1.3 克隆代码仓库
cd /opt
sudo mkdir planning-app
cd planning-app
sudo git clone git@github.com:davidisgreat1128-collab/planning-app.git

# ============================================================
# 步骤2: 恢复配置文件
# ============================================================
# 2.1 从备份恢复 .env
sudo scp user@backup-server:/backups/.env.20260321 /opt/planning-app/planning-app/.env

# 或手动创建（如果有记录）
sudo nano /opt/planning-app/planning-app/.env
# 填入所有环境变量

# 2.2 验证 .env 文件
cat /opt/planning-app/planning-app/.env

# ============================================================
# 步骤3: 拉取 Backend 镜像（⚡ 快速恢复，1-3分钟）
# ============================================================
# ⭐ 优先方案：从 Docker Hub 拉取镜像（使用镜像加速器，速度快）
sudo docker pull davidisgreat1128/planning-app-backend:v1.0.0
sudo docker tag davidisgreat1128/planning-app-backend:v1.0.0 planning-app-backend:latest

# 备选方案：本地构建镜像（如果拉取失败，耗时5-10分钟）
# cd /opt/planning-app/planning-app/backend
# sudo docker build -t planning-app-backend:latest .

# ============================================================
# 步骤4: 启动 Docker 服务（不含数据）
# ============================================================
cd /opt/planning-app/planning-app
sudo docker compose up -d

# 等待服务启动
sleep 60

# ============================================================
# 步骤5: 恢复 MySQL 数据库
# ============================================================
# 5.1 从备份服务器下载最新备份
sudo scp user@backup-server:/backups/mysql/planning_app_20260321_120000.sql.gz /tmp/

# 5.2 解压备份文件
gunzip /tmp/planning_app_20260321_120000.sql.gz

# 5.3 导入数据库
sudo docker exec -i planning-app-mysql mysql \
    -u root \
    -p"${MYSQL_ROOT_PASSWORD}" \
    < /tmp/planning_app_20260321_120000.sql

# 5.4 验证数据恢复
sudo docker exec planning-app-mysql mysql \
    -u root \
    -p"${MYSQL_ROOT_PASSWORD}" \
    -e "USE planning_app_prod; SHOW TABLES; SELECT COUNT(*) FROM users;"

# ============================================================
# 步骤6: 恢复 Redis 数据（如有备份）
# ============================================================
# 6.1 停止 Redis 容器
sudo docker compose stop redis

# 6.2 恢复 dump.rdb
sudo docker cp /tmp/redis_dump.rdb planning-app-redis:/data/dump.rdb

# 6.3 重启 Redis
sudo docker compose start redis

# ============================================================
# 步骤7: 恢复用户上传文件
# ============================================================
sudo tar -xzf /tmp/uploads.tar.gz -C /opt/planning-app/planning-app/backend/

# ============================================================
# 步骤8: 申请 SSL 证书
# ============================================================
# 8.1 确保域名 DNS 已解析到新服务器IP
dig txjjzyzqbx.cn

# 8.2 申请证书
sudo certbot --nginx -d txjjzyzqbx.cn -d www.txjjzyzqbx.cn

# 8.3 配置自动续期
sudo crontab -e
# 添加: 0 3 * * 0 certbot renew --quiet && systemctl reload nginx

# ============================================================
# 步骤9: 启用 HTTPS 配置
# ============================================================
cd /opt/planning-app/planning-app
sudo bash scripts/deploy-production.sh ssl-only

# ============================================================
# 步骤10: 验证生产环境
# ============================================================
sudo bash scripts/verify-production-fixed.sh

# ============================================================
# 步骤11: 配置自动备份
# ============================================================
sudo crontab -e
# 添加 MySQL 备份任务（每天4次）
# 0 0,6,12,18 * * * /opt/planning-app/planning-app/scripts/backup-mysql.sh >> /var/log/planning-app-backup.log 2>&1
```

### 4.2 场景2: 数据库误删除/损坏

**恢复步骤**（预计时间：10-15 分钟）:

```bash
# 1. 停止后端服务（避免新数据写入）
sudo docker compose stop backend

# 2. 查找最新备份
ls -lh /opt/planning-app/backups/mysql/daily/ | tail -5

# 3. 恢复数据库
BACKUP_FILE="/opt/planning-app/backups/mysql/daily/planning_app_20260321_180000.sql.gz"
gunzip -c "$BACKUP_FILE" | sudo docker exec -i planning-app-mysql mysql \
    -u root \
    -p"${MYSQL_ROOT_PASSWORD}"

# 4. 验证数据
```
