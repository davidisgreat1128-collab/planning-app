## 1. 架构概览

### 1.1 三层架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    Component 层（UI 层）                      │
│  category-drawer.vue / task-edit.vue / index.vue             │
│                                                               │
│  职责：                                                       │
│  ✅ 用户交互（点击、输入、拖拽）                              │
│  ✅ 数据展示（渲染列表、表单）                                │
│  ✅ 调用 Store 的 actions                                    │
│  ❌ 禁止直接调用 Repository 或 API                           │
└──────────────────────┬──────────────────────────────────────┘
                       │ dispatch actions
                       ↓
┌─────────────────────────────────────────────────────────────┐
│                    Store 层（状态管理层）                     │
│  categoryStore / taskStore / planningStore                   │
│                                                               │
│  职责：                                                       │
│  ✅ 全局状态管理（Pinia）                                     │
│  ✅ 调用 Repository 的方法                                   │
│  ✅ 提供计算属性（computed）                                 │
│  ✅ 管理业务逻辑（如任务四象限分组）                          │
│  ❌ 禁止直接调用 API                                         │
│  ❌ 禁止直接操作 localStorage                                │
└──────────────────────┬──────────────────────────────────────┘
                       │ call repository methods
                       ↓
┌─────────────────────────────────────────────────────────────┐
│                Repository 层（数据访问层）                    │
│  CategoryRepository / TaskRepository / PlanningRepository    │
│                                                               │
│  职责：                                                       │
│  ✅ 数据 CRUD 操作                                           │
│  ✅ memoryCache 内存缓存（Map 结构）                         │
│  ✅ localStorage 持久化                                      │
│  ✅ operationQueue 离线操作队列                              │
│  ✅ 版本控制（乐观锁，version 字段）                         │
│  ✅ syncWithServer() 后台同步                                │
│  ❌ 禁止访问 Vue 实例或 DOM                                  │
└──────────────────────┬──────────────────────────────────────┘
                       │ HTTP requests (RESTful API)
                       ↓
┌─────────────────────────────────────────────────────────────┐
│                    API 层（后端接口）                         │
│  POST /api/v1/categories                                     │
│  PUT  /api/v1/categories/:id                                 │
│  DELETE /api/v1/categories/:id                               │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 数据流向

#### 读取数据流（自上而下）

```
用户打开页面
    ↓
Component 调用 Store.hydrate()
    ↓
Store 调用 Repository.hydrate()
    ↓
Repository 从 localStorage 加载缓存
    ↓
Repository 从服务器同步最新数据
    ↓
Repository 更新 memoryCache
    ↓
Store 通过 computed 自动更新
    ↓
Component 自动重新渲染
```

#### 写入数据流（自下而上）

```
用户点击"保存"按钮
    ↓
Component 调用 Store.createCategory(data)
    ↓
Store 调用 Repository.create(data)
    ↓
Repository 更新 memoryCache
    ↓
Repository 写入 localStorage（debounce 500ms）
    ↓
Repository 添加操作到 operationQueue
    ↓
Repository 后台同步到服务器（debounce 500ms）
    ↓
服务器返回成功
    ↓
Repository 清理 operationQueue
    ↓
Store 自动更新（computed 属性）
    ↓
Component 自动重新渲染
```

### 1.3 每层职责边界

| 层级 | 可以做 | 不可以做 |
|------|--------|---------|
| **Component** | ✅ 调用 Store 的 actions<br>✅ 展示数据<br>✅ 用户交互处理 | ❌ 直接调用 API<br>❌ 直接访问 Repository<br>❌ 直接操作 localStorage |
| **Store** | ✅ 调用 Repository<br>✅ 管理全局状态<br>✅ 提供计算属性 | ❌ 直接调用 API<br>❌ 直接操作 localStorage<br>❌ 访问 DOM |
| **Repository** | ✅ 调用 API<br>✅ 管理缓存<br>✅ 操作 localStorage | ❌ 访问 Vue 实例<br>❌ 访问 DOM<br>❌ 调用 uni API（除 uni.request） |

## 2. Repository 层详解

### 2.1 Repository 标准接口

每个 Repository 必须实现以下方法：

```javascript
/**
 * 基础 Repository 接口
 * @template T 实体类型
 */
class BaseRepository {
  /**
   * 启动时加载数据（从 localStorage + 服务器）
   * @returns {Promise<void>}
   */
  async hydrate() { ... }

  /**
   * 获取全部数据（从内存缓存，已排序）
   * @returns {T[]}
   */
  getAll() { ... }

  /**
   * 按 ID 获取单条数据
   * @param {string} id
   * @returns {T | null}
   */
  getById(id) { ... }

  /**
   * 创建数据
   * @param {Partial<T>} data
   * @returns {Promise<T>}
   */
  async create(data) { ... }

  /**
   * 更新数据
   * @param {string} id
   * @param {Partial<T>} data
   * @returns {Promise<T>}
   */
  async update(id, data) { ... }

  /**
   * 删除数据（软删除，标记 deletedAt）
   * @param {string} id
   * @returns {Promise<void>}
   */
  async delete(id) { ... }

  /**
   * 同步到服务器
   * @returns {Promise<void>}
   */
  async sync() { ... }
}
```

### 2.2 CategoryRepository 完整实现

#### 2.2.1 数据结构

```javascript
/**
 * 分类实体
 */
interface Category {
  id: string              // 唯一标识（cat_timestamp_random）
  name: string            // 分类名称
  sortOrder: number       // 排序字段（支持拖拽）
  version: number         // 版本号（乐观锁）
  createdAt: number       // 创建时间戳
  updatedAt: number       // 更新时间戳
  deletedAt: number | null // 软删除时间戳
}

/**
 * 操作队列项
 */
interface QueueOperation {
  id: string              // 操作唯一 ID
  type: 'create' | 'update' | 'delete'
  entityId: string        // 实体 ID
  data: Partial<Category> // 操作数据
  timestamp: number       // 操作时间戳
  status: 'pending' | 'syncing' | 'failed'
  retryCount: number      // 重试次数
}
```

#### 2.2.2 核心属性

```javascript
class CategoryRepository {
  constructor() {
    // 内存缓存（Map: id → category）
    this.memoryCache = new Map()

    // 离线操作队列
    this.operationQueue = []

    // Debounce 定时器
    this.saveTimer = null

    // 同步状态
    this.isSyncing = false
    this.lastSyncTime = null
  }
}
```

**为什么用 Map 而非数组？**
- 查找性能：`O(1)` vs `O(n)`
- 更新效率：直接 `map.set(id, data)` vs 需要 `findIndex` 后替换
- 删除效率：直接 `map.delete(id)` vs 需要 `splice`

#### 2.2.3 hydrate 启动流程

```javascript
/**
 * 启动时加载数据（三步流程）
 */
async hydrate() {
  // 步骤1: 从 localStorage 加载缓存（离线可用）
  this._loadFromLocalStorage()

  // 步骤2: 从服务器同步最新数据（在线时）
  try {
    await this.sync()
  } catch (err) {
    // 离线模式，使用本地缓存
    console.warn('离线模式，使用本地缓存', err)
  }

  // 步骤3: 重放操作队列（上传未同步的修改）
  await this._replayQueue()
}
```

**调用时机**：App 启动时，在 `App.vue` 的 `onLaunch` 中调用：

```javascript
// App.vue
import { useCategoryStore } from '@/store/category'

export default {
  onLaunch() {
    const categoryStore = useCategoryStore()
    await categoryStore.hydrate()
  }
}
```

#### 2.2.4 内存缓存管理

```javascript
/**
 * 获取所有分类（已排序，过滤已删除）
 */
getAll() {
  return Array.from(this.memoryCache.values())
    .filter(cat => !cat.deletedAt)  // 过滤软删除
    .sort((a, b) => (a.sortOrder || 0) - (b.sortOrder || 0))  // 按 sortOrder 排序
}

/**
 * 按 ID 获取分类
 */
getById(id) {
  const cat = this.memoryCache.get(id)
  return cat && !cat.deletedAt ? cat : null  // 软删除的视为不存在
}
```

#### 2.2.5 创建操作

```javascript
/**
 * 创建分类
 */
async create(data) {
  // 1. 构造完整对象
  const category = {
    id: this._generateId(),  // 生成唯一 ID
    ...data,
    version: 1,              // 初始版本号
    createdAt: Date.now(),
    updatedAt: Date.now(),
    deletedAt: null
  }

  // 2. 更新内存缓存
  this.memoryCache.set(category.id, category)

  // 3. 添加到操作队列
  this._addToQueue({
    type: 'create',
    entityId: category.id,
    data: category
  })

  // 4. 持久化到 localStorage
  this._saveToLocalStorage()

  // 5. 后台同步到服务器（debounce 500ms）
  this._debouncedSync()

  return category
}
```

**为什么用 debounce？**

场景：用户快速创建3个分类（间隔 < 200ms）

- ❌ **不用 debounce**：触发3次同步请求 → 服务器压力大
- ✅ **用 debounce**：只触发1次同步请求（500ms 后） → 批量上传

#### 2.2.6 更新操作（乐观锁）

```javascript
/**
 * 更新分类（乐观锁版本控制）
 */
async update(id, data) {
  const category = this.memoryCache.get(id)
  if (!category) throw new Error('分类不存在')

  // 乐观锁：递增 version
  const updated = {
    ...category,
    ...data,
    version: category.version + 1,  // ← 关键：版本号+1
    updatedAt: Date.now()
  }

  // 更新缓存
  this.memoryCache.set(id, updated)

  // 添加到队列
  this._addToQueue({
    type: 'update',
    entityId: id,
    data: updated
  })

  // 持久化 + 同步
  this._saveToLocalStorage()
  this._debouncedSync()

  return updated
}
```

**版本冲突检测（在 sync 时）**：

```javascript
// 本地修改
localCategory = { id: 1, name: 'A', version: 5 }

// 服务器最新数据
serverCategory = { id: 1, name: 'B', version: 6 }

// 冲突判断
if (serverCategory.version > localCategory.version) {
  // 服务器更新 → 使用服务器版本（覆盖本地）
  this.memoryCache.set(id, serverCategory)
  console.warn(`版本冲突：${serverCategory.name}，使用服务器版本`)
}
// 否则保留本地版本（本地优先策略）
```

#### 2.2.7 软删除

```javascript
/**
 * 删除分类（软删除）
 */
async delete(id) {
  const category = this.memoryCache.get(id)
  if (!category) throw new Error('分类不存在')

  // 标记为已删除（保留数据）
  category.deletedAt = Date.now()

  // 添加到队列
  this._addToQueue({
    type: 'delete',
    entityId: id,
    data: { deletedAt: category.deletedAt }
  })

  // 持久化（保留已删除数据在缓存中）
  this._saveToLocalStorage()

  // 后台同步
  this._debouncedSync()
}
```

**为什么保留已删除数据？**

1. **撤销功能**：用户误删后可恢复
2. **同步需要**：需要告知服务器"这条数据已删除"
3. **审计追踪**：保留删除时间和操作记录

**清理策略**：定期任务清理 30 天前的软删除数据

#### 2.2.8 localStorage 持久化

```javascript
// 配置常量
const STORAGE_KEY = 'planning_app_categories'
const QUEUE_KEY = 'planning_app_category_queue'

/**
 * 保存到 localStorage
 */
_saveToLocalStorage() {
  const categories = Array.from(this.memoryCache.values())
  localStorage.setItem(STORAGE_KEY, JSON.stringify(categories))
  localStorage.setItem(QUEUE_KEY, JSON.stringify(this.operationQueue))
}

/**
 * 从 localStorage 加载
 */
_loadFromLocalStorage() {
  // 加载数据
  const cached = localStorage.getItem(STORAGE_KEY)
  if (cached) {
    const categories = JSON.parse(cached)
    categories.forEach(cat => {
      this.memoryCache.set(cat.id, cat)
    })
  }

  // 加载队列
  const queue = localStorage.getItem(QUEUE_KEY)
  if (queue) {
    this.operationQueue = JSON.parse(queue)
  }
}
```

**localStorage 容量限制**：5MB（约可存储 5000 条分类数据）

#### 2.2.9 syncWithServer 同步逻辑

```javascript
/**
 * 同步到服务器（三步流程）
 */
async sync() {
  if (this.isSyncing) return  // 防止并发同步

  this.isSyncing = true
  try {
    // 步骤1: 获取服务器最新数据
    const serverData = await categoryApi.getAll()

    // 步骤2: 合并服务器数据（处理版本冲突）
    this._mergeServerData(serverData)

    // 步骤3: 上传本地操作队列
    await this._uploadQueue()

    this.lastSyncTime = Date.now()
  } finally {
    this.isSyncing = false
  }
}
```

**合并服务器数据**：

```javascript
/**
 * 合并服务器数据（版本冲突解决）
 */
_mergeServerData(serverData) {
  serverData.forEach(serverCat => {
    const localCat = this.memoryCache.get(serverCat.id)

    if (!localCat) {
      // 服务器有但本地没有 → 新数据，直接添加
      this.memoryCache.set(serverCat.id, serverCat)
    } else if (serverCat.version > localCat.version) {
      // 服务器版本更新 → 覆盖本地
      this.memoryCache.set(serverCat.id, serverCat)
      console.warn(`版本冲突：${serverCat.name}，使用服务器版本`)
    }
    // 否则保留本地版本（本地优先）
  })

  this._saveToLocalStorage()
}
```

## 3. Store 层详解

### 3.1 Store 职责

**Store 是什么？**

Store 是 Pinia 状态管理库的核心，负责：
1. 管理全局状态（响应式数据）
2. 提供计算属性（computed）
3. 提供 actions（调用 Repository）

**Store 不是什么？**

Store 不负责：
- ❌ 数据持久化（由 Repository 管理）
- ❌ HTTP 请求（由 Repository 调用 API）
- ❌ DOM 操作（由 Component 管理）

### 3.2 CategoryStore 完整示例

```javascript
// frontend/Planning-app/store/category.js
import { defineStore } from 'pinia'
import { computed } from 'vue'
import CategoryRepository from '@/repositories/CategoryRepository'

export const useCategoryStore = defineStore('category', () => {
  // ========== 状态（State）==========

  /**
   * 所有分类（计算属性，自动从 Repository 获取）
   */
  const categories = computed(() => CategoryRepository.getAll())

  // ========== 计算属性（Getters）==========

  /**
   * 激活的分类数量
   */
  const activeCategoriesCount = computed(() => {
    return categories.value.length
  })

  /**
   * 按名称查找分类（模糊匹配）
   */
  function getCategoriesByName(name) {
    return categories.value.filter(cat => cat.name.includes(name))
  }

  // ========== 操作（Actions）==========

  /**
   * 启动时加载数据
   */
  async function hydrate() {
    await CategoryRepository.hydrate()
  }

  /**
   * 创建分类
   */
  async function createCategory(data) {
    return await CategoryRepository.create(data)
  }

  /**
   * 更新分类
   */
  async function updateCategory(id, data) {
    return await CategoryRepository.update(id, data)
  }

  /**
   * 删除分类
   */
  async function deleteCategory(id) {
    await CategoryRepository.delete(id)
  }

  /**
   * 重新排序（拖拽后调用）
   */
  async function reorderCategories(newOrder) {
    // newOrder: [{ id: 'cat_1', sortOrder: 0 }, { id: 'cat_2', sortOrder: 1 }, ...]
    for (const item of newOrder) {
      await CategoryRepository.update(item.id, { sortOrder: item.sortOrder })
    }
  }

  /**
   * 按 ID 获取分类
   */
  function getCategoryById(id) {
    return CategoryRepository.getById(id)
  }

  /**
   * 手动同步到服务器
   */
  async function sync() {
    await CategoryRepository.sync()
  }

  // ========== 导出 ==========

  return {
    // 状态
    categories,
    activeCategoriesCount,

    // 方法
    hydrate,
    createCategory,
    updateCategory,
    deleteCategory,
    reorderCategories,
    getCategoryById,
    getCategoriesByName,
    sync
  }
})
```

### 3.3 Store 使用示例（在 Component 中）

```vue
<!-- category-drawer.vue -->
<script setup>
import { ref } from 'vue'
import { useCategoryStore } from '@/store/category'

const categoryStore = useCategoryStore()

// 响应式数据（自动更新）
const categories = categoryStore.categories

// 创建分类
const newCategoryName = ref('')
async function handleCreate() {
  await categoryStore.createCategory({ name: newCategoryName.value })
  newCategoryName.value = ''
}

// 删除分类
async function handleDelete(id) {
  await categoryStore.deleteCategory(id)
}
</script>

<template>
  <view>
    <!-- 分类列表（自动渲染，无需手动刷新） -->
    <view v-for="cat in categories" :key="cat.id">
      {{ cat.name }}
      <button @tap="handleDelete(cat.id)">删除</button>
    </view>

    <!-- 创建表单 -->
    <input v-model="newCategoryName" />
    <button @tap="handleCreate">创建</button>
  </view>
</template>
```

**为什么 categories 自动更新？**

因为 `categories` 是 `computed` 计算属性：
1. Repository.memoryCache 更新
2. `categories = computed(() => Repository.getAll())` 自动重新计算
3. Vue 自动重新渲染组件

## 4. Component 层详解

### 4.1 Component 职责

Component 是 Vue 组件，负责：
1. **用户交互**：点击、输入、拖拽、滚动
2. **数据展示**：渲染列表、表单、图表
3. **调用 Store**：通过 actions 修改数据

Component **不应该**：
- ❌ 直接调用 API
- ❌ 直接访问 Repository
- ❌ 直接操作 localStorage
- ❌ 编写复杂业务逻辑（应在 Store 或 Repository）

### 4.2 迁移示例

#### 示例1：创建分类

**❌ 旧写法（直接调用 API）**：

```javascript
// category-drawer.vue（旧代码）
import { categoryApi } from '@/api/category'

const categories = ref([])

async function saveCategory() {
  const res = await categoryApi.create({ name: form.value.name })
  categories.value.push(res.data)  // 手动更新数组
}
```

**问题**：
1. 状态不同步：其他组件的 categories 不会更新
2. 无离线支持：网络断开时失败
3. 无缓存：刷新页面数据丢失

**✅ 新写法（调用 Store）**：

```javascript
// category-drawer.vue（新代码）
import { useCategoryStore } from '@/store/category'

const categoryStore = useCategoryStore()
const categories = categoryStore.categories  // 响应式

async function saveCategory() {
  await categoryStore.createCategory({ name: form.value.name })
  // 无需手动更新，categories 自动同步
}
```

**优势**：
1. 全局同步：所有组件自动更新
2. 离线支持：自动添加到队列
3. 持久化：自动保存到 localStorage

#### 示例2：删除分类

**❌ 旧写法**：

```javascript
async function deleteCategory(id) {
  await categoryApi.delete(id)
  const index = categories.value.findIndex(c => c.id === id)
  categories.value.splice(index, 1)  // 手动删除
}
```

**✅ 新写法**：

```javascript
async function deleteCategory(id) {
  await categoryStore.deleteCategory(id)
  // 自动从列表移除，无需手动操作
}
```

#### 示例3：拖拽排序

**❌ 旧写法**：

```javascript
async function onDragEnd(result) {
  // 手动重新排序数组
  const newOrder = reorder(categories.value, result.source.index, result.destination.index)
  categories.value = newOrder

  // 手动批量更新
  for (let i = 0; i < newOrder.length; i++) {
    await categoryApi.update(newOrder[i].id, { sortOrder: i })
  }
```

## 5. 离线操作队列设计

### 5.1 队列结构

```javascript
/**
 * 操作队列项
 */
interface QueueOperation {
  id: string              // 操作唯一 ID（op_timestamp_random）
  type: 'create' | 'update' | 'delete'
  entityId: string        // 实体 ID（如 cat_123）
  data: Partial<T>        // 操作数据
  timestamp: number       // 操作时间戳
  status: 'pending' | 'syncing' | 'failed'
  retryCount: number      // 重试次数（0-5）
}
```

### 5.2 添加到队列

```javascript
/**
 * 添加操作到队列
 */
_addToQueue(operation) {
  this.operationQueue.push({
    id: this._generateId(),
    ...operation,
    timestamp: Date.now(),
    status: 'pending',
    retryCount: 0
  })

  // 持久化到 localStorage
  localStorage.setItem(QUEUE_KEY, JSON.stringify(this.operationQueue))
}
```

### 5.3 上传队列（指数退避重试）

```javascript
/**
 * 上传操作队列到服务器
 */
async _uploadQueue() {
  const pendingOps = this.operationQueue.filter(op => op.status === 'pending')

  for (const op of pendingOps) {
    try {
      op.status = 'syncing'

      // 调用 API
      if (op.type === 'create') {
        await categoryApi.create(op.data)
      } else if (op.type === 'update') {
        await categoryApi.update(op.entityId, op.data)
      } else if (op.type === 'delete') {
        await categoryApi.delete(op.entityId)
      }

      // 成功 → 从队列移除
      this.operationQueue = this.operationQueue.filter(o => o.id !== op.id)
    } catch (err) {
      op.status = 'failed'
      op.retryCount++

      // 超过最大重试次数（5次）→ 放弃
      if (op.retryCount >= 5) {
        console.error(`操作失败（已重试5次），放弃`, op)
        this.operationQueue = this.operationQueue.filter(o => o.id !== op.id)
      } else {
        // 指数退避：1s → 2s → 4s → 8s → 16s
        const delay = Math.pow(2, op.retryCount) * 1000
        console.warn(`操作失败，${delay}ms 后重试`, op)
        await new Promise(resolve => setTimeout(resolve, delay))
      }
    }
  }

  // 更新 localStorage
  localStorage.setItem(QUEUE_KEY, JSON.stringify(this.operationQueue))
}
```

**为什么用指数退避？**

| 重试次数 | 延迟 | 说明 |
|---------|------|------|
| 1 | 1秒 | 可能是临时网络抖动 |
| 2 | 2秒 | 网络可能正在恢复 |
| 3 | 4秒 | 等待服务器重启 |
| 4 | 8秒 | 等待网络恢复 |
| 5 | 16秒 | 最后一次尝试 |

避免频繁重试导致服务器压力过大。

### 5.4 同步触发时机

```javascript
// 1. 用户操作后（debounce 500ms）
async create(data) {
  // ...
  this._debouncedSync()  // ← 延迟 500ms 后同步
}

// 2. App 启动时

  // ...
  await this.sync()  // ← 立即同步
}

// 3. 网络恢复时

  await CategoryRepository.sync()
})

// 4. 定时轮询（可选，每 30 秒）

  await CategoryRepository.sync()
}, 30000)
```

## 7. 常见问题FAQ

### Q1：为什么要用三层架构？直接调用 API 不行吗？

**A**：直接调用 API 的问题：

| 问题 | 影响 |
|------|------|
| 状态不同步 | 组件A创建分类，组件B看不到 |
| 无离线支持 | 网络断开时用户无法操作 |
| 无缓存 | 每次刷新页面都要重新加载 |
| 重复代码 | 每个组件都要写 `try-catch`、错误处理 |
| 难以测试 | 必须启动服务器才能测试 |

三层架构解决所有问题：
- ✅ 全局状态同步（Pinia）
- ✅ 离线队列（Repository）
- ✅ 持久化缓存（localStorage）
- ✅ 统一错误处理（Repository 层）
- ✅ 可单元测试（Repository 是纯 JS 类）

### Q2：memoryCache 和 localStorage 有什么区别？

**A**：

| 对比项 | memoryCache (Map) | localStorage |
|--------|------------------|-------------|
| 存储位置 | 内存（RAM） | 浏览器磁盘 |
| 读取速度 | **极快**（纳秒级） | 较慢（毫秒级） |
| 容量 | 无限制（受内存限制） | 5MB |
| 持久化 | ❌ 刷新页面丢失 | ✅ 永久保存 |
| 用途 | 运行时缓存 | 持久化备份 |

**配合使用**：
1. 所有读取从 memoryCache（快）
2. 每次修改同步写入 localStorage（持久化）
3. 启动时从 localStorage 恢复到 memoryCache

### Q3：离线操作队列会不会无限增长？

**A**：不会，有以下保护机制：

1. **自动清理**：同步成功后立即从队列移除
2. **最大重试**：失败 5 次后放弃并移除
3. **定时同步**：网络恢复后自动上传队列
4. **队列持久化**：队列也存到 localStorage，不会因刷新丢失

**极端情况**：离线 1 个月，操作 1000 次
- 队列大小：约 100KB（可接受）
- 恢复上线后：批量上传（约 10 秒）

### Q4：版本冲突（乐观锁）真的会发生吗？

**A**：单用户场景很少发生，但以下情况可能：

| 场景 | 冲突可能性 |
|------|-----------|
| 同一用户，多个设备（手机+电脑） | 中等 |
| 多用户协作（未来扩展） | 高 |
| 用户离线操作 1 周后上线 | 低 |

**解决策略**：
- 当前：本地优先（覆盖服务器）
- 未来：弹窗让用户选择（保留哪个版本）

### Q5：debounce 500ms 会不会导致数据丢失？

**A**：不会，因为：

1. **立即写入 memoryCache**：数据不会丢失
2. **立即写入 localStorage**：即使浏览器崩溃也能恢复
3. **debounce 只影响网络同步**：延迟 500ms 上传服务器

**流程**：
```
用户点击"保存" → 立即更新 memoryCache → 立即写入 localStorage
                 ↓ （500ms 后）
                同步到服务器
```

即使 debounce 期间浏览器崩溃，下次启动时 localStorage 会恢复数据。

### Q6：三层架构会增加代码量吗？

**A**：初期会增加，但长期减少：

| 阶段 | 代码量 | 说明 |
|------|--------|------|
| 第1个功能 | +30% | 需要写 Repository + Store + Component |
| 第2个功能 | +10% | 复用 Repository 和 Store |
| 第3个功能 | +5% | 只需修改 Component |
| 第10个功能 | -20% | 大量复用，代码更简洁 |

**示例**：
- 旧代码：每个组件都写 `try-catch`、错误处理、数组更新（50行）
- 新代码：调用 `categoryStore.create()`（1行）
