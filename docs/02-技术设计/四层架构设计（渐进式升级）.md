## 1. 架构概览

### 1.1 四层架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    Component 层（UI 层）                      │
│  category-drawer.vue / task-edit.vue / index.vue             │
│                                                               │
│  职责：                                                       │
│  ✅ 用户交互（点击、输入、拖拽）                              │

│  ✅ 复杂场景：调用 Composable                                │
│  ❌ 禁止直接调用 Repository 或 API                           │
```

### 1.2 数据流向

#### 三层架构数据流（简单场景）

**读取数据流**：

```
用户打开页面
    ↓
Component 调用 Store.hydrate()
    ↓
Store 调用 Repository.hydrate()
    ↓
Repository 从 localStorage 加载缓存
    ↓
Repository 从服务器同步最新数据
    ↓
Repository 更新 memoryCache
    ↓
Store 通过 computed 自动更新
    ↓
Component 自动重新渲染
```

**写入数据流**：

```
用户点击"保存"按钮
    ↓
Component 调用 Store.createCategory(data)
    ↓
Store 调用 Repository.create(data)
    ↓
Repository 更新 memoryCache
    ↓
Repository 写入 localStorage（debounce 500ms）
    ↓
Repository 添加操作到 operationQueue
    ↓
Repository 后台同步到服务器（debounce 500ms）
    ↓
服务器返回成功
    ↓
Repository 清理 operationQueue
    ↓
Store 自动更新（computed 属性）
    ↓
Component 自动重新渲染
```

#### 四层架构数据流（复杂场景）⭐ 新增

**场景1：复杂表单提交**

```
用户填写表单
    ↓
Component 调用 Composable.submitTask()
    ↓
Composable 验证表单数据
    ↓
Composable 调用 taskStore.updateTask(data)
    ↓
Composable 调用 categoryStore.updateCategory(data)  // 多Store协调
    ↓
Composable 调用 planStore.linkTaskToPlan(data)
    ↓
各 Store 分别调用对应的 Repository
    ↓
Repository 更新缓存、写入localStorage、同步服务器
    ↓
Composable 处理成功/失败逻辑
    ↓
Component 显示结果（成功提示/错误信息）
```

**场景2：页面业务流程（拖拽）**

```
用户拖拽任务
    ↓
Component 调用 Composable.handleDragStart()
    ↓
Composable 初始化拖拽状态机（状态：idle → dragging）
    ↓
用户移动 → Component 调用 Composable.handleDragMove()
    ↓
Composable 更新拖拽坐标、计算目标日期
    ↓
用户放下 → Component 调用 Composable.handleDragEnd()
    ↓
Composable 调用 taskStore.moveTask(taskId, newDate)
    ↓
Store 调用 Repository.update()
    ↓
Repository 同步到服务器
    ↓
拖拽状态机转换：dragging → idle
    ↓
Component 自动重新渲染
```

### 1.3 每层职责边界

| 层级 | 可以做 | 不可以做 |
|------|--------|---------|
| **Component** | ✅ 简单场景：调用 Store<br>✅ 复杂场景：调用 Composable<br>✅ 展示数据<br>✅ 用户交互处理 | ❌ 直接调用 API<br>❌ 直接访问 Repository<br>❌ 直接操作 localStorage<br>❌ 编写复杂业务逻辑 |
| **Composable** ⭐ | ✅ 封装复杂表单逻辑<br>✅ 协调多个 Store<br>✅ 管理页面业务流程<br>✅ 提供可复用业务逻辑 | ❌ 全局状态管理<br>❌ 数据持久化<br>❌ 直接调用 Repository<br>❌ 直接调用 API<br>❌ 访问 DOM |
| **Store** | ✅ 调用 Repository<br>✅ 管理全局状态<br>✅ 提供计算属性 | ❌ 直接调用 API<br>❌ 直接操作 localStorage<br>❌ 访问 DOM |
| **Repository** | ✅ 调用 API<br>✅ 管理缓存<br>✅ 操作 localStorage | ❌ 访问 Vue 实例<br>❌ 访问 DOM<br>❌ 调用 uni API（除 uni.request） |

## 2. 架构演进说明（三层 → 四层）

### 2.1 为什么升级到四层架构？

在项目发展过程中，三层架构（Component → Store → Repository）在以下场景中遇到了问题：

#### 问题1：复杂表单逻辑无处安放

**场景**：任务编辑表单（task-edit.vue）

- 30+ 个表单字段
- 15+ 个验证规则
- 5+ 个格式化函数
- 协调 3 个 Store（taskStore + categoryStore + planStore）

**困境**：

- ❌ 放 Component？→ Component 过重（3265行）
- ❌ 放 Store？→ 不是全局状态，是单个页面的临时状态
- ❌ 放 Repository？→ Repository 只负责数据访问，不管业务逻辑

**解决方案**：提取 **useTaskForm.js**（Composable 层）

- 821行业务逻辑从 Component 中分离
- task-edit.vue 和 AddTaskPanel.vue 复用同一逻辑
- **消除 70% 代码重复**

#### 问题2：多Store协调逻辑分散

**场景**：任务编辑需要同时操作：

- taskStore.updateTask()
- categoryStore.linkTaskToCategory()
- planStore.linkTaskToPlan()
- holidayStore.checkDateConflict()

**困境**：

- 放 Component？→ Component 过重，难以测试
- 放某个 Store？→ 跨 Store 调用破坏单一职责

**解决方案**：Composable 层协调多个 Store

```javascript
// useTaskForm.js（Composable层）
async function submitTask() {
  // 协调多个 Store
  await taskStore.updateTask(form.value)
  await categoryStore.linkTaskToCategory(form.value.categoryId)
  await planStore.linkTaskToPlan(form.value.planId)
}
```

#### 问题3：可复用业务逻辑散落

**场景**：象限管理逻辑在多个页面中重复：

- task-edit.vue（任务编辑）
- AddTaskPanel.vue（快速添加）
- index.vue（日历页面）

**解决方案**：提取 **useTaskQuadrant.js**（Composable 层）

- 统一的象限切换、颜色获取、优先级计算逻辑
- 3 个页面复用同一 Composable
- **消除代码重复，保持逻辑一致性**

### 2.2 四层架构的关键决策 ⭐

**Composable 层是可选的，不是强制的**

```
简单场景（保留三层架构）：
Component → Store → Repository → API
  ↑
  └─ 用于简单列表展示、简单CRUD等场景

复杂场景（使用四层架构）：
Component → Composable → Store → Repository → API
  ↑
  └─ 用于复杂表单、多Store协调、页面业务流程等场景
```

**何时使用 Composable？**

| 场景 | 是否使用 Composable |
|------|-------------------|
| 简单列表展示 | ❌ 三层架构即可 |
| 简单 CRUD | ❌ 三层架构即可 |
| 复杂表单（>15个字段） | ✅ 提取 useXxxForm.js |
| 需要协调 3+ 个 Store | ✅ 提取 Composable |
| 多个页面重复业务逻辑 | ✅ 提取可复用 Composable |
| 页面级复杂交互（拖拽） | ✅ 提取状态机 Composable |

## 3. Composable 层详解 ⭐ 新增

### 3.1 什么是 Composable？

Composable 是 Vue 3 Composition API 的可复用逻辑单元，命名规范为 `useXxx.js`。

**Composable 的本质**：

- 封装可复用的**业务流程**
- 返回响应式状态和方法
- 可以组合使用（Composable 调用其他 Composable）

**Composable ≠ Store**：

| 对比项 | Composable | Store |
|--------|-----------|-------|
| 作用域 | 局部状态（组件级） | 全局状态（应用级） |
| 持久化 | ❌ 不持久化 | ✅ 持久化（通过 Repository） |
| 复用性 | ✅ 多个组件可复用同一逻辑 | ✅ 全局唯一实例 |
| 用途 | 业务流程封装 | 数据状态管理 |

### 3.2 Composable 标准结构

```javascript
// composables/useTaskForm.js（标准模板）

import { ref, computed } from 'vue'
import { useTaskStore } from '@/store/task'
import { useCategoryStore } from '@/store/category'
import { usePlanStore } from '@/store/plan'

/**
 * 任务表单业务逻辑
 * @param {object} options - 配置选项
 * @param {string} options.mode - 'create' | 'edit'
 * @param {string} options.taskId - 任务ID（编辑模式需要）
 * @returns {object} 表单状态和方法
 */
export function useTaskForm(options = {}) {
  // ============================================================
  // 1. 引入 Store（可以引入多个）
  // ============================================================
  const taskStore = useTaskStore()
  const categoryStore = useCategoryStore()
  const planStore = usePlanStore()

  // ============================================================
  // 2. 响应式状态（局部状态，不放 Store）
  // ============================================================
  const form = ref({
    title: '',
    description: '',
    categoryId: null,
    planId: null,
    quadrant: 'q4',
    startDate: null,
    endDate: null
  })
  const errors = ref({})
  const isSubmitting = ref(false)

  // ============================================================
  // 3. 计算属性（基于 Store 数据）
  // ============================================================
  const isFormValid = computed(() => {
    return form.value.title.length > 0 && Object.keys(errors.value).length === 0
  })

  // ============================================================
  // 4. 业务方法（协调多个 Store）
  // ============================================================

  /**
   * 验证表单
   * @returns {boolean} 是否通过验证
   */
  function validateForm() {
    errors.value = {}
    if (!form.value.title) {
      errors.value.title = '标题不能为空'
    }
    if (form.value.title.length > 100) {
      errors.value.title = '标题不能超过100个字符'
    }
    return Object.keys(errors.value).length === 0
  }

  /**
   * 提交表单（协调多个 Store）
   * @returns {Promise<object>} 创建/更新后的任务对象
   */
  async function submitForm() {
    if (!validateForm()) {
      throw new Error('表单验证失败')
    }

    isSubmitting.value = true
    try {
      // 协调多个 Store
      const task = await taskStore.createTask(form.value)
      if (form.value.categoryId) {
        await categoryStore.linkTaskToCategory(task.id, form.value.categoryId)
      }
      if (form.value.planId) {
        await planStore.linkTaskToPlan(task.id, form.value.planId)
      }
      return task
    } finally {
      isSubmitting.value = false
    }
  }

  /**
   * 重置表单
   */
  function resetForm() {
    form.value = {
      title: '',
      description: '',
      categoryId: null,
      planId: null,
      quadrant: 'q4',
      startDate: null,
      endDate: null
    }
    errors.value = {}
  }

  // ============================================================
  // 5. 返回公开接口
  // ============================================================
  return {
    // 状态
    form,
    errors,
    isSubmitting,
    // 计算属性
    isFormValid,
    // 方法
    validateForm,
    submitForm,
    resetForm
  }
}
```

### 3.3 在 Component 中使用 Composable

```vue
<!-- task-edit.vue -->
<script setup>
import { useTaskForm } from '@/composables/useTaskForm'

// 调用 Composable
const { form, errors, isFormValid, submitForm, resetForm } = useTaskForm({
  mode: 'create'
})

// Component 只处理 UI 逻辑
async function handleSubmit() {
  try {
    await submitForm()
    uni.showToast({ title: '保存成功', icon: 'success' })
    uni.navigateBack()
  } catch (error) {
    uni.showToast({ title: error.message, icon: 'none' })
  }
}
</script>

<template>
  <view class="form">
    <input :value="form.title" @input="form.title = $event.detail.value" placeholder="任务标题" />
    <text v-if="errors.title" class="error">{{ errors.title }}</text>
    <button :disabled="!isFormValid" @tap="handleSubmit">保存</button>
  </view>
</template>
```

**优势**：

- Component 只有 30 行代码（原来 700+行）
- 业务逻辑全部在 Composable（可复用、可测试）
- task-edit.vue 和 AddTaskPanel.vue 复用同一 Composable

### 3.4 Composable 使用场景

#### 场景1：复杂表单逻辑

**适用条件**：

- 表单字段 > 15 个
- 验证规则 > 10 个
- 需要协调多个 Store

**示例**：useTaskForm、usePlanningForm

#### 场景2：多Store协调

**适用条件**：

- 需要同时操作 3+ 个 Store
- Store 之间有依赖关系

**示例**：

```javascript
// useTaskSubmit.js
async function submitTask() {
  // 协调多个 Store
  const task = await taskStore.createTask(data)
  await categoryStore.linkTask(task.id, categoryId)
  await planStore.linkTask(task.id, planId)
  await holidayStore.checkConflict(task.startDate)
}
```

#### 场景3：页面级业务流程

**适用条件**：

- 复杂交互逻辑（拖拽、手势、动画）
- 状态机管理（idle → dragging → dropping）

**示例**：useDragDrop、useSwipeAction

```javascript
// useDragDrop.js（拖拽状态机）
const state = ref('idle')  // idle | dragging | dropping
const draggedItem = ref(null)

function handleDragStart(item) {
  state.value = 'dragging'
  draggedItem.value = item
}

function handleDragEnd() {
  state.value = 'idle'
  draggedItem.value = null
}
```

#### 场景4：可复用业务逻辑

**适用条件**：

- 多个页面需要相同的业务逻辑
- 逻辑独立于具体页面

**示例**：useTaskQuadrant、useTaskPriority

```javascript
// useTaskQuadrant.js（象限管理）
function getQuadrantColor(quadrant) {
  const colors = { q1: '#FF6B6B', q2: '#4ECDC4', q3: '#FFE66D', q4: '#95E1D3' }
  return colors[quadrant]
}

function getQuadrantLabel(quadrant) {
  const labels = { q1: '重要紧急', q2: '重要不紧急', q3: '不重要紧急', q4: '不重要不紧急' }
  return labels[quadrant]
}
```

### 3.5 Composable 禁止事项

| 禁止操作 | 原因 | 正确做法 |
|---------|------|---------|
| ❌ 写全局状态 | 多个页面状态互相干扰 | 全局状态放 Store |
| ❌ 直接调用 Repository | 破坏分层架构 | 通过 Store 调用 |
| ❌ 直接调用 API | 破坏分层架构 | 通过 Store 调用 |
| ❌ 数据持久化 | 职责不明确 | 数据持久化放 Repository |
| ❌ 放纯工具函数 | Composable 过重 | 纯函数放 utils/ |
| ❌ 访问 DOM | 破坏分层 | DOM 操作放 Component |

## 4. Repository 层详解

### 4.1 Repository 标准接口

每个 Repository 必须实现以下方法：

```javascript
/**
 * 基础 Repository 接口
 * @template T 实体类型
 */
class BaseRepository {
  /**
   * 启动时加载数据（从 localStorage + 服务器）
   * @returns {Promise<void>}
   */
  async hydrate() { ... }

  /**
   * 获取全部数据（从内存缓存，已排序）
   * @returns {T[]}
   */
  getAll() { ... }

  /**
   * 按 ID 获取单条数据
   * @param {string} id
   * @returns {T | null}
   */
```

## 5. Store 层详解

### 5.1 Store 职责

**Store 是什么？**

Store 是 Pinia 状态管理库的核心，负责：
1. 管理全局状态（响应式数据）
2. 提供计算属性（computed）
3. 提供 actions（调用 Repository）

**Store 不是什么？**

Store 不负责：
- ❌ 数据持久化（由 Repository 管理）
- ❌ HTTP 请求（由 Repository 调用 API）
- ❌ DOM 操作（由 Component 管理）
- ❌ 复杂业务流程（由 Composable 协调）⭐ 新增

**Store 层详细实现请参考三层架构版本的第3节（完全相同）**

## 6. Component 层详解

### 6.1 Component 职责（四层架构）

Component 是 Vue 组件，负责：
1. **用户交互**：点击、输入、拖拽、滚动
2. **数据展示**：渲染列表、表单、图表
3. **简单场景**：直接调用 Store
4. **复杂场景**：调用 Composable ⭐ 新增

Component **不应该**：
- ❌ 直接调用 API
- ❌ 直接访问 Repository
- ❌ 直接操作 localStorage
- ❌ 编写复杂业务逻辑（>50行）→ 应提取到 Composable

### 6.2 迁移示例（三层 vs 四层）

#### 示例1：简单场景（三层架构即可）

**场景**：简单的分类列表展示和CRUD

```vue
<!-- category-drawer.vue -->
<script setup>
import { useCategoryStore } from '@/store/category'

const categoryStore = useCategoryStore()
const categories = categoryStore.categories  // 响应式

async function handleCreate() {
  await categoryStore.createCategory({ name: form.value.name })
  // 无需手动更新，categories 自动同步
}
</script>
```

**无需使用 Composable**：逻辑简单，直接调用 Store 即可

#### 示例2：复杂场景（四层架构）

**场景**：复杂任务表单（30+字段，协调3个Store）

**❌ 旧写法（Component 过重）**：

```vue
<!-- task-edit.vue（3265行） -->
<script setup>
import { ref } from 'vue'
import { useTaskStore } from '@/store/task'
import { useCategoryStore } from '@/store/category'
import { usePlanStore } from '@/store/plan'

const taskStore = useTaskStore()
const categoryStore = useCategoryStore()
const planStore = usePlanStore()

// 30+ 个表单字段
const form = ref({ /* ... */ })
const errors = ref({})

// 100+ 行验证逻辑
function validateForm() { /* ... */ }

// 50+ 行格式化逻辑
function formatDate() { /* ... */ }

// 150+ 行提交逻辑（协调3个Store）
async function submitForm() {
  // 验证
  if (!validateForm()) return

  // 协调多个 Store
  const task = await taskStore.createTask(form.value)
  await categoryStore.linkTaskToCategory(task.id, form.value.categoryId)
  await planStore.linkTaskToPlan(task.id, form.value.planId)

  // 处理成功/失败
  // ...
}
</script>
```

**✅ 新写法（四层架构）**：

```vue
<!-- task-edit.vue（30行） -->
<script setup>
import { useTaskForm } from '@/composables/useTaskForm'

// Component 只需 30 行代码，业务逻辑全部在 Composable
const { form, errors, isFormValid, submitForm } = useTaskForm({ mode: 'create' })

async function handleSubmit() {
  try {
    await submitForm()  // Composable 处理所有业务逻辑
    uni.showToast({ title: '保存成功', icon: 'success' })
  } catch (error) {
    uni.showToast({ title: error.message, icon: 'none' })
  }
}
</script>

<template>
  <view class="form">
    <input :value="form.title" @input="form.title = $event.detail.value" />
    <text v-if="errors.title">{{ errors.title }}</text>
    <button :disabled="!isFormValid" @tap="handleSubmit">保存</button>
  </view>
</template>
```

**优势**：

- Component 从 3265行 → 30行（-99%）
- 业务逻辑复用率 70%（task-edit.vue 和 AddTaskPanel.vue 共享）
- 可测试性大幅提升（Composable 是纯 JS 函数）

## 9. 常见问题FAQ

### Q1：三层架构和四层架构有什么区别？

**A**：

| 对比项 | 三层架构 | 四层架构 |
|--------|---------|---------|
| 层次 | Component → Store → Repository | Component → **Composable** → Store → Repository |
| 适用场景 | 简单列表、简单CRUD | 复杂表单、多Store协调、复杂交互 |
| Component 职责 | 调用 Store | 简单场景调用 Store，复杂场景调用 Composable |
| 代码复用 | Store 层复用 | Store + **Composable** 双层复用 |

### Q2：什么时候应该使用 Composable？

**A**：满足以下任一条件就应该使用 Composable：

1. **复杂表单**：表单字段 > 15个，验证规则 > 10个
2. **多Store协调**：需要同时操作 3+ 个 Store
3. **可复用业务逻辑**：多个页面需要相同的业务逻辑
4. **复杂交互**：拖拽、手势、状态机等复杂交互
5. **Component 过重**：Component 超过 800行

### Q3：Composable 和 Store 的区别是什么？

**A**：

| 对比项 | Composable | Store |
|--------|-----------|-------|
| **作用域** | 局部状态（组件级） | 全局状态（应用级） |
| **持久化** | ❌ 不持久化 | ✅ 持久化（通过 Repository） |
| **职责** | 业务流程编排 | 数据状态管理 |
| **调用链** | Composable → Store | Store → Repository |
| **示例** | useTaskForm（表单逻辑） | taskStore（任务数据） |

### Q4：Composable 能直接调用 Repository 吗？

**A**：❌ **绝对不可以**

**原因**：
- 破坏分层架构
- 绕过 Store，导致状态不同步
- 绕过 Repository 的缓存和离线队列机制

**正确做法**：
```javascript
// ❌ 错误
import { taskRepository } from '@/repositories/taskRepository'
await taskRepository.create(data)  // 跨层调用

// ✅ 正确
import { useTaskStore } from '@/store/task'
const taskStore = useTaskStore()
await taskStore.createTask(data)  // 通过 Store 调用
```

### Q5：Composable 文件过大怎么办？

**A**：如果 Composable 超过 600行，按照以下策略拆分：

1. **提取纯工具函数到 utils/**：

```javascript
// ❌ 放在 Composable（不推荐）
function formatDate(date) { return dayjs(date).format('YYYY-MM-DD') }

// ✅ 放在 utils/date.js
export function formatDate(date) { return dayjs(date).format('YYYY-MM-DD') }
```

2. **拆分为多个 Composable**：

```javascript
// useTaskForm.js → 拆分为：
// - useTaskFormState.js（表单状态管理）
// - useTaskFormValidation.js（验证逻辑）
// - useTaskFormSubmit.js（提交逻辑）
```

3. **组合使用多个 Composable**：

```javascript
// useTaskForm.js
export function useTaskForm() {
  const { form, errors } = useTaskFormState()
  const { validate } = useTaskFormValidation()
  const { submit } = useTaskFormSubmit()

  return { form, errors, validate, submit }
}
```

### Q6：四层架构会增加代码量吗？

**A**：初期会增加，但长期减少：

| 阶段 | 代码量 | 说明 |
|------|--------|------|
| 第1个功能 | +15% | 需要额外写 Composable |
| 第2个功能 | 0% | 复用第1个功能的 Composable |
| 第3个功能 | -10% | 大量复用 |
| 第10个功能 | -30% | 代码复用率达到 70% |

**实际案例**：
- task-edit.vue + AddTaskPanel.vue（旧代码）：5863行
- task-edit.vue + AddTaskPanel.vue + useTaskForm.js（新代码）：4616行
- **减少 1247行（-21%）**

### Q7：如何调试 Composable？

**A**：Composable 是纯 JS 函数，可以：

1. **单元测试**：

```javascript

test('表单验证', () => {
  const { form, validateForm } = useTaskForm()
  form.value.title = ''
  expect(validateForm()).toBe(false)
})
```

2. **浏览器 Console**：

```javascript
import { useTaskForm } from '@/composables/useTaskForm'

const { form, errors, submitForm } = useTaskForm({ mode: 'create' })

// 查看表单状态
console.log(form.value)

// 查看错误

```
