# 重复任务+普通任务（一次性任务）=统一的任务系统

# 一、核心思想

1. **统一任务视图**
   - 不管任务是否重复，用户看到的都是**某一天的任务列表**。
   - 系统只关心：这一天该显示哪些任务。
2. **任务类型区分**
   - **一次性任务**：只出现一次。
   - **重复任务**：按照规则动态生成。
3. **操作统一**
   - 用户操作（修改、删除、完成）可以同时适用于一次性任务和重复任务。
   - 对重复任务，通过“覆盖”或“标记”实现局部修改或删除。
   - 对一次性任务，直接修改或删除即可。

------

# 二、核心数据结构

| 数据类型          | 内容                                                         | 适用任务                                   |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------ |
| **任务规则**      | 任务名称、开始时间、重复规则（每天/每周）、默认属性（优先级、标签等） | 仅重复任务                                 |
| **任务实例**      | 生成的当天任务对象（用于前端展示和操作）                     | 临时生成，重复任务或一次性任务都可视作实例 |
| **任务执行记录**  | 日期、任务ID、完成状态、修改历史                             | 所有任务                                   |
| **覆盖/删除标记** | 仅针对重复任务，单日修改或删除                               | 重复任务                                   |

> 注：一次性任务没有规则，它本身就是“实例”，只需要执行记录即可。

------

# 三、任务生成和展示逻辑

1. **获取某一天任务列表**：

```
1. 先查一次性任务是否在当天存在 → 直接加入列表
2. 再查重复任务规则，判断规则是否适用于当天
3. 应用重复任务的单日删除标记
4. 应用重复任务的单日覆盖修改
5. 将重复任务生成实例加入列表
6. 返回完整任务列表
```

1. **任务实例只作为展示**
   - 不提前存储重复任务实例到数据库。
   - 一次性任务本身就是实例。
2. **用户操作逻辑**：

| 操作     | 一次性任务   | 重复任务         |
| -------- | ------------ | ---------------- |
| 修改当天 | 修改实例属性 | 创建单日覆盖     |
| 修改未来 | 无           | 拆分任务规则     |
| 修改全部 | 无           | 修改任务规则     |
| 删除当天 | 删除实例     | 创建单日删除标记 |
| 删除未来 | 无           | 修改规则结束时间 |
| 删除全部 | 删除实例     | 删除任务规则     |
| 完成     | 写入执行记录 | 写入执行记录     |

------

# 四、数据库设计建议

1. **一次性任务表**

2. **重复任务规则表**

3. **重复任务覆盖/删除表**

4. **任务执行记录表**

> 执行记录统一存储，方便统计和打卡历史。

------

# 五、未来任务查询

- **一次性任务**：直接查任务表。
- **重复任务**：动态计算，按照规则、覆盖和删除标记生成实例。
- **最终展示**：一次性任务 + 重复任务实例 → 用户看到的当天任务列表。

------

# 六、总结设计思想

1. **统一任务视图**：用户看到的每天任务，无论一次性或重复任务，都用同一逻辑生成。
2. **数据分层**：
   - **任务规则**（重复任务）
   - **任务实例**（当天展示）
   - **执行记录**（历史和统计）
   - **覆盖/删除标记**（特殊情况）
3. **动态生成**：重复任务不存每天实例，减少数据库膨胀。
4. **操作一致性**：修改、删除、完成操作对所有任务都可统一处理。
5. **历史保留**：规则修改或删除不影响过去执行记录。
