# 阶段三、统一设计思路的核心结构



## 一、统一任务体系结构

```
全部任务
├─ 规划（复杂分类）
│   ├─ 规划A
│   │   ├─ 任务A1（一次性/重复）
│   │   └─ 任务A2（一次性/重复）
│   ├─ 规划B
│   │   ├─ 任务B1（一次性/重复）
│   │   └─ 任务B2（一次性/重复）
├─ 分类（普通分类）
│   ├─ 工作C
│   │   ├─ 任务C1（一次性/重复）
│   │   └─ 任务C2（一次性/重复）
│   ├─ 做菜D
│       ├─ 任务D1（一次性/重复）
│       └─ 任务D2（一次性/重复）
└─ 未分类
    ├─ 任务E（一次性/重复）
    └─ 任务F（一次性/重复）
```

**说明：**

1. **全部任务** = 汇总视图，包含所有规划、分类和未分类任务。
2. **规划（复杂分类）** = 高级分类，可包含多个任务，每个任务可以是一次性或重复任务。
   - 可以有更多属性，例如目标完成时间、依赖关系、优先级规则。
3. **普通分类** = 简单标签分类，如“工作”、“做菜”。
   - 任务可以是一次性或重复。
4. **未分类** = category_id/规划ID为空的任务。
5. **任务类型**：
   - 一次性任务：只存在一次
   - 重复任务：由规则动态生成实例

------

## 二、数据库设计思路

1. **规划/分类表**（统一管理规划和分类）

2. **一次性任务表**

3. 重复任务规则表**

4. 覆盖/删除标记表**（重复任务专用）

5. 执行记录表**

------

## 三、任务生成与显示逻辑

1. **生成当天任务**：

```
当天任务 = 一次性任务 + 重复任务实例
```

- **一次性任务**：直接查询当天存在的任务
- **重复任务**：
  - 根据规则动态生成当天实例
  - 应用单日覆盖或删除标记

1. **按分类/规划展示**：

- 查询规划ID = 某规划 → 得到规划下任务
- 查询 分类ID= 某分类 → 得到分类下任务
- 未分类任务 分类ID/规划ID = NULL → 单独显示

1. **操作逻辑**：

| 操作     | 一次性任务   | 重复任务         |
| -------- | ------------ | ---------------- |
| 修改当天 | 修改实例     | 单日覆盖         |
| 修改未来 | 不适用       | 拆分规则         |
| 修改全部 | 不适用       | 修改规则         |
| 删除当天 | 删除实例     | 单日删除标记     |
| 删除未来 | 不适用       | 修改规则结束时间 |
| 删除全部 | 删除实例     | 删除规则         |
| 完成     | 写入执行记录 | 写入执行记录     |

------

## 四、未来任务查询

- **全部任务视图**：合并一次性任务 + 重复任务实例
- **规划视图**：过滤规划ID
- **分类视图**：过滤 分类ID
- **未分类视图**：分类ID/规划ID = NULL
- 重复任务实例动态生成 → 不提前生成数据库实例

------

## 五、总结设计思想

1. **层级结构**：

```
全部任务
├─ 规划（复杂分类）
├─ 分类（普通分类）
└─ 未分类
```

1. **任务类型**：

- 一次性任务 = 实例
- 重复任务 = 规则动态生成实例

1. **操作统一**：

- 修改、删除、完成操作不受分类/规划影响
- 重复任务覆盖/删除机制适用所有层级

1. **动态生成未来任务**：

- 查询任意日期 → 计算重复任务实例 + 一次性任务
- 支持分类/规划筛选

1. **“全部任务“视图**：

- 汇总所有规划、分类和未分类任务
- 给用户一个全局任务视角
