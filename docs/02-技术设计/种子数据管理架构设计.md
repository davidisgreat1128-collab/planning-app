## 1. 需求背景

### 1.1 业务问题

**问题1：生产环境数据缺失**
- 服务器数据库 `holidays` 和 `work_days` 表为空（0条数据）
- 导致 APP 端无法显示节假日、农历、"班"/"休"角标
- 原因：Docker 容器启动时只运行 Migration，未运行 Seeders

**问题2：工作日数据年度更新**
- `work_days` 表数据每年变化（国务院每年11月公布下一年调休安排）
- 需要在每年11月1日提醒管理员更新明年数据
- 避免使用过期数据导致APP显示错误

### 1.2 技术债务

**原方案（Commit 3298e70）的问题**：

| 问题类型 | 具体表现 | 违反原则 |
|---------|---------|---------|
| **违反SRP** | `seed-if-empty.js` 承担4个职责：数据库连接、数据检查、种子文件执行、日志输出 | 单一职责原则 |
| **违反四层架构** | 直接调用 `Sequelize.query()` 操作数据库，跳过 Service 和 Repository 层 | 分层架构原则 |
| **缺少年度提醒** | 无定时检查机制，依赖人工记忆更新 | 自动化原则 |

## 2. 架构问题分析

### 2.1 原架构（❌ 不符合规范）

```
启动脚本（seed-if-empty.js）
   ├─ 创建 Sequelize 实例
   ├─ 直接执行 SQL 查询（SELECT COUNT(*)）
   ├─ 调用 execSync 运行种子文件
   └─ 输出日志

调用链：
seed-if-empty.js → Sequelize.query() → Database
（跨层调用，违反四层架构）
```

**职责分析**（违反SRP）：

| 职责 | 应该在哪一层 | 实际位置 |
|------|-------------|---------|
| 数据库连接管理 | Repository/Model 层 | seed-if-empty.js ❌ |
| 数据检查逻辑 | Service 层 | seed-if-empty.js ❌ |
| 种子文件执行 | Service 层 | seed-if-empty.js ❌ |
| 日志输出 | 启动脚本 | seed-if-empty.js ✅ |

**改变的理由分析**（违反SRP核心：一个改变的理由）：

- 理由1：数据库连接方式变更（如改用连接池） → 需要修改 seed-if-empty.js
- 理由2：数据检查逻辑变更（如增加新表） → 需要修改 seed-if-empty.js
- 理由3：种子文件执行方式变更（如改用并行导入） → 需要修改 seed-if-empty.js

**一个文件有3个改变的理由 → 严重违反SRP！**

---

### 2.2 目标架构（✅ 符合规范）

```
启动脚本（seed-if-empty.js）
   ↓
Service 层（holidayDataManager）
   ├─ ensureHolidayData()
   ├─ ensureWorkDayData()
   └─ checkWorkDayExpiry()
   ↓
Model 层（Holiday / WorkDay）
   ├─ Holiday.count()
   └─ WorkDay.findOne()
   ↓
Database（MySQL）

调用链：
启动脚本 → Service 层 → Model 层 → Database
（符合四层架构，无跨层调用）
```

**职责重新分配（符合SRP）**：

| 职责 | 层级 | 文件 | 改变的理由 |
|------|------|------|-----------|
| 启动入口、日志输出 | 启动脚本 | seed-if-empty.js | 启动流程变更 |
| 数据检查、种子导入 | Service 层 | holidayDataManager.js | 业务逻辑变更 |
| 定时任务调度 | Service 层 | scheduler.js | 调度策略变更 |
| 数据访问 | Model 层 | Holiday.js / WorkDay.js | 数据模型变更 |

**每个文件只有1个改变的理由 → 符合SRP ✅**

## 3. 架构重构方案

### 3.1 核心思想

**设计原则**：
1. ✅ **单一职责原则（SRP）**：每个模块只负责一件事
2. ✅ **四层架构**：严格遵循 启动脚本 → Service → Model → Database
3. ✅ **依赖倒置**：启动脚本依赖 Service 抽象，不依赖具体实现
4. ✅ **开闭原则**：对扩展开放（新增表），对修改关闭（无需改启动脚本）

### 3.2 架构图

```
┌──────────────────────────────────────────────────────────────┐
│  启动层（Docker Entrypoint）                                  │
│  backend/wait-for-mysql.sh + backend/seed-if-empty.js       │
│  职责：容器启动时调用 Service 层初始化                        │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  Service 层（业务逻辑）                                        │
│  backend/src/services/holidayDataManager.js                  │
│  职责：                                                       │
│  - 检查表是否为空（isTableEmpty）                             │
│  - 导入种子数据（ensureHolidayData / ensureWorkDayData）     │
│  - 检查数据有效期（checkWorkDayExpiry）                       │
│  - 完整初始化流程（initialize）                               │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  Model 层（数据模型）                                          │
│  backend/src/models/Holiday.js + WorkDay.js                  │
│  职责：                                                       │
│  - 定义数据结构（Sequelize Model）                            │
│  - 提供 ORM 方法（count / findOne / findAll）                │
└───────────────────────────┬──────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  Database 层（MySQL）                                          │
│  holidays 表（57条）+ work_days 表（39条）                     │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  定时任务层（Scheduler）                                        │
│  backend/src/services/scheduler.js                            │
│  职责：                                                        │
│  - 每天凌晨2点检查工作日数据有效期                              │
│  - 11月1日及之后发出数据更新提醒                               │
│  - 集成到 server.js 生命周期（启动/关闭）                      │
└──────────────────────────────────────────────────────────────┘
```

## 4. 实施细节

### 4.1 核心文件说明

#### 文件1：`backend/src/services/holidayDataManager.js`

**职责**：节假日数据管理服务（Service 层）

**方法**：

```javascript
class HolidayDataManager {
  /**
   * 检查表是否为空
   * @param {string} modelName - 'Holiday' 或 'WorkDay'
   * @returns {Promise<boolean>} true表示空表
   */
  async isTableEmpty(modelName) { ... }

  /**
   * 运行指定的种子文件
   * @param {string} seedFile - 种子文件名（如 '20260219000001-holidays.js'）
   * @returns {Promise<boolean>} 成功返回true
   */
  async runSeedFile(seedFile) { ... }

  /**
   * 检查并导入节假日数据（holidays 表）
   * @returns {Promise<boolean>}
   */
  async ensureHolidayData() { ... }

  /**
   * 检查并导入工作日数据（work_days 表）
   * @returns {Promise<boolean>}
   */
  async ensureWorkDayData() { ... }

  /**
   * 检查工作日数据有效期（每年11月1日检查）
   * @returns {Promise<object>} { needUpdate, message, currentYear, latestYear, targetYear }
   */
  async checkWorkDayExpiry() { ... }

  /**
   * 完整初始化流程（容器启动时调用）
   * @returns {Promise<object>} 执行结果
   */
  async initialize() { ... }
}
```

#### 文件2：`backend/src/services/scheduler.js`

**职责**：定时任务调度服务（Service 层）

**方法**：

```javascript
class Scheduler {
  /**
   * 计算距离下一次检查时间的毫秒数
   * @returns {number} 毫秒数（到明天凌晨2点）
   */
  calculateNextCheckTime() { ... }

  /**
   * 检查工作日数据有效期（定时任务）
   */
  async checkWorkDayExpiry() { ... }

  /**
   * 启动定时任务调度器（应用启动时调用）
   */
  start() { ... }

  /**
   * 停止所有定时任务（应用关闭时调用）
   */
  stop() { ... }
}
```

**调度逻辑**：

1. **应用启动时**：立即执行一次检查
2. **每天凌晨2点**：自动执行检查
3. **递归调度**：每次检查完成后，自动安排下一次检查
4. **避免重复**：使用 `lastCheckDate` 标记，同一天只检查一次

**集成到 server.js**：

```javascript
// server.js
const scheduler = require('./src/services/scheduler');

async function startServer() {
  // ...
  const server = app.listen(PORT, HOST, () => {
    logger.info('🚀 服务器已启动');

    // ⭐ 启动定时任务调度器
    scheduler.start();
  });

  // 优雅关机时停止调度器
  const shutdown = async (signal) => {
    // ...
    scheduler.stop();  // ⭐ 停止定时任务
    await db.sequelize.close();
    // ...
  };
}
```

#### 文件3：`backend/seed-if-empty.js`（重构后）

**职责**：启动脚本入口（不属于四层架构，但必须遵循分层调用）

**Before（❌ 违反四层架构）**：

```javascript
// 直接操作数据库
const sequelize = new Sequelize(...);
const [results] = await sequelize.query(`SELECT COUNT(*) FROM holidays`);
```

**After（✅ 符合四层架构）**：

```javascript
// 调用 Service 层
const holidayDataManager = require('./src/services/holidayDataManager');
const result = await holidayDataManager.initialize();
```

**代码对比**：

| 项目 | Before（原方案） | After（重构后） |
|------|----------------|----------------|
| **代码行数** | 128行 | 66行（-48%）|
| **职责数量** | 4个职责 | 1个职责 ✅ |
| **直接依赖** | Sequelize、execSync、Database | holidayDataManager（Service）✅ |
| **可测试性** | 困难（耦合数据库） | 容易（Mock Service）✅ |
| **扩展性** | 新增表需修改启动脚本 | 新增表只需修改 Service ✅ |

## 5. 工作日年度更新机制

### 5.1 业务背景

**问题**：
- 国务院每年11月公布下一年调休安排
- 开发者需要手动创建新的种子文件（如 `work-days-2027.js`）
- 如果忘记更新，APP 将显示错误的"班"/"休"角标

**解决方案**：自动提醒机制

### 5.2 提醒逻辑

```javascript
// 伪代码
if (当前月份 >= 11月 && 数据库最新年份 === 当前年份) {
  提醒："请添加 下一年 工作日数据"
}

if (数据库最新年份 < 当前年份) {
  提醒："数据已过期，请添加 当前年 工作日数据"
}
```

**示例**：

| 当前时间 | 数据库最新年份 | 提醒内容 |
|---------|--------------|---------|
| 2026年3月 | 2026年 | ✅ 工作日数据最新（2026年）|
| 2026年11月 | 2026年 | ⚠️ 请添加 2027年 工作日数据 |
| 2027年1月 | 2026年 | ⚠️ 数据已过期，请添加 2027年 工作日数据 |

## 7. 常见问题

### 7.1 容器启动时种子数据未导入

**现象**：容器日志中没有看到 `[HolidayDataManager]` 相关日志

**排查步骤**：

1. 检查 `wait-for-mysql.sh` 是否调用了 `seed-if-empty.js`：
   ```bash
   sudo docker exec -it planning-app-backend cat /app/wait-for-mysql.sh | grep seed-if-empty
   ```
   应该看到：`node /app/seed-if-empty.js`

2. 检查 `seed-if-empty.js` 是否存在：
   ```bash
   sudo docker exec -it planning-app-backend ls -la /app/seed-if-empty.js
   ```

3. 手动运行脚本调试：
   ```bash
   sudo docker exec -it planning-app-backend node /app/seed-if-empty.js
   ```

---

### 7.2 定时任务未按预期执行

**现象**：凌晨2点没有看到检查日志

**排查步骤**：

1. 检查服务器时区：
   ```bash
   sudo docker exec -it planning-app-backend date
   # 应该显示 CST（北京时间）
   ```

2. 检查定时任务是否启动：
   ```bash
   sudo docker compose logs backend | grep "启动定时任务调度器"
   ```
   应该看到：`✅ 定时任务调度器已启动`

3. 检查下次调度时间：
   ```bash
   sudo docker compose logs backend | grep "下一次检查将在"
   ```

4. 手动触发检查（调试用）：
   ```javascript
   // 临时修改 scheduler.js 的 calculateNextCheckTime()
   // 返回 60000（1分钟后执行）
   ```

---

### 7.3 工作日数据需要更新，如何添加？

**步骤**：

1. **等待国务院公布调休安排**（通常在10月底-11月初）

2. **创建新的种子文件**：
   ```bash
   # 文件名格式：YYYYMMDD-work-days-{年份}.js
   touch backend/src/seeders/20261101-work-days-2027.js
   ```

3. **参考现有文件格式**：
   ```javascript
   // 复制 20260306152306-work-days-2026.js 的内容
   // 修改 year 字段和 date 字段
   ```

4. **修改 `holidayDataManager.js`**（如果种子文件命名有变化）：
   ```javascript
   // holidayDataManager.js Line 80
   const seedFile = `20261101-work-days-${currentYear}.js`;  // 更新文件名
   ```

5. **提交代码并部署**：
   ```bash
   git add backend/src/seeders/20261101-work-days-2027.js
   git commit -m "feat(data): 添加2027年工作日调休数据"
   git push origin develop

   # 在服务器上拉取并重启
   ssh ubuntu@154.8.183.203
   cd /opt/planning-app/planning-app
   git pull origin develop
   sudo docker compose build backend
   sudo docker compose up -d backend
   ```
