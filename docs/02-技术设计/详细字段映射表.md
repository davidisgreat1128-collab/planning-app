## 1. 字段命名规范

### 1.1 核心规则

| 层级 | 命名规范 | 示例 | 说明 |
|------|---------|------|------|
| **数据库字段** | snake_case | `user_id`, `created_at`, `is_urgent` | MySQL 字段名（强制） |
| **后端 JS 代码** | camelCase | `userId`, `createdAt`, `isUrgent` | Sequelize Model 属性 |
| **前端 JS 代码** | camelCase | `userId`, `createdAt`, `isUrgent` | Vue/Store/Repository |
| **常量** | UPPER_SNAKE_CASE | `API_BASE_URL`, `MAX_RETRY` | 配置常量 |
| **类名/组件名** | PascalCase | `TaskRepository`, `AddTaskPanel` | 类/组件 |

### 1.2 Sequelize 自动映射

**全局配置**（backend/src/models/index.js）:
```javascript
const sequelize = new Sequelize(dbConfig.database, dbConfig.username, dbConfig.password, {
  host: dbConfig.host,
  dialect: dbConfig.dialect,
  timezone: dbConfig.timezone,
  underscored: true,  // ⭐ 全局开启 snake_case ↔ camelCase 自动映射
  // ...
});
```

**映射规则**:
```
数据库 (snake_case)       ← Sequelize自动映射 →       JS代码 (camelCase)
─────────────────────────────────────────────────────────────────────────
user_id                                                userId
user_name                                              userName
created_at                                             createdAt
updated_at                                             updatedAt
deleted_at                                             deletedAt
is_urgent                                              isUrgent
is_important                                           isImportant
is_all_day                                             isAllDay
task_date                                              taskDate
start_date                                             startDate
end_date                                               endDate
start_time                                             startTime
end_time                                               endTime
plan_id                                                planId
category_id                                            categoryId
```

### 1.3 布尔字段命名规范

**前缀规则**:
- `is_` / `is` - 状态判断（`isUrgent`, `isActive`, `isAllDay`）
- `has_` / `has` - 拥有关系（`hasPermission`, `hasTask`）
- `should_` / `should` - 行为建议（`shouldRetry`, `shouldNotify`）

**禁止的命名**:
- ❌ `urgent` (应该用 `isUrgent`)
- ❌ `completed` (应该用 `isCompleted` 或 `status`)
- ❌ `permission` (应该用 `hasPermission`)

### 4.3 四象限分类逻辑

```javascript
/**
 * 根据 isUrgent + isImportant 判断四象限
 * @returns {string} 象限名称
 */
function getQuadrant(task) {
  if (task.isUrgent && task.isImportant) return 'crisis';       // 第一象限：危机象限（红色）
  if (task.isUrgent && !task.isImportant) return 'trivial';     // 第三象限：无益象限（黄色）
  if (!task.isUrgent && task.isImportant) return 'planning';    // 第二象限：规划象限（蓝色）
  return 'eliminate';                                             // 第四象限：琐事象限（绿色）
}

// 示例
const task1 = { isUrgent: true, isImportant: true };
getQuadrant(task1); // => "crisis" (危机象限，紧急且重要，立即做)

const task2 = { isUrgent: false, isImportant: true };
getQuadrant(task2); // => "planning" (规划象限，重要不紧急，持续做)
```

### 4.4 容器归属判断逻辑

```javascript
/**
 * 判断任务所属容器
 * @param {Task} task - 任务对象
 * @returns {string} 容器描述
 */
function getTaskContainer(task) {
  if (task.planId) {
    const planning = PlanningRepository.getById(task.planId);
    return `规划: ${planning?.title || '未知规划'}`;
  }

  if (task.categoryId) {
    const category = CategoryRepository.getById(task.categoryId);
    return `分类: ${category?.name || '未知分类'}`;
  }

  return '无分类';
}

// 示例
const task1 = { id: 1, title: '完成报告', planId: 'P001', categoryId: null };
getTaskContainer(task1); // => "规划: 人生规划"

const task2 = { id: 2, title: '看书', planId: null, categoryId: 'CAT002' };
getTaskContainer(task2); // => "分类: 学习"

const task3 = { id: 3, title: '买菜', planId: null, categoryId: null };
getTaskContainer(task3); // => "无分类"
```

### 5.2 容器层级统计

```javascript
/**
 * 统计各容器的任务数量
 */
function getContainerStats() {
  const allTasks = TaskRepository.getAll();

  return {
    total: allTasks.length,
    byPlan: getPlanTaskStats(allTasks),
    byCategory: getCategoryTaskStats(allTasks),
    uncategorized: allTasks.filter(t => !t.planId && !t.categoryId).length
  };
}

function getPlanTaskStats(tasks) {
  const stats = {};
  const plannings = PlanningRepository.getAll();

  plannings.forEach(plan => {
    stats[plan.id] = {
      planTitle: plan.title,
      taskCount: tasks.filter(t => t.planId === plan.id).length
    };
  });

  return stats;
}

function getCategoryTaskStats(tasks) {
  const stats = {};
  const categories = CategoryRepository.getAll();

  categories.forEach(cat => {
    stats[cat.id] = {
      categoryName: cat.name,
      taskCount: tasks.filter(t => t.categoryId === cat.id).length
    };
  });

  return stats;
}

// 示例输出
getContainerStats();
```

## 6. 字段新增流程

### 6.1 强制检查清单 ✅

**步骤1: 创建新字段前（强制）**
```bash
# 1. 打开本文档
cat docs/02-技术设计/详细字段映射表.md

# 2. 在文档中搜索关键词，确认字段不存在
# 例如：要创建"任务优先级"字段，先搜索 "priority" 或 "优先级"

# 3. 在对应表格中查找是否已有类似字段
# 例如：Task 表已有 isUrgent/isImportant，是否复用？
```

**步骤2: 确认字段不存在后（创建）**
```bash
# 1. 在数据库创建字段（通过 migration 文件）
cd backend
npx sequelize-cli migration:generate --name add-priority-to-tasks

# 2. 编写 migration 文件（使用 snake_case）
# migrations/YYYYMMDDHHMMSS-add-priority-to-tasks.js
await queryInterface.addColumn('tasks', 'priority', {
  type: Sequelize.ENUM('low', 'medium', 'high'),
  allowNull: false,
  defaultValue: 'medium',
  comment: '任务优先级'
});

# 3. 运行 migration
npm run migrate

# 4. 更新后端 Model（使用 camelCase）
# backend/src/models/Task.js
priority: {
  type: DataTypes.ENUM('low', 'medium', 'high'),
  allowNull: false,
  defaultValue: 'medium'
}

# 5. 更新前端 Repository/Store（如需要）
# frontend/Planning-app/repositories/TaskRepository.js
# 无需修改，Sequelize 自动映射 priority ↔ priority

# 6. ⭐ 立即更新本文档（强制）
# 在"4.1 Task 任务字段映射表"中新增一行：
| 任务优先级 | priority | priority | priority | ENUM | 'medium' | 否 | low/medium/high |
```

**步骤3: 更新文档（必须）**
- 在本文档对应的表格中新增一行
- 填写：逻辑含义、前端字段、后端字段、数据库字段、类型、默认值、可空、说明
- 提交到 Git，记录在工作日志中

### 6.2 禁止行为 ❌

- ❌ **不查阅本文档就创建新字段**（可能导致重复字段）
- ❌ **创建字段后不更新本文档**（导致文档失效）
- ❌ **字段命名不遵循规范**（数据库必须 snake_case，代码必须 camelCase）
- ❌ **创建语义重复的字段**（如 taskTitle 和 title 同时存在）
- ❌ **在代码中使用 snake_case 字段名**（应该用 camelCase，让 Sequelize 自动映射）
