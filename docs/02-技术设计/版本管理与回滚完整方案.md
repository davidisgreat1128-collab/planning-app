## 1. 当前问题分析

### 1.1 现状评估

**✅ 已有基础**（很好的起点）：
- Docker Compose编排（MySQL + Redis + Backend + Nginx）
- 基础部署脚本（`scripts/deploy.sh`）
- 简单回滚机制（恢复`.env`文件）
- package.json有语义版本号（0.1.0）
- Git版本控制（有commit历史）

**❌ 存在问题**（需要改进）：

| 问题 | 影响 | 严重性 |
|------|------|--------|
| Docker镜像使用`latest`标签 | 无法追踪版本，无法回滚到特定版本 | 🔴 高 |
| 无版本号记录机制 | 不知道当前运行的是哪个版本 | 🔴 高 |
| 回滚只恢复`.env`文件 | 代码版本未回滚，数据不一致 | 🔴 高 |
| 无部署历史数据库 | 无法查看历史版本，无法审计 | 🟡 中 |
| 无`/version`接口 | 前端/运维无法获取版本信息 | 🟡 中 |
| 无部署锁机制 | 可能并发部署导致冲突 | 🟡 中 |

### 1.2 业务需求

**核心需求**：
1. 每个部署版本都有唯一标识
2. 可以查看当前运行版本（运维、前端、用户）
3. 可以查看历史部署记录（审计、追溯）
4. 可以一键回滚到任意历史版本
5. Docker镜像必须版本化
6. 部署过程可记录、可追溯

**非功能需求**：
- 简单易用（个人项目可落地）
- 不依赖复杂基础设施（不需要K8s、Harbor等）
- 可在单机环境运行
- 支持自动化（脚本化）

## 3. 版本号设计规则

### 3.1 版本号格式

**完整格式**：
```
v{语义版本}+{git-commit-short}+{时间戳}

示例: v0.1.0+e78ad3d+20260320-143022
```

**组成部分**：

| 部分 | 格式 | 来源 | 示例 | 说明 |
|------|------|------|------|------|
| 语义版本 | `MAJOR.MINOR.PATCH` | package.json | `0.1.0` | 手动维护的功能版本 |
| Git Commit | 7位短哈希 | `git rev-parse --short HEAD` | `e78ad3d` | 代码快照标识 |
| 时间戳 | `YYYYMMDD-HHMMSS` | `date +%Y%m%d-%H%M%S` | `20260320-143022` | 部署时间 |

### 3.2 语义化版本规范（SemVer 2.0）

**版本号含义**：`MAJOR.MINOR.PATCH`

| 版本类型 | 何时递增 | 示例 | 说明 |
|---------|---------|------|------|
| **MAJOR**（主版本） | 不兼容的API变更 | `1.0.0 → 2.0.0` | 重大架构调整、破坏性变更 |
| **MINOR**（次版本） | 向后兼容的功能新增 | `0.1.0 → 0.2.0` | 新增功能模块、API扩展 |
| **PATCH**（修订号） | 向后兼容的问题修复 | `0.1.0 → 0.1.1` | Bug修复、性能优化 |

**特殊版本号**：
- `0.x.y`: 开发阶段版本（API不稳定）
- `1.0.0`: 第一个稳定版本
- `1.0.0-alpha`: 预发布版本（alpha/beta/rc）

### 3.3 版本号生成逻辑

**Shell脚本实现**：
```bash
#!/bin/bash
# 生成完整版本号

# 1. 读取语义版本（package.json）
SEMVER=$(node -p "require('./backend/package.json').version")

# 2. 获取Git commit短哈希
GIT_COMMIT=$(git rev-parse --short HEAD)

# 3. 生成时间戳
TIMESTAMP=$(date '+%Y%m%d-%H%M%S')

# 4. 组合完整版本
FULL_VERSION="v${SEMVER}+${GIT_COMMIT}+${TIMESTAMP}"

echo "$FULL_VERSION"
# 输出: v0.1.0+e78ad3d+20260320-143022
```

### 3.4 版本号使用场景

| 场景 | 使用格式 | 示例 |
|------|---------|------|
| Docker镜像标签 | 完整版本 | `planning-app-backend:v0.1.0+e78ad3d+20260320-143022` |
| 部署历史记录 | 完整版本 | `deployments.json` 中记录 |
| API返回 | 完整版本 | `/version` 接口返回 |
| 回滚指定版本 | 完整版本或语义版本 | `rollback.sh v0.1.0` |
| Git Tag | 语义版本 | `git tag v0.1.0` |

## 4. Docker镜像版本策略

### 4.1 镜像标签命名规范

**三层标签策略**：

```bash
planning-app-backend:v0.1.0+e78ad3d+20260320-143022  # 完整版本（精确回滚）
planning-app-backend:v0.1.0                           # 语义版本（灵活回滚）
planning-app-backend:latest                           # 最新版本（仅开发用）
```

**标签说明**：

| 标签类型 | 格式 | 用途 | 稳定性 |
|---------|------|------|--------|
| **完整版本** | `v{semver}+{commit}+{timestamp}` | 精确回滚到某次部署 | 🟢 永久不变 |
| **语义版本** | `v{semver}` | 回滚到某个功能版本 | 🟡 可能被覆盖 |
| **最新版本** | `latest` | 本地开发快速迭代 | 🔴 频繁变更 |

### 4.2 镜像构建策略

**构建时打3个标签**：

```bash
#!/bin/bash
# 构建版本化镜像

FULL_VERSION="v0.1.0+e78ad3d+20260320-143022"
SEMVER="v0.1.0"

cd backend

# 构建镜像并打3个标签
docker build \
  -t planning-app-backend:${FULL_VERSION} \
  -t planning-app-backend:${SEMVER} \
  -t planning-app-backend:latest \
  --build-arg VERSION=${FULL_VERSION} \
  --build-arg GIT_COMMIT=e78ad3d \
  --build-arg BUILD_TIME=$(date -Iseconds) \
  .

cd ..
```

**为什么打3个标签？**

1. **完整版本**（`v0.1.0+e78ad3d+20260320-143022`）：
   - 精确标识某次部署
   - 永久不变，安全可靠
   - 用于审计、追溯、精确回滚

2. **语义版本**（`v0.1.0`）：
   - 标识功能版本
   - 每次部署会覆盖（指向最新的0.1.0）
   - 用于快速回滚到"最新的0.1.0版本"

3. **最新版本**（`latest`）：
   - 总是指向最新构建
   - 仅用于本地开发
   - 生产环境禁止使用

### 4.3 镜像生命周期管理

**保留策略**（避免磁盘占满）：

```bash
#!/bin/bash
# 清理旧镜像（保留最近10个完整版本）

docker images | grep planning-app-backend | grep -v latest | grep -v "v[0-9]\+\.[0-9]\+\.[0-9]\+$" | tail -n +11 | awk '{print $3}' | xargs docker rmi -f
```

**镜像存储规划**：

| 镜像类型 | 保留数量 | 磁盘占用（估算） |
|---------|---------|----------------|
| 完整版本镜像 | 最近10个 | ~500MB × 10 = 5GB |
| 语义版本镜像 | 当前所有 | ~500MB × 3 = 1.5GB |
| latest镜像 | 1个 | ~500MB |
| **总计** | — | **~6.5GB** |

## 5. 部署流程设计

### 5.1 部署流程总览

```
┌─────────────────────────────────────────────────────────────┐
│                      部署流程                                │
└─────────────────────────────────────────────────────────────┘

步骤1: 开发完成
  ├─ 修改代码
  ├─ 更新package.json版本号（手动）
  └─ Git commit + push

步骤2: 执行部署脚本
  ├─ bash scripts/deploy-v2.sh
  └─ 进入自动化流程 ↓

步骤3: 版本号生成
  ├─ 读取package.json → 0.1.1
  ├─ 获取git commit → e78ad3d
  ├─ 生成时间戳 → 20260320-143022
  └─ 组合版本号 → v0.1.1+e78ad3d+20260320-143022

步骤4: 环境检查
  ├─ 检查Docker是否安装
  ├─ 检查docker-compose是否安装
  ├─ 检查.env文件是否存在
  └─ 检查是否有其他部署正在进行（部署锁）

步骤5: 备份当前版本
  ├─ 读取deployments.json获取当前版本
  ├─ 创建备份目录 backups/deployments/{当前版本}/
  ├─ 备份docker-compose.yml
  ├─ 备份.env
  └─ 备份元数据（镜像ID、健康状态等）

步骤6: 构建版本化镜像
  ├─ docker build -t planning-app-backend:{完整版本}
  ├─ docker tag → {语义版本}
  └─ docker tag → latest

步骤7: 更新配置文件
  ├─ 更新docker-compose.yml中的image版本
  ├─ 设置环境变量（APP_VERSION等）
  └─ 生成.env.deploy临时文件

步骤8: 停止旧版本
  ├─ docker-compose down
  └─ 等待容器完全停止（grace period: 10s）

步骤9: 启动新版本
  ├─ docker-compose up -d
  └─ 等待容器启动

步骤10: 健康检查
  ├─ 等待30秒（初始化时间）
  ├─ 轮询 /health 接口（最多60次，每2秒）
  ├─ 验证返回状态为200
  └─ 检查响应时间 < 1秒

步骤11: 验证版本
  ├─ 调用 /version 接口
  ├─ 验证返回的版本号与部署版本一致
  └─ 确认数据库连接正常

步骤12: 记录部署历史
  ├─ 读取现有deployments.json
  ├─ 追加新部署记录
  │   ├─ 版本号
  │   ├─ 时间戳
  │   ├─ 操作者
  │   ├─ 健康状态
  │   ├─ 响应时间
  │   └─ 镜像信息
  └─ 写入deployments.json

步骤13: 清理旧镜像（可选）
  ├─ 保留最近10个完整版本镜像
  └─ 删除更早的镜像

步骤14: 完成部署
  ├─ 删除部署锁
  ├─ 打印部署报告
  │   ├─ 当前版本
  │   ├─ 健康状态
  │   ├─ 访问地址
  │   └─ 回滚命令
  └─ 退出（返回0）
```

### 5.2 关键步骤详解

#### 步骤3: 版本号生成（核心逻辑）

```bash
generate_version() {
  log_step "生成版本号..."

  # 1. 读取语义版本
  if [ ! -f "backend/package.json" ]; then
    log_error "backend/package.json 不存在！"
    exit 1
  fi

  SEMVER=$(node -p "require('./backend/package.json').version" 2>/dev/null)
  if [ -z "$SEMVER" ]; then
    log_error "无法读取package.json中的版本号！"
    exit 1
  fi

  # 2. 获取Git commit
  if ! git rev-parse --git-dir > /dev/null 2>&1; then
    log_error "当前目录不是Git仓库！"
    exit 1
  fi

  GIT_COMMIT=$(git rev-parse --short HEAD)

  # 3. 生成时间戳
  TIMESTAMP=$(date '+%Y%m%d-%H%M%S')

  # 4. 组合完整版本
  FULL_VERSION="v${SEMVER}+${GIT_COMMIT}+${TIMESTAMP}"

  # 5. 导出环境变量（供后续步骤使用）
  export APP_VERSION="$FULL_VERSION"
  export GIT_COMMIT="$GIT_COMMIT"
  export BUILD_TIME=$(date -Iseconds)

  log_info "✅ 版本号: $FULL_VERSION"
  log_info "   语义版本: v$SEMVER"
  log_info "   Git Commit: $GIT_COMMIT"
  log_info "   构建时间: $BUILD_TIME"
}
```

#### 步骤5: 备份当前版本（支持回滚）

```bash
backup_current_version() {
  log_step "备份当前版本..."

  # 检查是否首次部署
  if [ ! -f "deployments.json" ]; then
    log_info "首次部署，无需备份"
    return 0
  fi

  # 读取当前版本
  CURRENT_VERSION=$(jq -r '.currentVersion' deployments.json 2>/dev/null)
  if [ -z "$CURRENT_VERSION" ] || [ "$CURRENT_VERSION" == "null" ]; then
    log_warn "无法读取当前版本，跳过备份"
    return 0
  fi

  # 创建备份目录
  BACKUP_PATH="backups/deployments/${CURRENT_VERSION}"
  mkdir -p "$BACKUP_PATH"

  # 备份配置文件
  cp docker-compose.yml "$BACKUP_PATH/" 2>/dev/null || log_warn "docker-compose.yml备份失败"
  cp .env "$BACKUP_PATH/" 2>/dev/null || log_warn ".env备份失败"

  # 保存元数据
  cat > "$BACKUP_PATH/metadata.json" <<EOF
{
  "version": "$CURRENT_VERSION",
  "backupTime": "$(date -Iseconds)",
  "dockerImages": $(docker-compose images --quiet 2>/dev/null | jq -R . | jq -s . || echo "[]"),
```

## 6. 回滚机制设计

### 6.1 回滚流程总览

```
┌─────────────────────────────────────────────────────────────┐
│                      回滚流程                                │
└─────────────────────────────────────────────────────────────┘

步骤1: 用户执行回滚命令
  └─ bash scripts/rollback.sh [目标版本]

步骤2: 解析目标版本
  ├─ 如果未指定版本 → 回滚到上一个版本
  ├─ 如果指定完整版本 → v0.1.0+e78ad3d+20260320-143022
  └─ 如果指定语义版本 → v0.1.0（自动找最新的0.1.0）

步骤3: 验证目标版本
  ├─ 检查deployments.json中是否存在该版本
  ├─ 检查Docker镜像是否存在
  └─ 检查备份文件是否存在

步骤4: 确认回滚操作
  ├─ 显示当前版本
  ├─ 显示目标版本
  ├─ 询问用户确认（可跳过 --yes）
  └─ 等待用户输入 YES

步骤5: 备份当前版本（双重保险）
  ├─ 创建回滚前快照
  └─ 保存当前配置和镜像信息

步骤6: 停止当前服务
  ├─ docker-compose down
  └─ 等待容器完全停止

步骤7: 恢复配置文件
  ├─ 从备份恢复docker-compose.yml
  ├─ 从备份恢复.env
  └─ 更新镜像版本为目标版本

步骤8: 启动目标版本
  ├─ docker-compose up -d
  └─ 等待容器启动

步骤9: 健康检查
  ├─ 轮询 /health 接口
  └─ 验证服务正常

步骤10: 验证版本
  ├─ 调用 /version 接口
  └─ 确认返回的版本号与目标版本一致

步骤11: 记录回滚操作
  ├─ 追加回滚记录到deployments.json
  └─ 更新currentVersion

步骤12: 完成回滚
  ├─ 打印回滚报告
  └─ 退出（返回0）
```

### 6.2 回滚命令详解

**命令格式**：

```bash
# 回滚到上一个版本（最常用）
bash scripts/rollback.sh

# 回滚到指定完整版本
bash scripts/rollback.sh v0.1.0+e78ad3d+20260320-143022

# 回滚到指定语义版本（自动选最新的）
bash scripts/rollback.sh v0.1.0

# 回滚到N分钟前的版本
bash scripts/rollback.sh --time=10m

# 跳过确认（危险操作）
bash scripts/rollback.sh v0.1.0 --yes

# 列出可回滚的版本
bash scripts/rollback.sh --list
```

### 6.3 回滚脚本核心逻辑

```bash
#!/bin/bash
# ============================================================
# Planning App - 回滚脚本
# ============================================================

set -e

# 颜色输出
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
RED='\033[0;31m'
NC='\033[0m'

log_info() { echo -e "${GREEN}[INFO]${NC} $1"; }
log_warn() { echo -e "${YELLOW}[WARN]${NC} $1"; }
log_error() { echo -e "${RED}[ERROR]${NC} $1"; }

# ============================================================
# 函数: 获取目标版本
# ============================================================
get_target_version() {
  local input_version="$1"

  # 检查deployments.json是否存在
  if [ ! -f "deployments.json" ]; then
    log_error "deployments.json 不存在！无法回滚"
    exit 1
  fi

  # 如果未指定版本，回滚到上一个版本
  if [ -z "$input_version" ]; then
    log_info "未指定版本，回滚到上一个版本..."
    TARGET_VERSION=$(jq -r '.history[-2].version' deployments.json)
  else
    # 检查是否是完整版本（包含commit和时间戳）
    if echo "$input_version" | grep -qE '\+[0-9a-f]{7}\+[0-9]{8}-[0-9]{6}'; then
      # 完整版本，直接使用
      TARGET_VERSION="$input_version"
    else
      # 语义版本，找最新的该版本
      log_info "查找最新的 $input_version 版本..."
      TARGET_VERSION=$(jq -r ".history[] | select(.semver == \"${input_version#v}\") | .version" deployments.json | tail -1)
    fi
  fi

  # 验证版本是否存在
  if [ -z "$TARGET_VERSION" ] || [ "$TARGET_VERSION" == "null" ]; then
    log_error "无法找到目标版本: $input_version"
    log_info "可用版本:"
    jq -r '.history[] | "  \(.version) - \(.timestamp)"' deployments.json
    exit 1
  fi

  echo "$TARGET_VERSION"
}

# ============================================================
# 函数: 验证目标版本
# ============================================================
validate_target_version() {
  local target_version="$1"

  log_info "验证目标版本: $target_version"

  # 1. 检查Docker镜像是否存在
  if ! docker images | grep -q "planning-app-backend.*${target_version}"; then
    log_error "Docker镜像不存在: planning-app-backend:${target_version}"
    log_info "可用镜像:"
    docker images | grep planning-app-backend
    exit 1
  fi

  # 2. 检查备份文件是否存在（可选，不影响回滚）
  BACKUP_PATH="backups/deployments/${target_version}"
  if [ -d "$BACKUP_PATH" ]; then
    log_info "找到备份文件: $BACKUP_PATH"
  else
    log_warn "备份文件不存在，将使用Docker镜像回滚"
  fi

  log_info "✅ 验证通过"
}

# ============================================================
# 函数: 确认回滚操作
# ============================================================
confirm_rollback() {
  local current_version="$1"
  local target_version="$2"
  local skip_confirm="$3"

  echo
  log_warn "============================================================"
  log_warn "  即将执行回滚操作"
  log_warn "============================================================"
  echo "  当前版本: $current_version"
  echo "  目标版本: $target_version"
  echo

  if [ "$skip_confirm" != "yes" ]; then
    read -p "  是否继续? (输入 YES 确认): " CONFIRM
    if [ "$CONFIRM" != "YES" ]; then
      log_info "回滚已取消"
      exit 0
    fi
  else
    log_warn "跳过确认（--yes参数）"
  fi
}

# ============================================================
# 函数: 执行回滚
# ============================================================
execute_rollback() {
  local target_version="$1"

  log_info "============================================================"
  log_info "  开始回滚到: $target_version"
  log_info "============================================================"

  # 1. 备份当前版本（双重保险）
  log_info "[1/7] 备份当前版本..."
  CURRENT_VERSION=$(jq -r '.currentVersion' deployments.json)
  BACKUP_PATH="backups/rollback_from_${CURRENT_VERSION}_$(date +%Y%m%d-%H%M%S)"
  mkdir -p "$BACKUP_PATH"
  cp docker-compose.yml "$BACKUP_PATH/" || true
  cp .env "$BACKUP_PATH/" || true
  log_info "✅ 已备份到: $BACKUP_PATH"

  # 2. 停止当前服务
  log_info "[2/7] 停止当前服务..."
  docker-compose down
  log_info "✅ 服务已停止"

  # 3. 恢复配置文件（如果备份存在）
  log_info "[3/7] 恢复配置文件..."
  TARGET_BACKUP_PATH="backups/deployments/${target_version}"
  if [ -d "$TARGET_BACKUP_PATH" ]; then
    cp "$TARGET_BACKUP_PATH/docker-compose.yml" ./docker-compose.yml || log_warn "恢复docker-compose.yml失败"
    cp "$TARGET_BACKUP_PATH/.env" ./.env || log_warn "恢复.env失败"
    log_info "✅ 配置文件已恢复"
  else
    log_warn "备份不存在，仅切换镜像版本"
    # 更新docker-compose.yml中的镜像版本
    sed -i "s|image: planning-app-backend:.*|image: planning-app-backend:${target_version}|" docker-compose.yml
  fi

  # 4. 启动目标版本
  log_info "[4/7] 启动目标版本..."
  docker-compose up -d
  log_info "✅ 服务已启动"

  # 5. 等待健康检查
  log_info "[5/7] 等待服务健康检查..."
  sleep 30
  MAX_RETRIES=30
  RETRY_COUNT=0
  while [ $RETRY_COUNT -lt $MAX_RETRIES ]; do
    if curl -s -f http://localhost/health > /dev/null 2>&1; then
      log_info "✅ 健康检查通过"
      break
    fi
    RETRY_COUNT=$((RETRY_COUNT + 1))
    log_info "健康检查中... ($RETRY_COUNT/$MAX_RETRIES)"
    sleep 2
  done

  if [ $RETRY_COUNT -eq $MAX_RETRIES ]; then
    log_error "健康检查超时！回滚可能失败"
    log_error "请检查日志: docker-compose logs"
    exit 1
  fi

  # 6. 验证版本
  log_info "[6/7] 验证版本..."
  ACTUAL_VERSION=$(curl -s http://localhost/version | jq -r '.version' 2>/dev/null || echo "unknown")
  log_info "   API返回版本: $ACTUAL_VERSION"
  log_info "   目标版本: $target_version"

  # 7. 记录回滚操作
  log_info "[7/7] 记录回滚操作..."
  HISTORY=$(jq '.history' deployments.json)
  ROLLBACK_RECORD=$(cat <<EOF
{
  "version": "$target_version",
  "timestamp": "$(date -Iseconds)",
  "action": "rollback",
  "operator": "$USER",
  "fromVersion": "$CURRENT_VERSION",
  "success": true
}
EOF
  )
  echo "$HISTORY" | jq ". += [$ROLLBACK_RECORD]" > /tmp/history.json
  jq ".currentVersion = \"$target_version\" | .history = $(cat /tmp/history.json)" deployments.json > /tmp/deployments.json
  mv /tmp/deployments.json deployments.json
  rm /tmp/history.json
  log_info "✅ 回滚操作已记录"
}

# ============================================================
# 主流程
# ============================================================
main() {
  # 解析参数
  INPUT_VERSION=""
  SKIP_CONFIRM="no"
  LIST_VERSIONS="no"

  while [[ $# -gt 0 ]]; do
    case $1 in
      --yes)
        SKIP_CONFIRM="yes"
        shift
        ;;
      --list)
        LIST_VERSIONS="yes"
        shift
        ;;
      --time=*)
        TIME_AGO="${1#*=}"
        # TODO: 实现时间回滚逻辑
        shift
        ;;
      *)
        INPUT_VERSION="$1"
        shift
        ;;
    esac
  done

  # 列出版本
  if [ "$LIST_VERSIONS" == "yes" ]; then
    log_info "可回滚的版本:"
    jq -r '.history[] | "\(.version) - \(.timestamp) - \(.action)"' deployments.json
    exit 0
  fi

  # 获取目标版本
  TARGET_VERSION=$(get_target_version "$INPUT_VERSION")

  # 获取当前版本
  CURRENT_VERSION=$(jq -r '.currentVersion' deployments.json 2>/dev/null || echo "unknown")

  # 验证目标版本
  validate_target_version "$TARGET_VERSION"

  # 确认回滚
  confirm_rollback "$CURRENT_VERSION" "$TARGET_VERSION" "$SKIP_CONFIRM"

  # 执行回滚
  execute_rollback "$TARGET_VERSION"

  # 完成
  echo
  log_info "============================================================"
  log_info "✅ 回滚成功！"
  log_info "============================================================"
  log_info "  当前版本: $TARGET_VERSION"
  log_info "  验证接口: curl https://txjjzyzqbx.cn/version"
  log_info "  查看日志: docker-compose logs -f"
  echo
}

main "$@"
```

```javascript
    // 1. 读取环境变量（Docker构建时注入）

    const commit = process.env.GIT_COMMIT || 'unknown';
```

```bash
check_deployment_lock() {
  if [ -f "$DEPLOYMENT_LOCK" ]; then
    LOCK_TIME=$(stat -c %Y "$DEPLOYMENT_LOCK" 2>/dev/null || stat -f %m "$DEPLOYMENT_LOCK" 2>/dev/null)
    CURRENT_TIME=$(date +%s)
    LOCK_AGE=$((CURRENT_TIME - LOCK_TIME))

    if [ $LOCK_AGE -gt 1800 ]; then
      log_warn "部署锁已存在超过30分钟，可能是上次部署异常中断"
      read -p "是否强制解锁? (y/N): " FORCE_UNLOCK
      if [ "$FORCE_UNLOCK" == "y" ]; then

        log_info "已强制解锁"

        exit 1

    else

      log_error "如果确定没有其他部署，请删除: $DEPLOYMENT_LOCK"
      exit 1

  fi

  touch "$DEPLOYMENT_LOCK"
  log_info "已创建部署锁"
```

```bash
# ============================================================
# 部署历史操作库
# ============================================================

DEPLOYMENT_JSON="${DEPLOYMENT_JSON:-./deployments.json}"

# 初始化deployments.json

# 添加部署记录

  local version="$1"
  local semver="$2"
  local commit="$3"
  local action="$4"
  local operator="$5"
  local success="$6"

  init_deployment_json

  # 获取健康状态
  local health_status=$(curl -s http://localhost/health | jq -r '.status' 2>/dev/null || echo "unknown")
  local response_time=$(curl -w "%{time_total}" -o /dev/null -s http://localhost/health 2>/dev/null || echo "0")

  # 读取现有历史
  local history=$(jq '.history' "$DEPLOYMENT_JSON")

  # 创建新记录
  local new_record=$(cat <<EOF
{
  "version": "$version",
  "semver": "$semver",
  "commit": "$commit",
  "timestamp": "$(date -Iseconds)",
  "action": "$action",
  "operator": "$operator",
  "success": $success,
  "env": "production",
  "healthCheck": {
    "status": "$health_status",
    "responseTime": "${response_time}s"
  }
}
EOF
  )

  # 追加到历史
  echo "$history" | jq ". += [$new_record]" > /tmp/history.json

  # 更新deployments.json
  jq ".currentVersion = \"$version\" | .lastDeployTime = \"$(date -Iseconds)\" | .deployCount = (.deployCount + 1) | .history = $(cat /tmp/history.json)" "$DEPLOYMENT_JSON" > /tmp/deployments.json
  mv /tmp/deployments.json "$DEPLOYMENT_JSON"
  rm /tmp/history.json
}

# 获取当前版本
get_current_version() {
  init_deployment_json
  jq -r '.currentVersion' "$DEPLOYMENT_JSON"
}

# 获取上一个版本
get_previous_version() {
  init_deployment_json
  jq -r '.history[-2].version' "$DEPLOYMENT_JSON"
}
```

## 11. 常见问题与解决方案

### 11.1 部署类问题

**Q1: 部署时提示"部署锁已存在"**

**原因**: 上次部署异常中断，锁文件未删除

**解决**:
```bash
# 确认没有其他部署正在进行
docker-compose ps

# 删除锁文件
rm -f .deployment_lock

# 重新部署
bash scripts/deploy-v2.sh
```

**Q2: Docker镜像构建失败**

**原因**:
- 网络问题（无法拉取基础镜像）
- 磁盘空间不足
- Dockerfile语法错误

**解决**:
```bash
# 检查磁盘空间
df -h

# 清理Docker缓存
docker system prune -f

# 手动构建测试
cd backend
docker build -t test .
```

**Q3: 健康检查超时**

**原因**:
- 服务启动慢（数据库迁移耗时）
- 端口未开放
- 服务启动失败

**解决**:
```bash
# 查看容器日志
docker-compose logs backend

# 检查端口
netstat -tuln | grep 3000

# 手动测试健康接口
curl http://localhost:3000/health
```

### 11.2 回滚类问题

**Q4: 回滚时提示"镜像不存在"**

**原因**: Docker镜像已被清理

**解决方案A（从Git重新构建）**:
```bash
# 检出目标版本的代码
git checkout <commit>

# 重新构建镜像
bash scripts/deploy-v2.sh

# 回到当前分支
git checkout -
```

**解决方案B（从备份仓库拉取）**:
```bash
# 如果配置了镜像仓库
docker pull registry.example.com/planning-app-backend:v0.1.0
docker tag registry.example.com/planning-app-backend:v0.1.0 planning-app-backend:v0.1.0
```

**Q5: 回滚后数据库报错**

**原因**: 新版本的数据库schema无法在旧版本运行

**解决**: 数据库也回滚（⚠️ 数据会丢失）
```bash
# 找到对应版本的数据库备份
ls backups/mysql/

# 恢复数据库
bash scripts/restore-mysql.sh backups/mysql/v0.1.0_db.sql.gz

# 警告：会丢失回滚时间点之后的数据
```

**最佳实践**: 数据库迁移必须向后兼容
- 新增字段时设置默认值
- 删除字段分两步：先废弃 → 下个大版本再删除
- 修改字段类型时保留原字段，新增新字段

**Q6: 回滚后前端报错**

**原因**: 前端缓存了旧版本API

**解决**:
```bash
# 清理前端缓存
# H5端：Ctrl+Shift+R 强制刷新
# App端：清除应用缓存

# 或在Nginx配置添加no-cache头
add_header Cache-Control "no-cache, must-revalidate";
```

### 11.3 版本管理问题

**Q7: deployments.json文件损坏**

**原因**:
- 磁盘满
- 写入中断
- JSON格式错误

**解决**:
```bash
# 尝试修复JSON
cat deployments.json | jq . > /tmp/deployments_fixed.json
mv /tmp/deployments_fixed.json deployments.json

# 如果无法修复，从备份恢复
cp deployments.json.bak deployments.json

# 如果没有备份，重建（会丢失历史）
cat > deployments.json <<EOF
{
  "currentVersion": "当前版本",
  "lastDeployTime": "$(date -Iseconds)",
  "deployCount": 0,
  "history": []
}
EOF
```

**预防措施**: 每次更新前自动备份
```bash
# 在deployment-history.sh中添加
cp deployments.json deployments.json.bak 2>/dev/null || true
```

**Q8: 版本号冲突（时间戳相同）**

**原因**: 快速连续部署导致秒级时间戳相同

**解决**: 使用毫秒级时间戳
```bash
# 改进版时间戳生成
TIMESTAMP=$(date '+%Y%m%d-%H%M%S')-$(date '+%N' | cut -c1-3)
# 输出: 20260320-143022-456
```

### 11.4 性能优化问题

**Q9: 镜像构建太慢**

**优化1**: 使用多阶段构建缓存
```dockerfile
# 分离依赖安装和代码复制
COPY package*.json ./
RUN npm ci  # 这一层会被缓存

COPY . .  # 代码变更不影响上层缓存
```

**优化2**: 使用BuildKit
```bash
export DOCKER_BUILDKIT=1
docker build ...
```

**优化3**: 并行构建多个服务
```bash
# 同时构建backend和frontend
docker-compose build --parallel
```

**Q10: 部署过程太长**

**优化**: 减少健康检查等待时间
```bash
# 使用更激进的健康检查
MAX_RETRIES=30  # 从60改为30
RETRY_INTERVAL=1  # 从2秒改为1秒
```

## 12. 最佳实践

### 12.1 版本号管理最佳实践

**原则1: 语义化版本必须手动维护**
- ✅ 每次发布前手动更新package.json
- ✅ 遵循SemVer规范（MAJOR.MINOR.PATCH）
- ❌ 不要自动递增版本号（容易出错）

**原则2: Git commit必须规范**
- ✅ 使用Conventional Commits规范
- ✅ 格式: `<type>(<scope>): <subject>`
- ✅ 类型: feat/fix/docs/refactor/test/chore

示例:
```bash
git commit -m "feat(task): 添加任务拖拽功能"
git commit -m "fix(auth): 修复JWT过期问题"
git commit -m "docs(deploy): 更新部署文档"
```

**原则3: 部署前必须提交代码**
```bash
# 错误示例
bash scripts/deploy-v2.sh  # 有未提交的修改

# 正确示例
git add .
git commit -m "feat: xxx"
git push
bash scripts/deploy-v2.sh
```

### 12.2 部署流程最佳实践

**原则4: 小步快跑，频繁部署**
- ✅ 每天部署1-2次（小改动）
- ✅ 每次部署只包含少量功能
- ❌ 避免大批量修改一次性部署

**原则5: 生产部署前先测试**
```bash
# 本地测试
docker-compose -f docker-compose.dev.yml up

# 模拟生产环境测试
NODE_ENV=production docker-compose up

# 确认无误后再部署
bash scripts/deploy-v2.sh
```

**原则6: 部署时间选择**
- ✅ 在低峰时段部署（凌晨/深夜）
- ✅ 避免在工作日白天部署重大更新
- ✅ 部署前通知用户（如果有用户）

### 12.3 回滚策略最佳实践

**原则7: 快速回滚原则**
- ✅ 发现问题立即回滚（不要尝试修复）
- ✅ 回滚后在本地修复，重新部署
- ❌ 不要在生产环境直接修复

**原则8: 回滚后的处理**
```bash
# 1. 回滚
bash scripts/rollback.sh v0.1.0

# 2. 记录问题
echo "回滚原因: v0.1.1导致用户登录失败" >> rollback-notes.txt

# 3. 本地修复
git checkout develop
# 修复代码...
git commit -m "fix: 修复登录问题"

# 4. 重新部署
vim backend/package.json  # 改为0.1.2
bash scripts/deploy-v2.sh
```

**原则9: 数据库回滚谨慎**
- ✅ 尽量避免数据库回滚（会丢失数据）
- ✅ 数据库迁移必须向后兼容
- ✅ 重要操作前手动备份数据库
