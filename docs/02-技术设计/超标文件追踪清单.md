## 📖 使用说明

### Claude 如何使用本文件

**1. 发现新的超标文件时**：
```markdown
步骤1：计算超标百分比
  超标% = (当前行数 - 800) / 800 * 100%

步骤2：确定优先级
  > 2000行 → P0
  1000-2000行 → P1
  800-1000行 → P2

步骤3：在"待处理"表格中新增一行
  填写：文件路径、行数、超标%、发现时间、状态"📋 已标记"

步骤4：在"最近提醒记录"中添加提醒记录

步骤5：向用户发出提醒
```

**2. 用户要求生成拆分方案时**：
```markdown
步骤1：创建评估报告和拆分方案文档

步骤2：更新本文件
  - 状态改为"🟡 评估中"
  - 在"拆分方案文档索引"中添加链接

步骤3：提交给用户审批
```

**3. 用户批准拆分后**：
```markdown
步骤1：状态改为"✅ 方案已批准"

步骤2：执行拆分

步骤3：拆分完成后，状态改为"✔️ 已完成"

步骤4：移动到"已处理"区域，更新统计数据
```

## 📏 四层架构文件规模阈值 ⭐ 新增（2026-03-09）

根据 [四层架构设计（渐进式升级）.md](./四层架构设计（渐进式升级）.md)，不同架构层级有不同的文件规模阈值：

| 层级 | 阈值 | 理由 | 示例 |
|------|------|------|------|
| **Component 层** | <800行 | UI层应保持轻量，超过800行说明职责过重 | `pages/**/*.vue`、`components/**/*.vue` |
| **Composable 层** | <600行 | 业务流程层应职责单一，超过600行建议拆分 | `composables/*.js` |
| **Store 层** | <400行 | 状态管理应简洁，超过400行说明职责过重 | `store/*.js` |
| **Repository 层** | <500行 | 数据访问层相对固定，超过500行建议拆分 | `repositories/*.js` |
| **Utils 工具函数** | <300行 | 纯工具函数应短小精悍 | `utils/*.js` |

**超标判定规则**：

```
超标百分比 = (当前行数 - 阈值) / 阈值 * 100%

优先级判定：
- P0（严重超标）：超标 > 150%（如 Component > 2000行）
- P1（中度超标）：超标 25-150%（如 Component 1000-2000行）
- P2（轻度超标）：超标 0-25%（如 Component 800-1000行）
```

**拆分策略**（参考四层架构文档第8节）：

1. **Component 过重** → 提取 Composable 层（复杂表单逻辑、多Store协调）
2. **Composable 过重** → 拆分为多个 Composable 或提取纯函数到 utils/
3. **Store 过重** → 拆分为多个 Store（按功能模块划分）
4. **Repository 过重** → 拆分为多个 Repository（按数据实体划分）
