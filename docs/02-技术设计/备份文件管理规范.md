# 备份文件管理规范

> **目的**: 统一备份文件命名、存放、清理规则，防止误用备份文件
> **强制等级**: ⭐⭐⭐⭐⭐ 最高优先级
> **创建时间**: 2026-03-10
> **适用范围**: 所有代码重构、架构调整场景

---

## 1. 备份文件命名规范 ⭐ 强制执行

### 命名格式

```
<原文件名>.backup-<日期>-<目的>-<状态>.<扩展名>
```

**示例**：
```
✅ 正确命名：
  index.vue.backup-20260307-重构前-已完成.vue
  task-edit.vue.backup-20260308-提取组件前-已完成.vue
  AddTaskPanel.vue.backup-20260309-集成useTaskForm前-已废弃.vue

❌ 错误命名：
  index.vue.backup（缺少日期和目的）
  task-edit.bak（非标准扩展名）
  old-task-edit.vue（不清晰）
```

### 命名组成部分说明

| 部分 | 说明 | 可选值 |
|------|------|--------|
| `<日期>` | 8位数字，格式YYYYMMDD | 如 20260307 |
| `<目的>` | 备份原因，简短清晰 | 重构前、提取组件前、修复bug前、架构调整前 |
| `<状态>` | 当前状态 | 已完成、进行中、已废弃、待验证 |

## 2. 备份文件存放位置 ⭐ 强制执行

### 规则

**禁止**: 备份文件与源文件放在同一目录（容易误用）

**正确做法**: 所有备份文件统一存放在 `backups/` 目录

### 目录结构

```
Planning-app/
├── backups/                          ⭐ 备份文件统一存放目录
│   ├── pages/
│   │   └── calendar/
│   │       ├── index.vue.backup-20260307-Phase3重构前-已完成.vue
│   │       ├── task-edit.vue.backup-20260308-提取组件前-进行中.vue
│   │       └── ...
│   ├── components/
│   │   └── task/
│   │       ├── AddTaskPanel.vue.backup-20260309-集成useTaskForm前-已废弃.vue
│   │       └── ...
│   └── README.md                     备份目录说明文档
├── pages/
│   └── calendar/
│       ├── index.vue                 ⭐ 源文件（当前版本）
│       ├── task-edit.vue
│       └── ...
├── components/
│   └── task/
│       ├── AddTaskPanel.vue
│       └── ...
```

### 创建备份的标准流程

```bash
# 步骤1：创建backups目录（如果不存在）
mkdir -p backups/pages/calendar
mkdir -p backups/components/task

# 步骤2：复制文件到backups目录并重命名
cp pages/calendar/task-edit.vue backups/pages/calendar/task-edit.vue.backup-20260310-迁移save函数前-进行中.vue

# 步骤3：在 backups/README.md 中登记备份信息
```

## 4. Claude 使用备份文件的规则

### 规则1：读取代码时必须检查是否是备份文件

**强制检查流程**：

```
步骤1：使用 Read 工具前，检查文件路径
  文件路径包含 "backups/" → 这是备份文件！
  文件名包含 ".backup" → 这是备份文件！

步骤2：如果是备份文件
  向用户确认："⚠️ 检测到这是备份文件（<文件名>），您是需要查看历史版本吗？"
  等待用户确认后才读取

步骤3：如果用户未明确要求查看备份
  应读取源文件路径（如 pages/calendar/task-edit.vue）
  而不是备份文件路径（如 backups/pages/calendar/task-edit.vue.backup-xxx.vue）
```

### 规则2：创建备份文件的标准流程

**何时创建备份**：

| 场景 | 是否需要备份 |
|------|------------|
| 文件超过1000行 + 重构 | ✅ 必须备份 |
| 复杂重构（预计改动>500行） | ✅ 必须备份 |
| 简单修改（<100行） | ❌ 不需要备份（Git历史足够） |
| 架构调整、分层重构 | ✅ 必须备份 |

**创建流程**：

```
步骤1：判断是否需要备份
  参考上表规则

步骤2：创建backups目录（如果不存在）
  mkdir -p backups/<源文件相对路径>

步骤3：复制文件并重命名
  格式：<原文件名>.backup-<YYYYMMDD>-<目的>-<状态>.<扩展名>
  示例：cp pages/calendar/task-edit.vue backups/pages/calendar/task-edit.vue.backup-20260310-迁移save函数前-进行中.vue

步骤4：在 backups/README.md 中登记
  - 在"进行中的备份"表格中新增一行
  - 填写：备份文件、源文件、日期、目的、状态、关联文档

步骤5：Git commit 记录备份操作
  git add backups/
  git commit -m "backup(<模块>): 创建<文件名>备份（<目的>）"
```

### 规则3：重构完成后的备份处理

**更新流程**：

```
步骤1：更新 backups/README.md
  - 将对应备份从"进行中"移到"已完成"
  - 更新重构结果（如：3802行→789行）
  - 填写完成时间

步骤2：询问用户是否删除备份
  格式："✅ <文件名> 重构已完成（<原行数>→<现行数>），是否删除备份文件？
  建议：重构完成后保留1-2周，验证无问题后删除"

步骤3：用户确认后删除
  rm backups/<备份文件>
  在 backups/README.md 的"已废弃"区域记录删除日期和原因
```

### 恢复备份（如果重构失败）

```bash
# 从备份恢复源文件

# 提交恢复操作
git add pages/calendar/task-edit.vue
git commit -m "revert(task): 从备份恢复task-edit.vue（重构失败）"
```

### 定期清理备份

**清理策略**：

| 备份状态 | 清理时机 |
|---------|---------|
| 进行中的备份 | 不删除（重构未完成） |
| 已完成的备份 | 重构完成1-2周后，验证无问题可删除 |
| 已废弃的备份 | 立即删除 |

**清理命令**：

```bash
# 查看backups目录大小
du -sh backups/

# 删除单个备份文件
rm backups/pages/calendar/index.vue.backup-20260307-Phase3重构前-已完成.vue

# 删除后在 backups/README.md 中记录
```

## 6. 常见陷阱和纠正 ⚠️

### 陷阱1：误读备份文件作为当前代码

**现象**：
- Claude 在分析代码时，使用 Read 工具读取了 `index.vue.backup` 文件
- 导致Claude基于**旧版本代码**生成重构方案
- 用户发现Claude的描述与实际不符（如"4个Tab早已改为xx"）

**根本原因**：
- 备份文件与源文件放在同一目录
- Claude 读取代码前未检查是否是备份文件

**解决方案**：
```
Claude 在读取文件前必须检查：
  1. 文件路径是否在 backups/ 目录中？
  2. 文件名是否包含 .backup 关键词？
  3. 如果是备份文件，必须向用户确认："检测到这是备份文件，是否需要查看历史版本？"
  4. 用户未确认前，禁止读取备份文件
```

**预防措施**：
- ✅ 所有备份文件统一存放在 `backups/` 目录
- ✅ 备份文件命名包含 `.backup-` 关键词
- ✅ Claude 读取代码前强制检查路径和文件名

---

### 陷阱2：备份文件与源文件同目录

**错误示例**：
```
pages/calendar/
├── index.vue          ← 当前版本（789行）
├── index.vue.backup   ← 备份文件（3728行）❌ 错误放置！
└── task-edit.vue
```

**问题**：
- Claude 使用 Glob 工具查找 `pages/**/*.vue` 时会匹配到备份文件
- 容易误读备份文件
- 污染源代码目录

**正确做法**：
```
pages/calendar/
├── index.vue          ← 当前版本（789行）
└── task-edit.vue

backups/pages/calendar/
└── index.vue.backup-20260307-Phase3重构前-已完成.vue  ← 备份文件（3728行）✅
```

**强制规则**：
- ❌ 禁止在源代码目录（pages/、components/、composables/）中存放备份文件
- ✅ 所有备份文件必须存放在 `backups/` 目录

---

### 陷阱3：备份文件命名不清晰

**错误示例**：
```
❌ index.vue.backup       （缺少日期和目的）
❌ index.vue.old          （状态不清晰）
❌ index.vue.20260307     （缺少目的和状态）
❌ index-backup.vue       （不符合命名规范）
```

**问题**：
- 不知道备份的目的（为什么要备份？）
- 不知道当前状态（重构完成了吗？）
- 不知道是否可以删除
- 无法与源文件关联

**正确做法**：
```
✅ index.vue.backup-20260307-Phase3重构前-已完成.vue
   ↑ 清晰表明：日期、目的、状态、扩展名
```

**强制规则**：
- 日期：必须是8位数字YYYYMMDD格式
- 目的：必须简短清晰（如"重构前"、"提取组件前"）
- 状态：必须是4个状态之一（已完成、进行中、已废弃、待验证）
- 扩展名：必须保留原文件扩展名（如.vue、.js）

---

### 陷阱4：备份文件未登记

**现象**：
- 创建了备份文件但未在 `backups/README.md` 中登记
- 其他Claude实例不知道这个备份的目的和状态
- 无法追踪重构进度

**解决方案**：
```
强制规范：
  创建任何备份文件后，必须立即在 backups/README.md 中登记
  登记内容：备份文件名、源文件、日期、目的、状态、关联文档
```

---

### 陷阱5：长期不清理备份文件

**现象**：
- backups/ 目录堆积大量已完成的备份文件
- 占用磁盘空间
- 难以找到当前进行中的备份

**解决方案**：
```
清理策略：
  1. 重构完成1-2周后，验证无问题可删除"已完成"备份
  2. "已废弃"备份应立即删除
  3. 每月检查backups/目录大小，超过100MB应清理
```

## 7. 备份文件大小限制

**规则**：
- 单个备份文件 <10MB
- backups/ 目录总大小 <100MB
- 超过限制时，删除最旧的"已完成"备份

**检查命令**：
```bash
# 检查backups目录大小
du -sh backups/

# 检查单个备份文件大小
ls -lh backups/pages/calendar/

# 按文件大小排序（找出最大的备份文件）
du -h backups/**/*.vue | sort -hr | head -10
```

## 8. Git 管理备份文件

### 是否提交备份文件到Git？

**建议**：
- ✅ 重要的备份文件（如架构重构前）应提交到Git
- ✅ 进行中的备份应提交到Git（便于Claude切换）
- ❌ 临时备份（如小改动前）不需要提交

**提交规范**：
```bash
# 提交备份文件
git add backups/
git commit -m "backup(calendar): 创建task-edit.vue备份（迁移save函数前）"

# .gitignore 规则（可选）
# 如果不想提交所有备份，可以在.gitignore中配置：
# backups/**/*-临时备份-*.vue
```

## 11. 总结

### 核心原则

1. **统一存放**: 所有备份文件统一存放在 `backups/` 目录
2. **规范命名**: `<文件名>.backup-<日期>-<目的>-<状态>.<扩展名>`
3. **强制登记**: 所有备份文件必须在 `backups/README.md` 中登记
4. **读取检查**: Claude读取代码前必须检查是否是备份文件
5. **定期清理**: 重构完成1-2周后可删除已完成备份

### 预期效果

实施本规范后：
- ✅ 不再误读备份文件作为当前代码
- ✅ 备份文件清晰标记目的和状态
- ✅ 新Claude接手时可通过 backups/README.md 了解备份状态
- ✅ 重构失败时可快速恢复备份
- ✅ 避免备份文件堆积，定期清理
