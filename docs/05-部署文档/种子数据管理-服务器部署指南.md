## 5. 故障排查

### 5.1 容器启动失败（STATUS: Exited）

**现象**：`sudo docker compose ps` 显示 backend 容器 STATUS 为 "Exited"

**排查步骤**：

```bash
# 查看完整日志
sudo docker compose logs backend

# 查找错误信息
sudo docker compose logs backend | grep -i error
sudo docker compose logs backend | grep -i fail
```

**常见错误及解决方案**：

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `Cannot find module './src/services/holidayDataManager'` | 文件未复制到容器 | 重新构建镜像：`sudo docker compose build backend` |
| `SequelizeConnectionError` | 数据库连接失败 | 检查 MySQL 容器状态：`sudo docker compose ps mysql` |
| `npm ERR! missing script: db:seed` | package.json 中缺少脚本 | 检查 `backend/package.json` 是否有 `db:seed` 脚本 |

### 5.2 种子数据未导入（数据量仍为0）

**现象**：数据库查询 `SELECT COUNT(*)` 仍返回 0

**排查步骤**：

```bash
# 检查种子文件是否存在
sudo docker exec -it planning-app-backend ls -la /app/src/seeders/

# 手动运行种子导入脚本
sudo docker exec -it planning-app-backend node /app/seed-if-empty.js

# 查看输出日志
```

**可能原因**：
1. 种子文件命名错误（文件名不匹配）
2. 种子文件执行失败（语法错误）
3. 数据库权限问题

**解决方案**：
```bash
# 手动运行种子文件
sudo docker exec -it planning-app-backend npm run db:seed
```

### 5.3 定时任务未启动

**现象**：日志中没有看到 "[Scheduler] 定时任务调度器已启动"

**排查步骤**：

```bash
# 检查 scheduler.js 是否存在
sudo docker exec -it planning-app-backend ls -la /app/src/services/scheduler.js

# 检查 server.js 是否导入 scheduler
sudo docker exec -it planning-app-backend grep -n "scheduler" /app/server.js
```

**可能原因**：
1. `scheduler.js` 文件未复制到容器
2. `server.js` 未正确导入 scheduler
3. 代码语法错误导致模块加载失败

**解决方案**：
```bash
# 重新构建镜像
sudo docker compose build backend
sudo docker compose up -d backend
```

### 5.4 APP 端仍无法显示数据

**现象**：服务器数据正常，但APP端仍显示空白

**排查步骤**：

1. **检查 APP 端网络请求**：
   - 打开 APP 的开发者工具
   - 查看 Network 请求是否成功
   - 确认返回数据不为空

2. **清除 APP 缓存**：
   ```javascript
   // APP 设置 → 清除缓存 → 重启 APP
   ```

3. **检查前端代码版本**：
   - 确认前端代码是否也已更新
   - 前端 `HolidayDataService.js` 和 `HolidayRepository.js` 是否正常

4. **检查 localStorage 缓存**：
   ```javascript
   // 在 APP 控制台执行
   localStorage.clear();
   location.reload();
   ```

## 6. 回滚方案

### 6.1 快速回滚（回退到上一个版本）

```bash
# SSH 登录服务器
ssh ubuntu@154.8.183.203
cd /opt/planning-app/planning-app

# 查看当前版本
git log --oneline -1

# 回退到上一个版本（3298e70）
git reset --hard 3298e70

# 重新构建并重启
sudo docker compose build backend
sudo docker compose up -d backend

# 验证回滚成功
sudo docker compose logs backend --tail 50
```

**⚠️ 回滚后的影响**：
- ❌ 定时任务功能将失效（无11月1日提醒）
- ✅ 种子数据导入功能仍可用（3298e70 版本已支持）
- ✅ 数据库已导入的数据不受影响

### 6.2 数据库回滚（恢复备份）
