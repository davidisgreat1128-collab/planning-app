## ⚠️ 需要修复的3个问题

### 问题1: HTTP不会自动跳转到HTTPS

**现象**: 用户访问 `http://txjjzyzqbx.cn` 时不会自动跳转到 `https://`

**原因**: 当前使用的是 `planning-app-http.conf`（临时配置），未配置301跳转

**影响**:
- 用户可能访问不安全的HTTP版本
- 搜索引擎可能索引HTTP和HTTPS两个版本（SEO不利）
- Apple App Store审核可能被拒（要求强制HTTPS）

### 问题2: API v1 路径返回404

**现象**: `https://txjjzyzqbx.cn/api/v1/health` 返回 404

**原因**: `planning-app-http.conf` 配置已被简化，未包含API代理

**影响**: 前端无法访问后端API

### 问题3: TLS版本检测失败

**现象**: 验证脚本无法检测到TLS版本

**原因**: `openssl s_client` 命令执行方式需要优化

**影响**: 无法确认是否使用了最新的TLS 1.3协议

## 🔧 解决方案：启用HTTPS配置

### 方案概述

切换Nginx配置文件：

```
当前配置（临时）:
  ├─ planning-app-http.conf ← 仅用于SSL证书申请
  └─ planning-app-https.conf ← 完整的HTTPS配置（未启用）

切换后（生产）:
  ├─ planning-app-http.conf.bak ← 已禁用
  ├─ planning-app-https.conf ← 保留原文件
  └─ planning-app.conf ← 从planning-app-https.conf复制（Nginx加载此文件）
```

## 🔍 故障排查

### 问题1: Nginx配置语法错误

**错误信息**:
```
nginx: [emerg] cannot load certificate "/etc/letsencrypt/live/txjjzyzqbx.cn/fullchain.pem"
```

**解决**:
检查证书文件权限：
```bash
sudo ls -la /etc/letsencrypt/live/txjjzyzqbx.cn/
sudo chmod 644 /etc/letsencrypt/live/txjjzyzqbx.cn/*.pem
```

### 问题2: HTTPS访问502错误

**原因**: Backend容器未运行

**解决**:
```bash
docker compose ps
docker compose restart backend
docker compose logs backend
```

### 问题3: HTTP跳转仍未生效

**原因**: 浏览器缓存了旧的响应

**解决**:
- 清空浏览器缓存

## 📝 配置文件说明

### planning-app-http.conf（临时配置，已禁用）

**用途**: 仅用于SSL证书申请时的HTTP-01验证

**特点**:
- 监听80端口
- 提供 `/.well-known/acme-challenge/` 路径（Let's Encrypt验证）
- 临时提供健康检查和API代理（证书申请前）

**禁用时机**: SSL证书申请成功后立即禁用

### planning-app-https.conf（生产配置）

**用途**: 生产环境完整配置

**特点**:
- **HTTP部分**（80端口）:
  - `/.well-known/acme-challenge/` - 证书续期路径（必须保留）
  - `/health` - 健康检查（不跳转，用于Docker健康检查）
  - 其他所有请求 → 301跳转到HTTPS

- **HTTPS部分**（443端口）:
  - SSL证书配置（TLS 1.2/1.3）
  - 安全响应头（HSTS、CSP、X-Frame-Options等）
  - API代理（`/api/v1/`）
  - 健康检查（`/health`）
  - WebSocket支持

**启用方式**: 复制为 `planning-app.conf`，Nginx会自动加载

## ⏰ 证书自动续期

切换到HTTPS配置后，证书续期仍然正常工作：

### 续期工作原理

1. **Cron定时任务**（每周日凌晨3点）:
   ```bash
   0 3 * * 0 certbot renew --quiet --deploy-hook "docker compose -f /opt/planning-app/planning-app/docker-compose.yml exec nginx nginx -s reload"
   ```

2. **Certbot验证路径**:
   - 访问 `http://txjjzyzqbx.cn/.well-known/acme-challenge/<token>`
   - Nginx配置已保留此路径（planning-app-https.conf 第26-30行）
   - 验证成功后更新证书

3. **自动重载Nginx**:
   - `--deploy-hook` 会在证书更新后自动重载Nginx
   - 无需手动干预

### 检查续期配置

```bash
# 查看cron任务
crontab -l | grep certbot

# 手动测试续期（dry-run）
sudo certbot renew --dry-run

# 查看证书有效期
sudo openssl x509 -in /etc/letsencrypt/live/txjjzyzqbx.cn/fullchain.pem -noout -dates
```
