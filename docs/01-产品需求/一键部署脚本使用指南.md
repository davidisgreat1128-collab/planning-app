## 快速开始

### 首次部署（完整流程）

```bash
# 1. 进入项目目录
cd /opt/planning-app/planning-app

# 2. 确保.env文件已配置
cp .env.example .env
vim .env  # 配置数据库密码、JWT密钥等

# 3. 运行一键部署脚本
sudo bash scripts/deploy-production.sh
```

**执行时间**: 约5-10分钟
**预期结果**: HTTPS生产环境完全就绪

## 部署模式

### 1. 完整部署（full，默认）

```bash
sudo bash scripts/deploy-production.sh
# 或
sudo bash scripts/deploy-production.sh full
```

**适用场景**: 首次部署、全新服务器

**执行流程**:
1. ✅ 前置条件检查（Docker、.env、环境变量）
2. ✅ 拉取最新代码（Git pull develop）
3. ✅ 构建Docker镜像（Backend）
4. ✅ 启动Docker服务（MySQL、Redis、Backend、Nginx）
5. ✅ 服务健康检查（等待所有服务就绪）
6. ✅ 数据库初始化（迁移 + 种子数据）
7. ✅ 申请SSL证书（Let's Encrypt，webroot模式）
8. ✅ 切换HTTPS配置（Nginx配置切换）
9. ✅ 生产环境验证（17项检查）

**执行时间**: ~10分钟

## 前置条件

### 必须满足的条件

| 条件 | 检查方法 | 如何满足 |
|------|---------|---------|
| **Root权限** | `whoami` 返回 `root` | 使用 `sudo` 运行脚本 |
| **Docker已安装** | `docker --version` | [安装Docker](https://docs.docker.com/engine/install/) |
| **Docker Compose已安装** | `docker compose version` | 通常随Docker一起安装 |
| **.env文件已配置** | `cat .env` | 从 `.env.example` 复制并编辑 |
| **域名DNS已解析** | `nslookup txjjzyzqbx.cn` | 在域名注册商处配置A记录 |
| **80端口开放** | `nc -zv localhost 80` | 配置防火墙/安全组 |
| **443端口开放** | `nc -zv localhost 443` | 配置防火墙/安全组 |
| **Certbot已安装** | `certbot --version` | 脚本会自动安装 |

### .env文件必须配置的变量

```bash
# 数据库配置
MYSQL_ROOT_PASSWORD=your_secure_password_here

# Redis配置
REDIS_PASSWORD=your_redis_password_here

# JWT配置
JWT_SECRET=your_jwt_secret_here

# 域名配置（可选，脚本会使用默认值）
DOMAIN=txjjzyzqbx.cn
API_BASE_URL=https://txjjzyzqbx.cn/api/v1
CORS_ORIGIN=https://txjjzyzqbx.cn,https://www.txjjzyzqbx.cn
```

## 常见问题

### Q1: 脚本执行失败，如何查看详细错误？

**A**: 脚本使用 `set -e`，遇到错误会自动退出并显示错误信息。查看最后几行输出即可定位问题。

```bash
# 如果需要更详细的调试信息
bash -x scripts/deploy-production.sh
```

---

### Q2: SSL证书申请失败，怎么办？

**A**: 常见原因和解决方法：

| 错误 | 原因 | 解决方法 |
|------|------|---------|
| `Domain validation failed` | DNS未解析到服务器IP | 检查 `nslookup txjjzyzqbx.cn` |
| `Connection refused` | 80端口未开放 | 检查防火墙：`sudo ufw allow 80` |
| `.well-known` 不可访问 | Nginx配置错误 | 检查 `docker compose logs nginx` |
| `Rate limit exceeded` | 同一域名申请次数过多 | 等待1小时或使用 `--staging` 测试 |

**手动测试**:
```bash
# 测试.well-known路径是否可访问
curl http://txjjzyzqbx.cn/.well-known/acme-challenge/test

# 查看Certbot日志
sudo tail -f /var/log/letsencrypt/letsencrypt.log
```

---

### Q3: 数据库迁移失败，如何处理？

**A**: 脚本会捕获迁移错误并继续部署。如果需要手动迁移：

```bash
# 进入Backend容器
docker compose exec backend bash

# 手动运行迁移
npm run db:migrate

# 或强制重新迁移
npx sequelize-cli db:migrate:undo:all
npx sequelize-cli db:migrate
```

---

### Q4: 如何回滚到之前的版本？

**A**: 脚本不自动备份，但可以通过Git回滚：

```bash
# 查看Git历史
git log --oneline -10

# 回滚到指定提交
git reset --hard <commit-hash>

# 重新部署
sudo bash scripts/deploy-production.sh update
```

---

### Q5: 如何自定义域名？

**A**: 有两种方法：

**方法1: 使用环境变量**
```bash
DOMAIN=example.com EMAIL=admin@example.com sudo bash scripts/deploy-production.sh
```

**方法2: 修改.env文件**
```bash
# 编辑.env
vim .env

# 修改以下配置

API_BASE_URL=https://example.com/api/v1
CORS_ORIGIN=https://example.com,https://www.example.com

sudo bash scripts/deploy-production.sh
```

---

### Q6: 证书如何自动续期？

**A**: 脚本会在申请证书后自动配置Cron任务：

```bash
# 查看Cron任务
crontab -l | grep certbot

# 应该看到：
# 0 3 * * 0 certbot renew --quiet --deploy-hook "docker compose -f /opt/planning-app/planning-app/docker-compose.yml exec nginx nginx -s reload"

# 手动测试续期（不会真的续期）
sudo certbot renew --dry-run
```

## 故障排查

### 问题1: Docker服务启动失败

**检查步骤**:
```bash
# 1. 查看容器状态
docker compose ps

# 2. 查看失败容器的日志
docker compose logs <service_name>

# 3. 检查端口占用
sudo netstat -tulpn | grep -E ':(80|443|3000|3306|6379)'

# 4. 重启Docker服务
sudo systemctl restart docker
docker compose up -d
```

---

### 问题2: Nginx配置错误

**检查步骤**:
```bash
# 1. 查看Nginx日志
docker compose logs nginx | tail -50

# 2. 测试Nginx配置语法
docker compose exec nginx nginx -t

# 3. 检查配置文件
ls -la nginx/conf.d/

# 应该只有一个生效的配置文件：
# planning-app.conf（或planning-app-https.conf）
```

---

### 问题3: 生产验证失败

**处理方法**:

查看验证失败的具体项目，根据错误类型处理：

| 验证项 | 失败原因 | 解决方法 |
|--------|---------|---------|
| DNS解析失败 | DNS未生效 | 等待DNS传播（可能需要24小时） |
| SSL证书验证失败 | 证书未申请成功 | 重新运行 `ssl-only` 模式 |
| HTTP跳转失败 | Nginx配置未切换 | 手动运行 `enable-https.sh` |
| API路径404 | Backend未启动 | 检查Backend日志 |
| Docker容器异常 | 服务崩溃 | 查看对应容器日志 |

---

### 问题4: .env文件配置错误

**检查步骤**:
```bash
# 1. 检查必须的环境变量
grep -E 'MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|JWT_SECRET' .env

# 2. 检查变量格式（不应有空格）
cat .env | grep '= '  # 如果有输出，说明有多余空格

# 3. 重新加载环境变量
source .env
echo $MYSQL_ROOT_PASSWORD  # 应该有输出
```
